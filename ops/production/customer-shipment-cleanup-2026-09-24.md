# Очистка клиентов и отгрузок — 24 сентября 2026

По запросу владельца на `https://artel-crm.online` очищен справочник клиентов и удалены все 100 отгрузок. Удалены 66 действующих клиентских ролей и 176 архивных. Компании, используемые в платежах, работе, адресах или других ролях, сохранены для целостности истории; клиентская роль снята. Отгрузки помечены удалёнными штатными tombstone-записями, поэтому исходный импорт не возвращает их после перезапуска.

Использован `scripts/clear-customers-shipments.ts`: `plan` не пишет данные; `apply` под стандартной блокировкой OperationsStore сначала сохраняет и проверяет backup, проверяет сохранность остальных коллекций и только затем атомарно записывает результат. Автоматического запуска при старте или сборке нет. Платежи, склад, поставщики, адреса, автопарк, менеджеры, работа, Китай, сотрудники, сессии и все три банковских подключения сохранены. Удаляются только распределения платежей по удаляемым отгрузкам и назначения менеджеров удаляемым клиентским ролям.

На сервере скрипт выполнен через `docker exec` внутри единственного работающего контейнера, с его стандартной транзакционной блокировкой. Действующий runtime не заменялся: `artel-crm:20260924-banks-employees2`, SHA-256 backend `2a5cc0681ede561f49e07b12648cc452416fb7ef35490e0ded50a71f0e6396e4`. Код этого уже опубликованного runtime включён в основную ветку вместе с инструментом обслуживания.

Перед очисткой служба полного backup завершилась успешно. Точный backup состояния в момент транзакции: `/opt/artel-crm/data/operations/backups/directories-1790260547390-c0ffb3c3-904e-47f1-b38d-aaef6892efcd.json`. Отчёт: `/opt/artel-crm/ops/cleanup-20260924-result.json`, ревизия после очистки `10608`. Текущая ревизия продолжает меняться при автоматической синхронизации банков.

В основной локальной папке Desktop также удалены 100 отгрузок и 240 архивных клиентских ролей; действующих клиентов там уже не было. Отдельный backup лежит в `data/local-operations/backups/directories-1790260576849-02580107-3d40-49a7-bd6a-41f399e3e57f.json`. Локальное и production-хранилища не заменяли друг другом, банковские запросы локально не запускали.

Проверки: 230/230 API-тестов, TypeScript, ESLint, production build. Новый тест покрывает исходные и пользовательские отгрузки, совместную роль клиента/поставщика, сохранность платежей и адресов, повторное выполнение и чтение новым экземпляром хранилища. После записи production-план показывает нулевые количества; healthcheck успешен. В действующей авторизованной сессии проверены пустые Бензовозы, АЗС и Клиенты, включая обновление страницы.

Для ручного запуска необходимо явно передать `ARTEL_SNAPSHOT_DIR` и `ARTEL_STORE_DIR`, затем вызвать `npx tsx scripts/clear-customers-shipments.ts plan` или `apply`. Production-путь должен обслуживаться только внутри действующего контейнера через собранный автономный модуль либо при остановленном runtime под его lifetime lease; см. [инварианты хранения](storage-invariants.md).

При восстановлении нельзя целиком возвращать старое хранилище поверх актуального: банковские refresh tokens уже могли обновиться. Восстанавливать только согласованные бизнес-коллекции из backup, сохраняя актуальные банковские состояния и настройки.

## Проверка формы и исправление выбора компаний

В реальном браузере обнаружено, что редакторы бензовоза и исторической отгрузки предлагали всех неархивных контрагентов, включая компании только из платежей. В них добавлен фильтр по роли клиента/поставщика; ранее выбранная компания остаётся доступной при редактировании исторического документа. Редактор АЗС уже имел такой фильтр.

У 42 удалённых клиентских карточек оставалась только роль контрагента платежа. Они дополнительно архивированы с сохранением истории; это также позволяет явно добавить того же клиента повторно с прежним ID через штатную форму. Backup этой точечной корректировки: `/opt/artel-crm/data/operations/backups/directories-1790260882142-b0e0259c-0c7a-436c-8491-dc54da96472e.json`. Тест дополнен повторным добавлением клиента: прежние отгрузки при этом не возвращаются.

Для исправления формы опубликован образ `artel-crm:20260924-clean-customers` поверх действующего `20260924-banks-employees2`, заменены только статические файлы интерфейса. Backend и банковская конфигурация сохранены. Перед публикацией выполнены TypeScript, сборка, ESLint и повторный профильный тест.
