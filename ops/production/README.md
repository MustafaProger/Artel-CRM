1. Получить от пользователя отдельный домен или поддомен и направить его A-запись на `130.49.151.239`. Не использовать имена и HTTP-маршрут FuelLead/Руспласт.
2. Проверить DNS снаружи. Сохранить резервную копию текущей конфигурации CRM.
3. Под эксклюзивным `/opt/artel-crm/secrets/.runtime-env.lock` заменить `ARTEL_PUBLIC_ORIGIN` на точный HTTPS origin нового адреса. Формат файла — необработанные `KEY=value`, без shell expansion и без внешних кавычек.
4. Пересоздать только CRM: `docker compose --project-directory /opt/artel-crm up -d --no-build --pull never crm`.
5. Создать только новый `/etc/caddy/sites-enabled/artel-crm.caddy` по `site.caddy.template`. Существующий Caddyfile уже импортирует `sites-enabled/*.caddy`.
6. Проверить `caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile`. При успехе применить **reload**, не restart: `systemctl reload caddy`. Общие virtual hosts не редактировать.
7. Проверить публичные DNS, HTTPS-сертификат, перенаправление HTTP, реальный вход пользователя, API, desktop/mobile UI. Повторно сравнить контрольные суммы старых Caddy-файлов, PID Caddy, ID/StartedAt старых контейнеров и HTTP 200/200/204 FuelLead/Руспласт/CMS.

Порты общего firewall не менялись. `18083` не следует открывать наружу.

## Банки и переход на сервер

`ARTEL_BANK_REQUESTS_ENABLED=false` полностью блокирует новые банковские запросы production runtime. Для расписания нужны оба флага `ARTEL_BANK_REQUESTS_ENABLED=true` и `ARTEL_BANK_SYNC_ENABLED=true`. Сохранённые данные остаются доступны.

Оба подключения Сбера используют актуальные зашифрованные пары из `operations.json` и прежний `ARTEL_BANK_ENCRYPTION_KEY`. Сервер уже обновил эти пары. **Не запускать старую локальную синхронизацию с прежними снимками токенов.** После переноса Сбера ООО АРТЭЛЬ его активные локальные credentials также удалены, локальное расписание выключено.

Новый токен Т-Банка применён 24 сентября; чтение нужного счёта и плановая загрузка подтверждены. Порядок следующей замены токена:

1. Ещё раз проверить исходящий IP из контейнера; выпустить токен с этим IP и правами чтения счетов/операций. Старый доступ не отзывать до успешной проверки нового.
2. Сохранить новый токен через скрытый ввод: `ssh -t root@130.49.151.239 'python3 /opt/artel-crm/ops/set-tbank-token.py'`. Вариант `--stdin` предназначен только для закрытого канала передачи, без значений в argv или журнале.
3. Пересоздать только контейнер CRM и выполнить реальное чтение выписки. Проверить завершение полного периода, сохранённые операции и отсутствие дублей. Если старая задача остановилась после пяти ошибок, явно продолжить тот же период после успешного теста доступа.
4. Проверить автоматическую следующую загрузку. Не считать наличие токена доказательством подключения.

Скрипт установки сохраняет прежнюю конфигурацию `0600` и атомарно заменяет только значение токена. Он не включает расписание и не выполняет платежи. Текущее production-расписание включено.

Только подключение Т-Банка получает `ARTEL_BANK_TBANK_NK_TLS_CA_BASE64`. Системное доверие, другие проекты и проверка TLS не менялись. Публичные CA получены по ссылкам из [инструкции Т-Банка](https://developer.tbank.ru/docs/tls-settings); подробности в `docs/banking.md`.

## Резервные копии и откат

`artel-crm-backup.timer` запускает backup ежечасно. Проверяется SHA-256 JSON envelope с тем же JavaScript-сериализатором и содержимое полученного архива. Сохраняются 72 последние часовые копии и по одной в день за 30 дней; очистка касается только точного шаблона архивов этой CRM. При свободном месте менее 1 GiB backup отказывается начинать упаковку. Начальные архивы миграции сохраняются отдельно.

Ручной backup: `systemctl start artel-crm-backup.service`; проверка: `systemctl show artel-crm-backup.service -p Result -p ExecMainStatus`. Восстановление backup проверено в отдельном контейнере **без сети**, без банковских секретов в окружении и без публикации портов; восстановленная CRM загрузила данные и ответила 200.

Для отката кода оставить актуальные данные и секреты на месте, указать проверенный предыдущий образ в `/opt/artel-crm/.env` и пересоздать только `crm`. Для полного отключения нового размещения использовать `docker compose --project-directory /opt/artel-crm stop crm`; при необходимости отключить только `artel-crm-backup.timer`. Другие проекты не затрагивать.

Перед откатом данных выключить запросы к банкам, остановить только CRM и сохранить последнюю копию всего хранилища с конфигурацией. **Нельзя возвращать старые refresh tokens из архива:** сначала сохранить актуальный `sber.encryptedTokens` и неизменный ключ шифрования, восстановить бизнес-данные в отдельной папке и проверить их декодером; банковскую часть переносить из самого свежего рабочего состояния. Возврат к локальному приложению требует такого же переноса актуальных данных и отключения серверной синхронизации. Старый Vercel-снимок не является полным банковским откатом.
