# Структура

## Исходники

- `web/src/` — интерфейс React и TypeScript, модели, страницы и стили. `web/public/` содержит ресурсы приложения.
- `server/` — бизнес-логика, HTTP API, авторизация, хранение, интеграции и фоновые процессы.
- `server-render/` — запуск production-сервера и служебные утилиты.
- `api/` — входная точка API для совместимых окружений.
- `scripts/`, `tests/`, `qa/` — сборка, проверки и тестовый код. Отчёты и снимки проверок вынесены из рабочего дерева.
- `ops/`, `config/`, `.github/` — эксплуатационные сценарии, настройки и CI.
- `data/` — локальные данные и исходные наборы; это не документация, при уборке их не трогать.

## Сборка и выпуск

`npm run build` выполняет проверку типов и Vite-сборку интерфейса; `npm run build:server` собирает сервер; `npm run build:production` выполняет оба шага. `app-dist/` — собранные ресурсы, `server-render/production.mjs` — точка запуска.

Production хранит выпуски в `/opt/artel-crm/releases/`, рабочие данные отдельно в `/opt/artel-crm/data/`, секреты отдельно в `/opt/artel-crm/secrets/`. Актуальную базу определяют по фактическому образу контейнера и `release.json`, затем проверяют drift. Исторические каталоги выпусков не перезаписывают.

Активный образ проверяют по запущенному контейнеру `artel-crm-crm-1` и `/opt/artel-crm/release.json`. Метаданные выпуска связывают образ с коммитом и контрольной суммой `source.tar.gz`. Хранилище использует формат `artel-auth-partition-v2`; для проверки восстановления используют отдельный каталог без доступа к внешним интеграциям.
