# Локальное воспроизведение ЭТрН №7 — 29.09.2026

По новому прямому поручению Мустафы сохранённая ЭТрН №7 от 15.09.2026 используется как разрешённый исторический эталон для локальных тестов. Для этого сценария не требуются новый действительный рейс и подтверждение актуальности старых реквизитов. Это разрешение не распространяется на создание дубликата в действующем Saby или на новый юридически значимый обмен. Денис исключён из сценария; его карточка не изменялась.

Подготовлены новый локальный XML первого титула **ConsignmentNote / КНД 1110339 / версия 5.01**, его HTML/PDF-представление и полное сравнение с исходным комплектом. Рабочие хранилища, runtime, Saby и банковские расчёты инструмент не использует. Деплой не выполнялся.

## Что совпало и что различается

Принадлежность образца Олегу подтверждена независимой сверкой XML с уже сохранёнными приватными данными водителя и машины. Проверены имя, совпадения телефона с ранее сохранёнными источниками, соответствие машины 442 и точное соответствие вместимости. Полные персональные данные остаются только в [приватном аудите](</Users/mustafa/Library/Application Support/Artel-CRM/private/saby/etrn-7-local-replay/audit/independent-audit.json>); его результат привязан к SHA-256 первого титула.

| Проверка | Результат |
| --- | --- |
| Исходный архив | Совпали SHA-256 и размеры всех 14 файлов; повторная проверка после генерации не выявила изменений |
| Бизнес-значения первого титула | **96 из 96 совпали точно**, без округления и подмены отсутствующих значений |
| Структура первого титула и КНД | Дополнительно совпали 95 проверок наличия узлов, порядка и КНД |
| Заявленные сведения подписанта | Совпали 5 атрибутов; это сведения XML, а не электронная подпись |
| Служебные значения первого титула | 6 ожидаемых изменений: идентификатор файла, программа, дата и время генерации, UID накладной и идентификатор информационного поля |
| Титулы 2–4 | **Не генерируются**; все поля исходника показаны отдельно, в колонке нашего документа указано отсутствие |
| XSD 1110339 v5.01 | Исходный и созданный первые титулы проходят совместимую схему, описанную ниже |

Сверка охватывает участников и их отдельные роли, водителя, машину, груз, количество и единицы, площадки и маршрут, основания, даты и времена, дополнительные поля. Повторяемые элементы индексируются в XML-путях; отсутствие элемента/атрибута отличается от пустого значения. Сравнение выполняется по заново прочитанному созданному XML, а не по обещанию генератора сохранить входные данные.

Внутри самого эталона сохранены следующие особенности:

- Плановый адрес доставки первого титула отличается от фактического адреса выгрузки третьего; координаты при этом совпадают. Значения оставлены раздельно.
- `Грузопод = 27,9 т` воспроизведено как историческое значение образца. Оно не подтверждает грузоподъёмность машины 442 для новых перевозок и не переносится в её рабочую карточку.
- У получателя фактическое прибытие и убытие имеют одинаковое время. Инструмент не исправляет источник и не придумывает длительность разгрузки.
- Дата перевозки, даты/время действий участников и формирования титулов различаются и не сводятся к одной дате. В нашем документе меняется только локальное время формирования.
- Основание в эталоне — заказ №5. Отдельно сохранённый заказ/заявка №7 от 16.09.2026 не является этим основанием и не подставляется вместо него.
- Объём 8 м³ = 8 000 л, масса 6 718 кг = 6,718 т пересчитаны точно. Пустые суммы и отсутствующая стоимость не заполняются финансовыми данными CRM.

## Что именно реализовано

[Модель и сериализатор](../scripts/lib/etrn_replay.py) импортируют первый титул в редактируемый снимок XML без потери полей: сохраняются атрибуты, повторяемые элементы, порядок, содержательный текст и пустые узлы. Из снимка формируется новый XML Windows-1251 с отдельными локальными идентификаторами. Криптографические подписи исключаются; сведения `Подписант` сравниваются отдельно.

Это **генератор первого титула из снимка образца**, а не универсальное преобразование рабочего рейса CRM в ЭТрН. Совпадение показывает сохранность данных при импорте и повторной генерации. Оно не доказывает правильность заполнения из справочников и отгрузок. Сохранённый архив остальных титулов используется как эталон; новый цикл действий перевозчика и получателя не воспроизводится.

Действующий адаптер [заказа](../server/saby-transport-order.ts) по-прежнему формирует `TransportOrder`, КНД 1110361. Он не используется вместо ЭТрН и не расширялся этим офлайн-инструментом. Подписание, QR, сертификатные штампы, квитанции ГИС и статусы завершённого обмена в новый документ не переносятся.

HTML и PDF нашего документа строятся из созданного XML. Исходный PDF содержит три страницы и представляет комплект с результатами четырёх титулов; наша форма показывает первый титул. Поэтому состав разделов, вёрстка, число страниц и байты файлов различаются. Наш PDF содержит 5 страниц. Все 49 проверяемых длинных бизнес-значений извлечены из него без потери символов; полный результат — `pdf-comparison.json`. При просмотре исходника подтверждено перекрытие части текста штампами на страницах 1–2. В нашем PDF штампов нет; страницы просмотрены, перекрытий данных не обнаружено. Проверка наличия длинных текстовых значений дополняет просмотр страниц и точное XML-сравнение; короткие коды и числа не считаются доказанными только по поиску текста PDF.

## Повторный запуск

Из корня проекта:

```sh
ETRN_PDF_PYTHON='/Users/mustafa/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3' \
npm run replay:etrn -- \
  --archive '/Users/mustafa/Library/Application Support/Artel-CRM/private/saby/etrn-7-2026-09-15' \
  --output '/Users/mustafa/Library/Application Support/Artel-CRM/private/saby/etrn-7-local-replay/result' \
  --identity-audit '/Users/mustafa/Library/Application Support/Artel-CRM/private/saby/etrn-7-local-replay/audit/independent-audit.json'
```

`ETRN_PYTHON` задаёт Python для XML и сравнения; по умолчанию используется `python3`. `ETRN_PDF_PYTHON` задаёт Python с установленным `pypdf`; выше указан проверенный путь встроенного runtime Codex. Если runtime перемещён, получить его актуальный путь через `load_workspace_dependencies`. Нужны также локальный `xmllint`, зависимости проекта и Chrome; другой исполняемый файл браузера можно задать через `ETRN_CHROME_PATH`.

[Общая команда](../scripts/run_etrn_replay.mjs) сначала проверяет наличие `pypdf`, затем последовательно запускает [XML и отчёт](../scripts/replay_saby_etrn.py), [HTML/PDF и браузерные проверки](../scripts/render_etrn_replay.mjs), [сверку представления PDF](../scripts/compare_etrn_pdfs.py). Внешние сетевые запросы браузера блокируются. Для просмотра готового отчёта можно запустить `python3 scripts/serve_etrn_replay.py --output /приватный/каталог/result`: он выводит временную ссылку на loopback с отдельным случайным путём, без списка каталога; завершение процесса закрывает просмотр. Созданные HTML не используют внешние ресурсы; runtime CRM не запускается.

`scenario.json` сохраняет время и UUID локального сценария. Повтор с тем же архивом, снимком и параметрами даёт те же байты XML. PDF пересоздаётся; побайтовая повторяемость PDF не заявляется. Перед новой генерацией устаревшие производные PDF/отчёты отображения удаляются, а свежий отчёт связывает SHA-256 XML, HTML и PDF. Параметры `--generated-at` и `--replay-id` позволяют явно задать новый локальный сценарий.

Для теста изменения поля сохранить отдельную приватную копию `snapshot.json` и передать её через `--snapshot /абсолютный/приватный/путь.json`, выбрав отдельный `--output`. Исходный архив не редактировать. Значения снимка остаются строками; автоматическое округление и преобразование строк в числа исключено. CLI возвращает ненулевой код при расхождении бизнес-данных/сведений подписанта, ошибке XSD или проверок представления; таблица различий сохраняется для разбора.

Выходной каталог должен находиться вне checkout и отдельно от исходного архива. Приватные каталоги создаются с правами `0700`, файлы — `0600`; в консоль выводятся счётчики и результаты, без реквизитов. Символические ссылки в проверяемых выходных путях отклоняются. Никакие credentials для выполнения команды не требуются.

## Проверки и схема

**Пройдено 41/41 синтетических тестов**, включая полноценный вымышленный XML по XSD, и 5 браузерных проверок (два HTML на ширинах 1440/390 и печать PDF). Повтор на реальном приватном образце дал побайтно тот же XML. Намеренная прибавка 0,001 кг в отдельной копии снимка дала ровно одно бизнес-расхождение и код возврата 1, без округления. [Приватная проверка повторяемости](</Users/mustafa/Library/Application Support/Artel-CRM/private/saby/etrn-7-local-replay/repeat-and-mutation-check.json>).

Синтетические тесты запускаются отдельно от реального образца:

```sh
npm run test:etrn-replay
```

[Тесты модели](../tests/test_etrn_replay.py) покрывают точные значения и единицы, повторяемые узлы, порядок, пустое/отсутствующее значение, дополнительные поля, обнаружение изменений, кодировки, детерминизм, удаление подписей и отказ при чужом типе документа или неподдерживаемом XML. [Тесты отчёта и CLI](../tests/test_etrn_replay_cli.py) проверяют отображение значений именно созданного XML, экранирование HTML, сохранность архива, небезопасные пути и отмену устаревших производных артефактов. Эти тесты используют только вымышленные значения и временные каталоги.

Схема получена с [официальной страницы Saby 1110339 v5.01](https://formats.saby.ru/edo/trucking/126985?version=126985). Точный публичный оригинал и совместимая версия сохранены в `tests/fixtures/saby/`; [происхождение, SHA-256 и два исправления регулярных выражений](../tests/fixtures/saby/README.md#consignment-note-sender-title-1110339-501) описаны отдельно. В исходной схеме два лишних экранирования двоеточия мешают её компиляции libxml2; их удаление не меняет допустимые значения времени. Утверждение о прохождении проверки относится к этой явно документированной совместимой схеме, а не к неизменённому публичному файлу. XSD не доказывает актуальность реквизитов, криптографическую подпись, юридическую достаточность или принятие документа Saby/ГИС.

Следующий этап реальной интеграции остаётся отдельным: преобразование данных конкретного рабочего рейса в ЭТрН, генерация следующих титулов, полномочия подписантов и подтверждённый внешний обмен. Отсутствие этого этапа не блокирует разрешённые пользователем локальные тесты исторического образца.
