# Справочники: разделение компаний и безопасное удаление

Клиенты и поставщики используют общую коллекцию `companies`: одна компания может иметь обе роли. В интерфейсе больше нет выбора категории перевозчика. Ранее сохранённые роли перевозчика и ссылки из отгрузок сохраняются, редактирование карточки их не стирает. Новую компанию с ролью перевозчика сервер создать не позволяет.

В справочниках доступны клиенты, поставщики, менеджеры, товары, формы оплаты, автомобили, водители, адреса и назначения менеджеров компаний. Во всех списках есть удаление с подтверждением названия, блокировкой повторного нажатия и показом ошибки сервера. Добавление, редактирование и удаление доступны директору и администратору; проверка выполняется сервером. Обычный менеджер получает справочные списки в пределах действующего доступа.

## Хранение и зависимости

`DELETE /api/directories/{kind}/{id}` выполняется внутри того же атомарного `operations.mutate`, что и другие изменения. Для обычных записей тело содержит `{ "version": 0 }` (фактическую текущую версию), для назначения менеджера — `{ "managerId": "текущий id менеджера" }`. Изменённая с момента открытия подтверждения запись даёт `409`, повторно удалённая — `404`.

- `customers` / `suppliers` снимают только выбранную роль. При наличии другой роли общая компания сохраняется. Использование удаляемой роли в отгрузках блокирует действие.
- Физическое удаление компании блокируют отгрузки, платежи, складские записи, адреса, назначения менеджера и ссылки из задач/записей рабочего пространства. Автоматического каскада нет.
- Удаление менеджера блокируют отгрузки, назначения компаний и учётные записи сотрудников. Удаление автомобиля блокирует также водитель с автомобилем по умолчанию. Остальные записи блокируются при использовании в отгрузках. Проверяются ID и исторические подписи исходных строк.
- Связь клиента с менеджером удаляется отдельно: это настройка назначения по умолчанию, удаление не меняет менеджера ранее сохранённой отгрузки.

Исходный Excel/JSON остаётся неизменным. Для удалённых записей, которые могли бы восстановиться из исходного справочника или стандартных форм оплаты, сохраняются ID в `directories.deletedEntries`. Это сохранённое изменение слоя хранения с контрольной суммой, а не фильтр только на странице. Локальные записи удаляются из соответствующего массива. Импорт автопарка отмечается `directories.fleetSeedApplied=true`: он выполняется один раз для старого хранилища, а не заново при каждом чтении. Отдельная ручная миграция не требуется; метаданные сохраняются при первой следующей записи.

## Проверки

`npx tsx --test tests/api-directory-deletion.test.ts tests/api-directory-editing.test.ts tests/api-fleet-directory.test.ts` использует только временные каталоги. Покрываются удаление импортированных и новых записей, повторное чтение новым экземпляром storage, исходные/пользовательские зависимости, сохранение общей компании и исторической роли, конкурентные удаления, версии, запрет нового перевозчика, действующие HTTP-сессии и роли director/admin/manager, защита Origin.

`npm run test:directories-ui` запускает браузер с отдельным временным хранилищем и тестовым входом. Проверяет интерфейс карточек и удаления, отмену, сохранение после перезагрузки, общую компанию в двух списках, объяснение зависимости автомобиля и адаптивность. Проверка не доказывает состояние данных Vercel.
