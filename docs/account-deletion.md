# Удаление учётных записей

В разделе **Сотрудники и доступ → Учётные записи** директор или администратор может нажать «Удалить» у сотрудника и ввести его точное имя. Своя учётная запись и последний активный директор защищены в интерфейсе и на сервере.

Если у сотрудника остаются незавершённые задачи или неархивная работа с компаниями, удаление отклоняется. Сначала передайте записи действующему исполнителю либо завершите и архивируйте их в разделе «Работа».

Учётная запись скрывается из списка и новых назначений, вход запрещается, текущие сеансы и push-подписки отзываются. ID, имя, сотрудник справочника, отгрузки, клиентские назначения, исторические задачи, файлы и комментарии сохраняются. Исторические авторы продолжают отображаться по имени. Логин остаётся зарезервированным; восстановления удалённого аккаунта через интерфейс нет.

`DELETE /api/auth/users/:id` требует авторизованного директора/администратора и JSON `{ "version": 1, "confirmationName": "Имя сотрудника" }`. Устаревшая версия даёт 409, неверное имя — 400. Повтор того же удаления после потери ответа безопасен и не создаёт новую ревизию. Запись хранит `deletedAt` и `deletedBy`, имеет `active=false`.

Проверки API находятся в `tests/api-auth.test.ts`, `tests/api-work.test.ts`, `tests/api-push.test.ts`. Проверка desktop/mobile на синтетических данных: `node --import tsx scripts/verify_account_deletion.mjs` после `npm run build`. Реальных сотрудников для тестирования не удалять.
