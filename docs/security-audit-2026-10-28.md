По поручению пользователя проведён аудит Artel-CRM, внесены исправления и выполнена локальная регрессия. Production не выпускался; реальные операции, документы Saby, подписи, банковские запросы, пароли и ключи не менялись.

## Область и исходники

Исправления общей части перенесены в основной checkout узкими правками. Полный патч к сохранённой базе выпуска — [security-audit-20261028.patch](patches/security-audit-20261028.patch). **Основной checkout нельзя использовать вместо текущего release source при следующей публикации.** Перед выпуском нужна свежая сверка текущего сервера и повторное применение/проверка патча с учётом параллельной разработки.

## Подтверждённые проблемы и исправления

| Проблема | Условие и влияние | Исправление |
| --- | --- | --- |
| Отзыв доступа во время банковского запроса | Авторизация происходила до ожидания тела/провайдера. После отзыва сессии запрос мог запустить новое действие или выдать данные | Повторная проверка актуальной сессии/раздела/роли после тела, между шагами sync и перед JSON/CSV/PDF-ответом |
| Отзыв доступа во время предпросмотра подписания Saby | Последнее чтение сертификата могло завершиться после отзыва доступа, а preview возвращался без финальной проверки | Проверка прав после полного построения предпросмотра и до его возврата |
| Квадратичный разбор XML-сущностей | Недоверенное вложение с большим числом `&` без `;` могло занять event loop. На старом коде 8/16/32/64 КиБ занимали примерно 28/108/429/1672 мс | Линейный проход с ранним отказом; сохранены допустимые named/numeric Unicode entities и запреты DTD/XXE |
| Общая блокировка входа | 50 ошибок по произвольным логинам блокировали правильный вход всех сотрудников на 15 минут | Правильный пароль действующего аккаунта не блокируется чужими ошибками; лимит 5 ошибок своего аккаунта сохранён; одновременно допускаются не более 4 login-транзакций на middleware |
| Совпадение ключа логина и общего лимита | Допустимый логин `artel-global-login-limit` совпадал с внутренним ключом общего счётчика | Раздельные пространства ключей с переносом старых ограничений без их сброса |
| Избыточная запись при ограничении входа | Повторный неизменяющий 429 переписывал общий operations store | Изменение учитывается явно; неизменившийся отказ не создаёт новую редакцию хранилища |

Для известных и неизвестных логинов сохранён одинаковый путь вычисления scrypt. Отвергнут промежуточный вариант с быстрым отказом только для неизвестного имени: он раскрывал существование аккаунта по времени ответа. Gate срабатывает до постановки в очередь мутаций и освобождается в `finally`. Это ограничение внутри процесса, а не общая квота нескольких серверов. Исчерпанный собственный лимит аккаунта по-прежнему даёт 429; распределённый DDoS таким изменением не решается.

Уже принятая банковская задача не отменяется отзывом сессии: её существующая долговечная очередь сохраняется. Исправление запрещает следующий защищённый шаг и выдачу ответа после обнаруженного отзыва. Денежные расчёты, схема хранения и правила доступа к разделам не менялись.

Дополнительно в production HTTP runtime добавлена CSP: `script-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'`. Она блокирует исполняемую inline-разметку, подмену base и встраивание. Стили React/OpenLayers, карты и скачивание PDF сохранены. Это дополнительная защита, а не свидетельство найденной XSS. Политика применяется к standalone production runtime; историческое облачное размещение имеет отдельную конфигурацию.
