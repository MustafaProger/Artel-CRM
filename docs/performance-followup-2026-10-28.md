## Реализованные изменения

1. **Фоновый Saby-отбор.** Предварительный отбор заданий, для которых наступил срок обновления, использует один свежий скан. Каждый реально запускаемый job и каждое действие провайдера сохраняют собственную актуальную проверку прав. Для 10 / 50 / 100 архивных связанных рейсов число чтений уменьшилось с 41 / 201 / 401 до 1 / 1 / 1. Сохранены немедленный запуск после убытия, повторный запуск, остановка, ожидание завершения и границы владения lease.

2. **ETRN.** Полный snapshot переиспользуется только внутри одного синхронного блока со свежим read/mutate. Финальное обновление локальных metadata и освобождение lease успешно завершённого direct workflow объединены в одну durable-транзакцию: 27 чтений / 7 записей → 26 / 6 на одну завершённую direct-доставку. Сохранены intent/receipt, `fsync`, обработка неопределённого результата и fencing при ошибке. Обычное обновление двух доставок, для которых наступил срок, по-прежнему выполняет 32 чтения / 12 записей.

3. **Банки.** Планирование всех соединений использует один общий свежий read вместо трёх. Claim, токены, сроки повторов и публикация выписки остаются свежими транзакциями. Ошибка общего чтения сохраняется как отдельный failed-результат каждого соединения.

4. **Вход.** Неизменный `scrypt` вычисляется вне общей очереди mutate, внутри прежнего ограничения максимум в четыре запроса. Создание сессии возможно только в свежей транзакции после повторной проверки id/login/hash/salt/version/role/sections/driver/active/deleted, попыток входа и audience. Результат проверки credentials локален одному запросу; повтор callback после CAS-конфликта поддерживается. Setup сохраняет прежний атомарный путь. Освобождение очереди мутаций на время KDF не устраняет саму вычислительную работу или конкуренцию за libuv.

5. **Справочники.** `Set` сохранённых и удалённых ID заменяет вложенные линейные проверки при сборке компаний. Порядок и приоритет данных прежние.

6. **Браузер.** Скрытые банковские и кабинетные страницы прекращают polling; события focus и visibility объединяются в одно обновление. Основной код карт и OpenLayers загружается при открытии карты; лёгкие координатные функции и стили остаются в начальной загрузке. Поиск связей рейса по ID использует `Map`. Операторский журнал монтирует одну разметку для текущей ширины и показывает 50 операций на странице. Поиск, фильтры и счётчики работают по полному ответу; смена ширины сохраняет страницу, изменение фильтра сбрасывает её. API продолжает отдавать всю историю.

## Оставшиеся ограничения и сохранность

JSON остаётся общим файлом с пределом 64 MiB, полным чтением/разбором и durable-записью. Предел не менялся. Миграция в SQLite/PostgreSQL, разделение единственного исполнителя и выборочное хранение финансовых данных не включены: им нужны отдельная репетиция и доказательства сохранности FIFO, истории и идемпотентности. Активные Saby-задания всё ещё выполняют много транзакций. Локальное ускорение UI не означает устранения сетевого ожидания, конкуренции за CPU или очередей всех записей.

Первый performance-выпуск имел raw 65 / classified 27, `taskPassed=false`, `globalReviewed=false`. Эти результаты и supplements не переписывались и не переобъявлялись успешными. Сохранность нового выпуска проверена независимо, со свежей базой непосредственно перед switch; исходные отрицательные флаги нового аудита также сохранены. Согласованность связей сама по себе не доказывает физического инициатора внешних изменений.

Сохранены и неудачные диагностические прогоны: OOM исходного scheduler-бенчмарка, ранние ошибки fixtures, Vite/bootstrap и старые несовместимые ожидания общих operator-скриптов.
