# Saby: проверка протокола 30.09.2026

Исследование официальных источников для новой цепочки рейса. Это описание протокола и границ проверки, не подтверждение нового обмена в рабочем кабинете. Реальные документы не создавались; подписи и подтверждения участников не выполнялись. Приватные сведения не использованы в примерах.

## Заявка, подтверждение, отдельные ЭТрН

[TMS API заказов](https://link.sbis.ru/page/kbase_entity/2ecadb1a-5bd4-4858-83f4-74d83eb5735a?folderId=8f551622-a492-491f-8e75-605e0c41998d) документирует endpoint `https://tms.saby.ru/service/`, тип `TransportOrder`, первый титул `1110361`, отдельную запись титула перевозчика через `СБИС.ЗаписатьВложение`. Заказчик выполняет действие `Отправить`; перевозчик — `Утверждено` либо `Отклонено`. Подготовка действия может изменить служебные части XML, поэтому подпись относится к возвращённым актуальным байтам. Запись документа сама по себе не отправляет его перевозчику.

Для `СБИС.СписокИзменений` с `Тип=TransportOrder` этот источник указывает состояния: `4` — требуется обработка перевозчиком; `7` — утверждено; `9` — отрицательный итог. Объект документа хранит код как `Состояние.Код`, не как текст названия. [Общие коды API](https://saby.ru/help/integration/api/sequence/cod/) также разделяют черновик `0`, отправку `3`, доставку `4`, положительный итог `7`, ошибку `6`, отрицательный итог `9`, аннулирование `22`. Частично обработанный пакет может иметь положительный общий код: поэтому для нашей цепочки одного кода недостаточно.

Консервативный контракт CRM (инженерное решение): перед продолжением проверить ID, тип, стороны и текущую редакцию общей заявки; код `7`; актуальное неудалённое вложение титула перевозчика `1110362`; сообщённую Saby подпись именно этого вложения; отсутствие неполной/неоднозначной обработки. Подпись произвольного вложения или текст «утверждено» не подтверждают перевозчика. При неизвестной форме ответа продолжение запрещено до сверки. Это проверка сообщения оператора, не криптографическая проверка CRM.

[Формат заказа на портале ГИС ЭПД](https://public.epd-portal.ru/assets/static_files/json/links/%D0%A4%D0%BE%D1%80%D0%BC%D0%B0%D1%82%20%D1%8D%D0%BB%D0%B5%D0%BA%D1%82%D1%80%D0%BE%D0%BD%D0%BD%D0%BE%D0%B3%D0%BE%20%D0%B7%D0%B0%D0%BA%D0%B0%D0%B7%D0%B0%20%D0%B8%20%D0%B7%D0%B0%D1%8F%D0%B2%D0%BA%D0%B8.pdf) описывает два обязательных подписываемых файла. В титуле перевозчика `СодИнфПрв/@СодОпер`: `1` — принят, `2` — отказ. При разборе самого XML требуется сверять связь с первым титулом и `УИД_Зак`, а не переносить данные любого найденного `1110362`. Подтверждение заказа не является фактом погрузки ЭТрН.

По [руководству обмена ЭТрН](https://saby.ru/articles/tms/obmen_titulamy_etrn), грузам для разных адресов/получателей нужны отдельные накладные. Правило пользователя дополнительно сохраняет отдельную накладную для каждой строки, даже при совпадении адреса/клиента. Общая заявка — подтверждённое требование пользователя, не следствие объединения строк учёта.

## Нумерация и связи

[СБИС.ЗаписатьДокумент](https://saby.ru/help/integration/api/all_methods/doc) при отсутствии JSON-поля `Номер` берёт номер из первого формализованного файла либо генерирует по реестру. Поэтому XML с `CRM-UUID` не перейдёт на нумерацию Saby только от удаления JSON-поля. Точный номер сохраняется как строка, без самостоятельного увеличения последнего увиденного числа. [Настройки нумерации](https://saby.ru/help/regulations/number/) допускают разные области и момент выдачи номера; нельзя предполагать общую последовательность типов/лет/организаций.

Предлагаемый механизм: после полного предварительного контроля рейса записать единственный черновик без номера и формализованного вложения; сохранить возвращённые ID/номер; прочитать его отдельно; затем добавить XML с этим номером в тот же документ. Это опирается на документированную нумерацию оператора и обновление по ID. Работа пустого черновика и настройка конкретного TMS-реестра пока не проверены живой записью, поэтому являются границей первой приёмки. При отсутствии номера — остановка, без локального `max+1`. При неизвестном исходе создания — поиск метки и сверка, без повторного создания. Уже занятый номер не освобождается удалением неизвестного результата.

[API связи документов](https://saby.ru/help/integration/api/sequence/sv_doc) позволяет передать `ДокументОснование` с идентификатором уже существующего документа; обычный вид связи подразумевается без `ВидСвязи`. Для каждой ЭТрН нужно сохранять ID общей заявки в CRM и передавать её номер/дату в XML. Установка API-связи по точному ID предпочтительнее отложенного совпадения номера/даты; Saby предупреждает, что разрыв связи API не поддерживает.

## Проверенные поля формата

Пути ниже сверены с сохранёнными публичными XSD [1110361](../tests/fixtures/saby/transport-order-1110361-5.01.xsd) и [1110339](../tests/fixtures/saby/consignment-note-1110339-5.01.xsd); происхождение — [README](../tests/fixtures/saby/README.md). Полный формализованный XML обязан удовлетворять схеме, даже если пока не подписан.

| Предмет | Поле и правило |
| --- | --- |
| ИП в XML | `ИдСв/СвИП @ИННФЛ` (12 цифр), вложенный `ФИО` с фамилией/именем, отчество необязательно. Не `СвЮЛУч`. |
| ИП в JSON API | `СвФЛ` с 12-значным ИНН и полями имени; `ЧастноеЛицо=Нет` или отсутствие этого признака для ИП. В JSON нет симметричного `СвИП`. |
| Подача ТС | `ПунктПод/@ДатВрПод`: `ДД.ММ.ГГГГTЧЧ:ММ:СС+03:00`, UTC-флаг `НалКоорТочВрПод=1`. |
| Допустимое время подачи | `ПунктПод/@ПредВрПод`: время `ЧЧ:ММ:СС+03:00`, с `НалКоорТочПредВрПод=1`. Это предельное время часов, не длительность. |
| Допустимое время операции | `АдрПункт/@ПредВрОпер`, тот же формат времени; требует `ДатВрОпер` и соответствующие UTC-флаги. |
| Погрузка/выгрузка заявки | `АдрПункт/@Опер` допускает только `Погрузка` или `Выгрузка`; промежуточную остановку нельзя ложно обозначать выгрузкой. Для согласованного включения остановок существует повторяемый `СодИнфГО/ПромПунктМрш` (текст до 1000 знаков); в sequence он предшествует `СвГО`. |
| Опасный груз | `ИнфОпасн` заказа / `СвОпГруз` ЭТрН: ООН, отгрузочное имя, класс, классификационный код, группа упаковки, знак, `КодОгрЧерТун`. Строка туннельного кода сама по себе не подтверждает её пригодность для продукта. |
| Масса | Кг XML; тоннаж CRM ×1000. В обеих схемах `МасБрутЗнач` обязательно, `МасНетЗнач` необязательно. `МасГруз` заявки и `ПлМасГруз` ЭТрН обязательны. Известное нетто нельзя назвать брутто или опустить обязательный элемент. План отличается от `СвПогруз/@МасБрутОтгр`. |
| Объём | ЭТрН: м³, литры доставки /1000; отдельно вместимость машины. Заявка ограничивает объём до двух десятичных знаков; нельзя молча терять литры при несовместимой точности. |
| Габариты | Метры. Подтверждённое временное правило пользователя 1×1×1 не считать измерениями машины. |
| Указания ЭТрН | `УказГО/@УкНормПрвз` обязательно; `СвПА` обязательно, внутри лицо, способ передачи указаний, телефон. `ЗапрПерегруз` необязательно. Пустоту обязательного текста нельзя заменять выдуманным «нет». |
| Факты погрузки ЭТрН | `СвПогруз` обязательно, включая `ФДатВрПриб`, `ФДатВрУбыт`, `МасБрутОтгр`, `МетОпрМасс`. Без фактов полного валидного `1110339` нет. Честный неподписанный черновик Saby может требовать дальнейшего заполнения; он не равен готовому XML. |

Дополнительная сверка по таблицам 5.3/5.8 первичного формата заказа: `МетОпрМасс` обязателен, `01` означает взвешивание ТС до/после, `02` — поосно, `03` — расчёт по обмеру/техническим данным/поверенным приборам. Само деление тоннажа по литрам не устанавливает источник общей массы. `РаспрГр` обязателен: `0` — распределение по платформе возможно, `1` — невозможно. `ДелГр` обязателен: `0` — неделимый, `1` — делимый. Удалить эти атрибуты как необязательные нельзя. `ПрвзПищПрод` также обязателен; при отсутствии пищевых требований формат предписывает `Отсутствуют`. Это применимо к текущему подтверждённому дизельному грузу, не означает отсутствия требований ДОПОГ.

По [руководству заполнения заявки](https://online.saby.ru/page/kbase_entity/162c298b-8baf-4c3d-bf79-f493afadc048?folderId=04711f78-817c-44ab-9bc7-5e5f3fb6c7f7): допустимое время — предел прибытия/операции; промежуточная точка означает посещение без операций с грузом. Для наливного груза число грузовых мест — 1; оно не заменяет товарные литры. Опасный груз выбирают по паспорту/ДОПОГ, зависимые поля заполняет справочник. Код проезда зависит от классификации груза, а не выбранного маршрута. Свойства машины и вместимость — отдельные характеристики.

## НК как перевозчик чужого груза

**Последнее прямое уточнение пользователя 30.09.2026: НК только перевозит чужой груз.** Вариант продажи НК собственного товара больше не относится к целевому сценарию. Он приведён в официальных источниках как разграничение, а не как основание отменить ЭТрН пользователя. Выбор НК в качестве нашей организации рейса не подтверждает её роль грузоотправителя.

**Следующее уточнение закрыло роль отправителя: это Артэль.** Поэтому для обоих вариантов финансовой организации рейса применяется одна документальная цепочка Артэль → НК → выбранный получатель. Категория `nk_own_customer` не является самостоятельным основанием блокировки. Общая заявка связывает две разные организации; самозаявка и пропуск принятия перевозчиком не требуются.

[Официальная таблица Saby](https://online.saby.ru/page/kbase_entity/2ecadb1a-5bd4-4858-83f4-74d83eb5735a?folderId=cabc4252-19c5-4565-8b3c-1747107bf1c8) различает продажу собственного груза с доставкой своим транспортом без договора перевозки (путевой лист, ЭТрН не нужна) и привлечённого перевозчика (заявка и ЭТрН). [Разбор Saby ответов Минтранса](https://saby.ru/articles/tms/epd_mintrans) отдельно поясняет: доставка включена в цену товара — перевозочный договор не возникает автоматически; отдельная услуга перевозки требует реального договора и сторон. Самозаявку НК создавать для заполнения реквизита нельзя.

При этом отсутствие отдельного заказа не является безусловным запретом ЭТрН. [Руководство заполнения ТН](https://online.saby.ru/page/kbase_entity/2ecadb1a-5bd4-4858-83f4-74d83eb5735a?folderId=f7a002a6-d7c1-4c33-a79e-ceddb899cb0c), раздел «Заявка», допускает перевозку без отдельной заявки: в интерфейсе номер оставляют пустым, дату берут от ТН. [Первичный формат ТН, таблица 5.3](https://public.epd-portal.ru/assets/static_files/json/links/%D0%A4%D0%BE%D1%80%D0%BC%D0%B0%D1%82%20%D1%8D%D0%BB%D0%B5%D0%BA%D1%82%D1%80%D0%BE%D0%BD%D0%BD%D0%BE%D0%B9%20%D1%82%D1%80%D0%B0%D0%BD%D1%81%D0%BF%D0%BE%D1%80%D1%82%D0%BD%D0%BE%D0%B9%20%D0%BD%D0%B0%D0%BA%D0%BB%D0%B0%D0%B4%D0%BD%D0%BE%D0%B9.pdf) предписывает при отсутствии номера строку `Без номера`. В XML обязательные `НомЗак`/`ДатаЗак` поэтому можно представить без фиктивного документа: `Без номера` и дата ТН, если именно такой сценарий подтверждён. Не создавать при этом API-связь с несуществующим заказом и не показывать несуществующее утверждение перевозчиком.

Точный контракт исправления: `prepareTripSaby` использует `customerOrganization=config.customer` (Артэль) в обоих сценариях, перевозчик остаётся `config.carrier` (НК); `organization_id` рейса и финансовые расчёты не переписываются. В `preparationBlockers` удаляется безусловный запрет `nk_own_customer`; все проверки реквизитов, прав, нумерации, титула перевозчика и фактов сохраняются. Одинаковые стороны при ином неподтверждённом профиле не объявляются согласованной самозаявкой. Текущая проверка доступа обеих организаций остаётся применимой: сторонний отправитель в согласованный сценарий не добавлен. Возможность отсутствия отдельной заявки — свойство формата, а не необходимость обходить общую заявку Артэль → НК.

## Фоновая сверка завершённых локальных попыток

`phase=completed` в текущем workflow означает создание всех черновиков ЭТрН. Это не доказательство завершения четырёх титулов, приёма ГИС или отсутствия последующего аннулирования. Планировщик обновляет такие документы чтением раз в5мин, используя обновляемый `document.updatedAt`; проверка каждую минуту не означает сетевой запрос каждую минуту. В модели пока нет подтверждённого отдельного признака окончательного закрытия, поэтому прекращать сверку по надписи статуса/наличию подписи нельзя. Текущее бессрочное периодическое чтение соответствует этой границе; автоматических подписей или отправляющих действий оно не выполняет.

## Расчёт и стоимость перевозки

В [первичном формате заказа, таблица 7.9](https://public.epd-portal.ru/assets/static_files/json/links/%D0%A4%D0%BE%D1%80%D0%BC%D0%B0%D1%82%20%D1%8D%D0%BB%D0%B5%D0%BA%D1%82%D1%80%D0%BE%D0%BD%D0%BD%D0%BE%D0%B3%D0%BE%20%D0%B7%D0%B0%D0%BA%D0%B0%D0%B7%D0%B0%20%D0%B8%20%D0%B7%D0%B0%D1%8F%D0%B2%D0%BA%D0%B8.pdf), `СодИнфПрв/РазмПлатРасчет` относится к титулу перевозчика и обязателен при принятии (`СодОпер=1`). `@Расчет` — текст до2000символов, обязателен без `@СтТовБезНДС`; `@СтТовБезНДС` — decimal19.2, обязателен без `@Расчет`. Значение0 форматно допустимо. При наличии суммы обязательна действительная `@НалСт`; ставку нельзя вывести из нуля. `@СтТовУчНал`, `@КодОКВ=643`, `@ВалНаим` необязательны. Указание договора соответствует текстовому механизму расчёта. Это не поле первого титула отправителя; CRM не должна формировать/подписывать ответ перевозчика без отдельного полномочия. Нулевая стоимость Saby не изменяет финансовые величины CRM.

## Остатки, которые нельзя вывести из API

- Уточнение пользователя 30.09.2026 закрыло время: план выбранной даты **09:00**, допустимо **до 19:00**. Передавать `19:00:00+03:00`; не длительность и не симметричный допуск.
- Кто юридически осуществляет погрузку и владеет конкретной инфраструктурой; нельзя назначать Артэль по совпадению с отправителем.
- Уточнение пользователя 30.09.2026 закрыло нормативные указания: допустима ссылка на уже переданный договор. Переадресовка — грузополучателю по телефону приёмщика выбранной площадки.
- Масса рейса — нетто из документа. Выбранный с разрешения пользователя метод `03` соответствует техническому источнику; он не превращает нетто в брутто. Нужен отдельный подтверждённый плановый брутто для обеих схем.
- Последующее правило пользователя «бери дату перевозки» относится к заполнению даты основания. Отдельная явная настройка может применять это правило; официальный формат не подтверждает им продление или действительность исходного договора.
- Уточнение пользователя 30.09.2026 определило источник фактов погрузки: сотрудник вводит их в CRM. Конкретные значения вносятся по действительной погрузке; утверждение заявки их не создаёт.
- Вариант дизеля и точный туннельный код: значение «д» не заменять на D/E догадкой. Официальный [ADR 2025](https://unece.org/info/Transport/pub/395786) и материалы UNECE различают варианты UN1202; сопоставление с реальным продуктом и справочником Saby требует подтверждённого варианта.
- Состав промежуточных остановок и их включение в общую заявку: сохранить их в маршруте CRM, не вставлять в ЭТрН и не выдавать за погрузку/выгрузку.

## Граница приёмки

Документация/XSD подтверждают контракт. Синтетические тесты проверяют локальные переходы и защиту от дублей. Выдачу номеров конкретным реестром, реальный read-back нового заказа, титул и подпись перевозчика, реальные новые ЭТрН и завершение обмена можно подтвердить только на выбранной действительной перевозке с действиями уполномоченных участников.

## Идентификаторы участников в имени заявки

В первичном формате заказа (ссылка выше, раздел II, пункт4) имя первого титула — `ON_ZAKZVGO_A_O_W_GGGGMMDD_N`: `A` и `O` являются идентификаторами участников, составленными из кода оператора и присвоенного им кода организации. Значение `0` явно определено для `W` — отсутствуют дополнительные получатели. Разрешение заменить `A`/`O` одиночным `0` при загрузке черновика `1110361` не найдено.

[СБИС.ПодготовитьДействие](https://saby.ru/help/integration/api/all_methods/develop_doc) документированно заполняет идентификаторы участников и формирует имя формализованного файла. Это подтверждает возможность изменения первоначального файла на этапе подготовки; само по себе не доказывает приём `1110361` с произвольными временными значениями до этого этапа. Поэтому проверку действительных ID для TransportOrder нельзя снимать на основании аналогии с другим типом документа. Успешная проверка организаций и исторические ID не являются подтверждением актуальных ID; недостаток прав не обходится другим форматом XML. Перед первой новой цепочкой нужен разрешённый источник действительных ID либо отдельное явное подтверждение Saby такого режима черновика. Специализированная ссылка TMS при последней повторной проверке была недоступна, и дополнительное разрешение по ней не подтверждено.
