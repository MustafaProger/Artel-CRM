# Отгрузка машины нескольким клиентам

Новая форма следует порядку: дата отгрузки → поставщик и место загрузки → цена поставщика за тонну → тоннаж всей машины → товар → клиенты → водитель и автомобиль → раскрываемые дополнительные затраты.

Для каждого клиента отдельно выбираются компания, форма оплаты, литры, цена за литр, сумма перевозки и место выгрузки. Менеджер подставляется, если у компании однозначная связь с записью справочника; его можно выбрать вручную. Места загрузки и выгрузки ограничены соответствующей компанией. Кнопка «Добавить клиента» создаёт ещё такой же блок.

Тоннаж клиента рассчитывается автоматически:

`Тоннаж всей машины × литры клиента / сумма литров всех клиентов`.

Например, для машины 16 т и клиентов с 10 000 и 6 000 л получаются 10 и 6 т. При изменении литров или состава клиентов пересчитываются все доли. Ручного поля тоннажа клиента нет. Точность распределения — минимум шесть знаков после запятой; остаток округления распределяется по наибольшим дробным остаткам, поэтому сумма долей точно совпадает с исходным тоннажем. Положительная доля, округляющаяся до нуля, отклоняется с пояснением.

Допзатраты по умолчанию равны нулю и относятся ко всей машине. Они распределяются между клиентами пропорционально литрам, с сохранением общей суммы. Сумма перевозки указывается отдельно у каждого клиента. Закупочная цена в новой форме всегда задаётся за тонну. Продажа клиента = литры × цена за литр; закупка клиента = рассчитанные тонны × цена поставщика.

В справочник добавлены семь водителей и пять машин из предоставленного списка. Гена и Саша используют общий МАЗ 700; Петр и Олег — общий Hyundai 442. Указанные названия машин сохранены буквально, без предположений о полных госномерах. У Газели РПЗ вместимость и секции не заданы. При выборе водителя автоматически выбирается его машина; в этой отгрузке можно выбрать другую. Телефоны, объём и секции видны в форме и справочнике.

В таблице каждому клиенту соответствует отдельная строка. Редактирование любой такой строки открывает всю машину со всеми клиентами. Кнопка изменения состава клиентов также открывает общую форму. Удаление клиента из формы перераспределяет тоннаж между оставшимися клиентами; хотя бы один клиент должен остаться.

## Сохранение и совместимость

`POST /api/shipment-trips` создаёт всю отгрузку, `GET /api/shipment-trips/:id` возвращает её общие поля и клиентов, `PATCH /api/shipment-trips/:id` сохраняет изменения и состав клиентов одной транзакцией. Обновление принимает версии всех текущих строк. Если другое окно изменило данные или состав, сервер отклоняет устаревшее сохранение. Ошибка любого клиента не сохраняет остальные строки. Удалить клиента с привязанным банковским платежом или заменить его другим контрагентом нельзя.

`DELETE /api/shipment-trips/:id` с версиями всех клиентов удаляет отгрузку целиком. Перед удалением интерфейс показывает весь состав машины и запрашивает подтверждение. Привязанный платёж у любого клиента блокирует удаление всей группы.

Клиентские строки содержат служебную связь `trip_id`, исходный тоннаж машины `trip_total_tonnes` и общие допзатраты `trip_additional_costs`. Сервер самостоятельно рассчитывает доли и проверяет целостность группы при чтении. Одиночное изменение или удаление групповой строки через прежний API запрещено. Выбранный для рейса `vehicle_id` сохраняется отдельно от автомобиля водителя по умолчанию.

Исходные XLSX-выгрузки и старые операции не пересчитываются. Старые одиночные строки продолжают открываться в прежнем редакторе. Наполнение автопарка идемпотентно: существующие записи не заменяются; дополнения доступны при чтении и физически сохраняются при следующей обычной записи в рабочее хранилище.

Предоставленный `шаблон.xlsx` прочитан как справочный документ. Изменение правил прибыли, банковских оплат, сроков и нумерации не входит в эту доработку; действующие правила этих расчётов сохранены.

## Проверка

`npm run test:api`, `npm run lint`, `npm run build`, затем `npm run test:shipments-ui`.

Браузерный сценарий использует production preview с временным хранилищем. Проверяет исходную таблицу и фильтры, создание и изменение многоклиентской отгрузки, замену автомобиля, допзатраты, сохранение данных после ошибки, повторное открытие из строки второго клиента, добавление и удаление клиента с пересчётом, подтверждённое удаление всей машины, защиту несохранённых изменений и размеры 320/390/768/1440 px. Рабочие данные не используются для тестовых записей.
