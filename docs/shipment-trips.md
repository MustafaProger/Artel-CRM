# Отгрузка машины нескольким клиентам

Новая форма следует порядку: дата отгрузки → поставщик и место загрузки → цена поставщика за тонну → тоннаж всей машины → товар → клиенты → водитель и автомобиль → раскрываемые дополнительные затраты.

Для каждого клиента отдельно выбираются компания, форма оплаты, литры, цена за литр, сумма перевозки и место выгрузки. Менеджер подставляется из явного назначения в «Справочники → Клиенты и менеджеры»; его можно выбрать вручную. Места загрузки и выгрузки ограничены соответствующей компанией. Кнопка «Добавить клиента» создаёт ещё такой же блок.

Тоннаж клиента рассчитывается автоматически:

`Тоннаж всей машины × литры клиента / сумма литров всех клиентов`.

Например, для машины 16 т и клиентов с 10 000 и 6 000 л получаются 10 и 6 т. При изменении литров или состава клиентов пересчитываются все доли. Ручного поля тоннажа клиента нет. Точность распределения — минимум шесть знаков после запятой; остаток округления распределяется по наибольшим дробным остаткам, поэтому сумма долей точно совпадает с исходным тоннажем. Положительная доля, округляющаяся до нуля, отклоняется с пояснением.

Допзатраты по умолчанию равны нулю и относятся ко всей машине. Они распределяются между клиентами пропорционально литрам, с сохранением общей суммы. Сумма перевозки указывается отдельно у каждого клиента. Закупочная цена в новой форме всегда задаётся за тонну. Продажа клиента = литры × цена за литр; закупка клиента = рассчитанные тонны × цена поставщика.

В справочник добавлены семь водителей и пять машин из предоставленного списка. Гена и Саша используют общий МАЗ 700; Петр и Олег — общий Hyundai 442. Указанные названия машин сохранены буквально, без предположений о полных госномерах. У Газели РПЗ вместимость и секции не заданы. При выборе водителя автоматически выбирается его машина; в этой отгрузке можно выбрать другую. Телефоны, объём и секции видны в форме и справочнике.

В таблице каждому клиенту соответствует отдельная строка. Редактирование любой такой строки открывает всю машину со всеми клиентами. Кнопка изменения состава клиентов также открывает общую форму. Удаление клиента из формы перераспределяет тоннаж между оставшимися клиентами; хотя бы один клиент должен остаться.

## Сохранение и совместимость

`POST /api/shipment-trips` создаёт всю отгрузку, `GET /api/shipment-trips/:id` возвращает её общие поля и клиентов, `PATCH /api/shipment-trips/:id` сохраняет изменения и состав клиентов одной транзакцией. Обновление принимает версии всех текущих строк. Если другое окно изменило данные или состав, сервер отклоняет устаревшее сохранение. Ошибка любого клиента не сохраняет остальные строки. Удалить клиента с привязанным банковским платежом или заменить его другим контрагентом нельзя.

`DELETE /api/shipment-trips/:id` с версиями всех клиентов удаляет отгрузку целиком. Перед удалением интерфейс показывает весь состав машины и запрашивает подтверждение. Привязанный платёж у любого клиента блокирует удаление всей группы.

Клиентские строки содержат служебную связь `trip_id`, исходный тоннаж машины `trip_total_tonnes` и общие допзатраты `trip_additional_costs`. Сервер самостоятельно рассчитывает доли и проверяет целостность группы при чтении. Одиночное изменение или удаление групповой строки через прежний API запрещено. Выбранный для рейса `vehicle_id` сохраняется отдельно от автомобиля водителя по умолчанию.

Исходные XLSX-выгрузки и старые операции не пересчитываются. Старые одиночные строки продолжают открываться в прежнем редакторе. Наполнение автопарка идемпотентно: существующие записи не заменяются; дополнения доступны при чтении и физически сохраняются при следующей обычной записи в рабочее хранилище.

## Прибыль и дни с отгрузки — 10 сентября 2026

Для всех новых и ранее созданных автоматических отгрузок действует `template-payment-form`, по текстовым правилам `шаблон.xlsx` (строка 2). Старые настройки `null`, `excel-rounded`, `excel-exact` и другие правила автоматических строк заменяются при расчёте текущего представления; само рабочее хранилище при чтении не переписывается.

- Сумма покупателя = литры × цена продажи за литр; цена за тонну = сумма покупателя / тонны.
- Закупка машины = тоннаж клиента × общая закупочная цена за тонну. Ранее поддержанная закупка за литр в одиночном редакторе сохраняет явную единицу цены.
- Безнал и ф2: прибыль = сумма покупателя − закупка − перевозка − дополнительные затраты.
- Наличные: прибыль = сумма покупателя − закупка × 0,83 − перевозка − дополнительные затраты.
- Правило ф2 явно подтверждено владельцем как безнал. Коэффициент не зависит от соотношения закупки и продажи. Неизвестная форма оплаты оставляет прибыль пустой с пояснением.
- Дополнительные затраты — одна сумма, включающая КВП. Если у исторической строки это поле отсутствует, начальное значение берётся из КВП; при явно заданных допзатратах КВП повторно не вычитается. Явный ноль также имеет приоритет. Исходное поле КВП сохраняется отдельно для истории.
- Прибыль не округляется до целого рубля. Десятичная точность результата сохраняется; денежное представление в интерфейсе ограничено двумя знаками после запятой.

Исторические результаты продаж, закупок и прибыли из Excel остаются исходными при чтении и изменении нефинансовых данных. При явном изменении финансовых полей или формы оплаты прибыль пересчитывается по шаблону. Распознанные единицы продажи/закупки исходной строки сохраняются; её особые неизвестные формулы не подменяются предположениями. Обе формы передают в предварительный расчёт название выбранной формы оплаты, поэтому изменение только этого поля сразу меняет прибыль и совпадает с API после сохранения.

Колонка «Дней с отгрузки» показывает календарные дни от отгрузки до сегодня по Москве, пока сумма оплаты меньше продажи или оплата неизвестна. После полной оплаты или переплаты значение пустое. Сегодня и будущая дата дают 0; отсутствующая или некорректная дата — пустое значение. В форме машины счётчик виден, пока хотя бы один клиент не рассчитался. API машины возвращает `paidAmount` каждого клиента как отдельное поле только для чтения; оно не попадает в сохраняемые поля формы. Исторический срок остаётся в исходных данных.

«Перевозчик / водитель» — единая колонка таблицы, фильтров и CSV: выбранный водитель, иначе исходное значение перевозчика. Исходный текст хранится без изменения. В уменьшенном виде автомобиль / госномер скрыт. Расширенный / стандартный / уменьшенный виды содержат 31 / 21 / 11 колонок.

## Клиенты и менеджеры

В «Справочники → Клиенты и менеджеры» можно сохранить, заменить и снять назначение менеджера по ID клиента. Таблица владельца ещё не предоставлена: связи не выводятся из исторических подписей и похожих названий. При смене клиента обе формы подставляют менеджера по явной связи; для клиента без назначения поле очищается и заполняется вручную. Менеджера отгрузки можно изменить вручную. Смена назначения в справочнике не меняет сохранённые отгрузки и не назначает права доступа.

API использует `POST /api/directories` с `{kind: "customerManagers", companyId, managerId}`; `managerId: null` снимает назначение. Повторное сохранение той же связи идемпотентно. `directories.customerManagers` совместимо со старыми хранилищами версии 2 без этого поля. При создании отгрузки без `manager_id` сервер сам подставляет явное назначение клиента; при смене клиента без назначения требует выбрать менеджера.

## Проверка

Актуальная проверка формул шаблона: 45 API-тестов, 21 групп браузерных сценариев, сборка, TypeScript и ESLint. Проверены обе ветви прибыли при закупке выше и ниже продажи, ф2 как безнал, дробные рубли, однократный учёт КВП, изменение только формы оплаты, сохранение/reload, дни при полной и частичной оплате, а также возврат долга при увеличении продажи. Артефакты: `qa/template-formulas-2026-09-10/`.

`npm run test:api`, `npm run lint`, `npm run build`, затем `npm run test:shipments-ui`.

Браузерный сценарий использует production preview с временным хранилищем. Проверяет исходную таблицу и фильтры, создание и изменение многоклиентской отгрузки, замену автомобиля, допзатраты, сохранение данных после ошибки, повторное открытие из строки второго клиента, добавление и удаление клиента с пересчётом, подтверждённое удаление всей машины, защиту несохранённых изменений и размеры 320/390/768/1440 px. Рабочие данные не используются для тестовых записей.
