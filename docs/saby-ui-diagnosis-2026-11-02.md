В 12:56:04 МСК согласованным чтением сохранённых данных подтверждён текущий выпуск `artel-crm:20261101-stage6-repair-172a07ad`, healthy, 0 restart; bundle hash сверён с release config. Снимок проверен по checksum, без OperationsStore, provider calls или записей.

У рейсов 52 и 54 workflow completed, lastError=null; обе стороны всех трёх ЭТрН confirmed, completedAt сохранены. У ЭТрН 51 рейса 52 в момент снимка status=unknown, активный lease, lastError=null. У обеих остальных ЭТрН status=draft. Это состояние сохранённых данных CRM, а не новая независимая проверка провайдера или подтверждение приёмки клиентами.

Причинная цепочка в опубликованном source `.local/stage6-repair-20261101/source`:

1. `server/etrn-service.ts:471`: даже refresh уже существующей ЭТрН временно сохраняет status=unknown перед чтением/проверкой документа. Подтверждённые подписи при этом не сбрасываются.
2. `server/trip-workflow-issues.ts:19`: классификатор получает текущие документы вместо статусов доставок workflow.
3. `web/src/trip-workflow-issues.ts:6,31`: unknown считается требующим внимания; для обычного документа с dispatch это индекс 6, то есть этап 7. Активный refresh и completedAt здесь не учитываются.
4. `web/src/TripsPage.tsx:35`: список загружается при смене вкладки/refresh; периодическое обновление предусмотрено только для «В процессе», не для обычного списка рейсов.
5. `web/src/TripEtrnPanel.tsx:43,64,27`: открытие Saby читает свежий workflow по GET и передаёт workflowIssues обратно в карточку. Если refresh уже закончился, старая метка исчезает. Открытие не выполняет повторного подписания или отправки.

Локальный прогон действующего классификатора на снимке воспроизвёл ложную метку для №52: completed + обе confirmed + unknown + lastError=null дают «Отправка клиентам / Обработка ЭТрН приостановлена». Замена только промежуточного status на успешный readback draft убирает метку. Такой же временный случай в снимке есть у №47/49; это не устанавливает номер третьего рейса на пользовательских скриншотах. №54 в момент снимка уже без предупреждения; точный промежуточный ответ в 12:52 не записан.

Не всякое предупреждение этапа 7 ложно: №41 в том же снимке имеет отдельную содержательную ошибку автоматической сверки состава связанных ЭТрН; она сохраняется даже при status=draft. Поэтому просто скрывать все ошибки у completed нельзя.
