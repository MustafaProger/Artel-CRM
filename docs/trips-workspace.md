# Рейсы в основной CRM

Страница «Рейсы» использует существующую модель `shipment-trips`. Доступ выдаётся любому сотруднику через «Сотрудники и доступ» отдельной отметкой «Рейсы». Имя и должность сотрудника не определяют доступ. Старым менеджерам раздел автоматически не включается; их прежние стартовые страницы сохраняются.

До сохранения форма является локальным черновиком. «Сохранить рейс» одной транзакцией создаёт рабочий рейс и по одной строке «Отгрузок» на доставку. При редактировании меняются эти же строки. Создание использует стабильный ключ повторного запроса; потеря ответа и повторное нажатие не создают второй рейс. Повтор с изменённым содержимым отклоняется. Удалённый рейс не восстанавливается старым запросом.

Сохраняются наша организация, дата, поставщик, закупочная цена за тонну, общий тоннаж, товар, водитель, фактический автомобиль и дополнительные затраты. У каждой доставки свои клиент, менеджер, форма оплаты, литры, цена продажи за литр, стоимость доставки, пометка «счёт не нужен» и заметка. Для рейса есть общая заметка. Расчёты тоннажа, затрат, прибыли и взаиморасчётов не менялись. Числа стоимости доставки вводятся в рублях явно; масштаб сокращений Telegram не угадывается.

Места погрузки и доставки находятся в существующем справочнике `addresses`, связаны с компанией и типом площадки. В «Справочниках» доступен раздел «Места погрузки и доставки»; администратор также может добавить место из формы рейса. Место содержит название, фактический адрес, HTTPS-ссылку на Яндекс.Карты и при необходимости пару координат. Юридический адрес компании автоматически не становится адресом площадки.

При выборе места сохраняются отдельные снимки адреса, карты и координат. Изменение справочника не обновляет ранее сохранённый рейс незаметно. Для изменения маршрута выбирают другое место. Используемое место нельзя удалить или перенести на другую компанию/тип. Редактирование карточки компании сохраняет дополнительные сведения места, даже если старый интерфейс их не передал.

Плановое и фактическое время погрузки/выгрузки задаются отдельно, по Москве. Фактическое время не заполняется автоматически. Обязательность сведений для Saby проверяется отдельно от возможности сохранить рейс в CRM.

## Права и совместимость

- Новый список `GET /api/shipment-trips` и операции Saby требуют раздел «Рейсы».
- Общие создание, чтение и изменение рейса доступны через «Рейсы» либо прежние «Отгрузки», чтобы действующий редактор отгрузок продолжал работать.
- Для менеджера применяется прежняя область собственных клиентов и отгрузок. Рейс с чужими строками целиком не раскрывается; его собственные строки остаются в «Отгрузках» с запретом группового редактирования.
- Изменение прав отзывает сессии. Клиентская навигация и серверная проверка действуют независимо.
- Удаление рейса и изменение справочников сохраняют прежнее административное ограничение. Доступ к «Рейсам» сам по себе не даёт финансовые выписки или управление сотрудниками.
- Старые хранилища не требуют массовой перезаписи. Новые поля записываются при обычных сохранениях. Локальное хранилище не переносится на production.

## Saby и следующий этап

Состояние передачи относится к сохранённому рейсу. Ошибка Saby не удаляет рейс и не отменяет клиентские строки. После начала передачи данные защищены от изменения до сверки документов. Отдельно сохраняются связь каждой доставки с документом, снимок переданных данных, идентификаторы, редакции и ошибки. Подробный контракт, формализованный XML, конфигурация и ограничения проверки: [Интеграция Saby](saby-integration.md).

Программная запись документа в Saby и подписанная передача перевозчику — разные этапы. Подписание, интерфейс водителя, QR/карты для водителя, зарплата, уведомления, счета/УПД и 1С остаются в [согласованном backlog](trips-saby-implementation-handoff-2026-09-28.md#сохранить-на-следующий-этап-сейчас-не-реализовывать).

Состав недостающих сведений водителей находится в [отдельной сверке](trips-driver-readiness-2026-09-28.md). Пустые поля старой карточки не означают отсутствие уже переданных документов.

## Проверки

`npm run test:api`, `npm run typecheck`, `npm run lint`, `npm run build:production`, `npm run test:trips-ui` и существующие сценарии отгрузок, справочников, авторизации, прав и взаиморасчётов. Все записи автотестов выполняются во временных хранилищах, банковские данные синтетические, реальные запросы в банки/Saby не выполняются.

Фактический состав пройденных проверок и версия сервера фиксируются в отдельном отчёте релиза; этот документ описывает поведение, а не подтверждает внешнюю отправку.
