## Изменения и сохранённое поведение

- `server/operations-store.ts`: повторная проверка контрольной суммы и структуры пропускается только при точном совпадении заново прочитанных байтов файла и идентификатора исходных данных. При каждом чтении файл по-прежнему открывается и читается. В кеше хранятся строки, а не доступные вызывающему коду объекты; каждый ответ заново разбирается и проходит прежние миграции. Изменённые, повреждённые, недоступные и подменённые файлы не заменяются старым снимком. Отзыв сессии виден на следующем чтении. Атомарная запись, блокировки и проверки перед записью сохранены.
- `server/directory-operations.ts`: ID и нормализованное имя вычисляются один раз для каждого точного написания в текущем вызове; принадлежность сохранённым и удалённым ID проверяется через `Set`. Порядок, последнее написание, приоритет ручных карточек, метаданные и удаления сохранены.

Схема хранения не менялась. Уменьшение интервалов обновления, отключение фоновых задач, изменение правил расчётов или кеширование устаревших ответов в браузере в выпуск не входят. Общая анимация появления страницы остаётся 220 мс; она не задерживает начало запроса.

## Сеть и границы измерений

До выпуска выполнены пять пар внешних запросов к health с новым TLS-соединением. Через маршрут по умолчанию общее время составляло **0,607–1,149 с**, через `en0` — **0,212–0,306 с**. Таким образом, помимо backend обнаружена заметная разница сетевого пути. Эти измерения не доказывают, что вся задержка вызвана VPN или прокси, и не отражают повторные запросы браузера по уже открытому соединению. VPN, прокси и DNS не менялись.

После выпуска три пары дали через `en0` **0,201 / 0,398 / 0,206 с**, через маршрут по умолчанию — **0,847 / 0,599 / 0,722 с**. Основная наблюдаемая разница — установка TLS: примерно **0,47–0,63 с** по умолчанию против **0,08–0,17 с** через `en0`. Сетевой вклад сохранился после ускорения backend.

В одном замере работающего контейнера CPU достигал **98,75%**. Лимит 1 CPU не изменён; устойчивое снижение фоновой нагрузки не доказано. Подтверждён результат по времени запросов, а не устранение всех причин нагрузки сервера.

Изолированные 17 маршрутов, публичные проверки без сессии и авторизованная браузерная приёмка дают разные виды доказательств. Авторизованная полная HTTP-нагрузка на рабочие данные production не выполнялась. Время первого входа также включает последовательные проверки сессии, общего снимка и данных выбранной страницы; эту архитектуру данным выпуском не меняли.

## Повторяемая проверка HTTP

Добавлен `scripts/verify_page_latency.mjs`: разрешены только перечисленные GET-маршруты; вход, запись данных, синхронизация провайдеров и отправки не выполняются. Статистика содержит коды ответов, объёмы и времена без тел ответов, Cookie, сведений о пользователях и доступах провайдеров. Защищённый прогон требует действующей авторизованной сессии; 401/403 или HTML вместо API-ответа считаются ошибкой.

Публичная проверка без сессии:

```sh
node scripts/verify_page_latency.mjs --base-url https://artel-crm.online --public-only --samples 10 --burst --output /private/path/new-public-summary.json
```

Для разрешённого защищённого прогона значение Cookie хранится в отдельном приватном обычном файле с правами `0600`, а не в аргументе команды или отчёте:

```sh
ARTEL_PERF_COOKIE_FILE=/private/path/session-cookie node scripts/verify_page_latency.mjs --base-url https://artel-crm.online --samples 7 --burst --output /private/path/new-authenticated-summary.json
```

Пути выше — примеры; файл статистики должен быть новым. Скрипт использует keep-alive, до четырёх параллельных запросов и несжатые ответы (`Accept-Encoding: identity`). Первые замеры включают установку соединения. Его результаты нельзя выдавать за измерения рендеринга браузера.
