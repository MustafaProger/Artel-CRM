# Исправление дозаполнения заявки №17 — 07.10.2026

## Подтверждённая ошибка и исправление существующего документа

После сохранения водителем фактов погрузки и массы цепочка остановилась при дозаполнении ранее принятого черновика. В CRM сохранились признаки начатой записи, а чтение Saby подтвердило прежнее содержимое без массы. Исходный HTTP 500 не содержит сохранённого полного ответа, поэтому внутренняя причина ошибки провайдера не установлена.

Код повторно передавал весь документ через `СБИС.ЗаписатьДокумент`. Исправление использует документированный `СБИС.ЗаписатьВложение`: только прежняя редакция, прежнее вложение и полное содержимое XML. Документ и редакция одновременно не передаются. [Описание метода Saby](https://saby.ru/help/integration/api/all_methods/write_enclosure).

Для существующей №17 сначала проверены прежние ID/редакция/вложение, отсутствие подписей, полный хеш исходного черновика, сохранённые факты водителя, права и автоматическое поручение. После свежего проверенного backup выполнена ровно одна отдельная корректирующая запись. В 14:24:05 МСК повторное чтение подтвердило полное совпадение XML с рассчитанным титулом, включая сохранённую массу. Новая заявка или номер не создавались; факты водителя и прежние попытки не сбрасывались. Защищённое намерение и полные доказательства сохранены только на сервере, повтор корректировки запрещён.

Штатный планировщик затем подтвердил массу, перевёл `driverFlow` в `ready`, снял прежнюю ошибку и начал подготовку подписи по уже существующему поручению. Это подтверждение исправления записи массы, а не доказательство подписания.

## Защита новых дозаполнений

- Намерение записи сохраняется непосредственно перед внешним запросом, после авторизации и проверки актуальности обработки. Автоматического повтора после 401, сетевой неопределённости или HTTP 500 нет.
- До записи и после неё сверяются прежние редакция, идентификатор и имя вложения. Перед первой записью дополнительно сверяется полный исходный хеш, после неё — всё деловое содержимое титула.
- Первая безопасная диагностика ошибки записи сохраняется отдельно и не стирается последующими чтениями. Секреты, ответы провайдера и содержимое документов в диагностику не входят.
- Если после начатой попытки сохранился прежний черновик без массы, CRM прямо сообщает, что дозаполнение не подтверждено и необходима сверка; второй запрос записи не выполняется.

## Остановка проверки после подготовки подписи

У №17 сохранён результат единственного Prepare: привязка и полный манифест файлов, `preparedVerified=false`, `dispatchState=not_sent`, без `executeAttempted`. Повторный Prepare запрещён. Прежнее общее сообщение ошибочно подразумевало неизвестный результат отправки подписи, хотя Execute ещё не начинался.

Исправлена проекция такого строго определённого состояния: «Подготовленные сведения Saby не прошли проверку. Запрос на подпись ещё не отправлялся. Требуется сверка». Сохранённая история не переписывается; диагностический этап больше не называется Execute без факта его отправки.

Чтение подготовленного XML выявило два преобразования Saby: удаление четырёх повторных полей из блока груза при сохранении их значений в общей части документа и добавление `НалКоорТочВрОпер="1"` у пункта выгрузки без `ДатВрОпер`. Остальные различия — уже поддерживаемое заполнение заголовка/подписанта, запись того же юридического наименования, нули после десятичной точки и разрешённое пользователем добавление координат при неизменном адресе.

Для формата 5.01 приложение ФНС определяет `НалКоорТочВрОпер` как признак UTC у `ДатВрОпер`; атрибут обязателен при наличии даты/времени, но сам дату/время не задаёт. Это источник значения поля конкретного формата, а не заключение о действительности приказа на текущую дату. [Приложение ФНС](https://www.nalog.gov.ru/html/sites/www.new.nalog.ru/docs/edo/pril_fns108_130223.docx), [исходная XSD титула отправителя](https://www.nalog.gov.ru/html/sites/www.new.nalog.ru/files/about_fts/docs/xsd/xsd_fns108_251224.zip).

Сравнение принимает удалённые дубликаты только для единственного груза с единственной доставкой, двумя нумерованными пунктами и прежней связью погрузка 1 → выгрузка 2. Четыре исходных поля должны точно подтверждаться неизменной общей информацией, строкой доставки, объёмом и адресом пункта выгрузки. Частичные удаления, лишние поля, неоднозначность и несколько доставок не подпадают под исключение. Добавленный UTC-флаг принимается только как `1` на прежнем однозначном пункте выгрузки при отсутствии даты/времени, предельного времени и его собственного UTC-флага в обеих версиях. Любые остальные поля сравниваются по прежним правилам.

Изменяются только копии XML для сравнения. Байты Saby, имена, SHA256 вложений, манифест и поручение не заменяются. Согласованные 600 минут обработки не меняются и не подставляются в поле предельного времени.

В 14:44:51 МСК отдельная проверка с запретом любых методов изменения восстановила **тот же сохранённый манифест №17** и подтвердила его имена/хеши и полное деловое соответствие. Состояние записи не менялось: `preparedVerified=false`, Execute отсутствовал. Вызовов Write/Prepare/Execute в этой проверке — 0. Независимый обзор и 20 дополнительных синтетических проверок подмен не обнаружили обхода защиты.
