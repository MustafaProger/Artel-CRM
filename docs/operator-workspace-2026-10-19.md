# Операторская — 19 октября 2026

Основание — расшифровка «Новая запись 3.txt» и последующее уточнение пользователя: доступ как для сотрудника; сейчас реализовать доступную основу, остальные показатели добавить позднее. Счета, 1С и отдельный проект artel-operator в задачу не входят.

## Поведение

- Три вкладки: «Аналитика», «Заправки», «Реквизиты». Доступ назначается существующим правом `operator`; текущие назначения не изменяются. Директор и администратор имеют доступ по существующей политике. Все сотрудники с этим правом работают в общем журнале операторской.
- Заправка: дата, имя водителя текстом, свободно задаваемый сервис с подсказками Газпромнефть/Лукойл/Роснефть, процент скидки, литры, цена за литр, введённая оператором сумма, получатель и комментарий. Скидка хранится отдельно: формула в записи не определена, автоматического пересчёта нет. Сумма поддерживает копейки, литры/цена/скидка — до шести десятичных знаков.
- Новая запись не оплачена. Сотрудник отдельно подтверждает получение денег. При ошибке может снять подтверждение; оба события сохраняются с автором и временем. Исправление финансовых полей оплаченной записи требует сначала снять подтверждение. Это защищает ранее подтверждённую сумму от незаметной замены.
- Дата в журнале не означает завершённую заправку. Выдача штрихкода/QR и сообщения в мессенджерах остаются ручными; CRM их не отправляет и не создаёт платежей.
- Получатель: наименование, банк, карта и/или телефон, другие реквизиты. Копирование полного блока, редактирование, архив и возврат. Заправка связана с получателем и содержит историческую копию реквизитов. Изменение справочника не переписывает сохранённые заправки. Архивные реквизиты недоступны для нового выбора.
- Аналитика: число записей, сумма литров, введённые суммы с подтверждённой и неподтверждённой оплатой. Общие фильтры периода, поиска и оплаты; десятичное суммирование. Это не прибыль, бухгалтерский долг или автоматическая сверка кабинетов.
- Имя водителя пока не связано с автопарком или клиентом CRM; внешняя привязка получателя также не согласована. Фотография-образец отсутствует. Эти пробелы не заменены выдуманными правилами.

## Хранение и права

Необязательное поле `operations.operator` добавляется только при первой записи. Старые данные при чтении не мигрируются. Все записи используют OperationsStore и его транзакционную блокировку. Сервер заново проверяет активную сессию и право раздела внутри транзакции. Доступ водителя и отдельного логистического API не расширяется.

Для создания, редактирования, оплаты и архива обязательны UUID запроса; повтор совпадающего запроса того же сотрудника возвращает прежний ID без повторного действия. Иной автор или тело с тем же ключом отклоняются. Версии защищают запись и выбор реквизитов от устаревшего изменения. После сохранения интерфейс отдельно перечитывает данные. При потере ответа он блокирует изменение формы и предлагает повторить тот же запрос.

Реквизиты существуют только в закрытом хранилище и авторизованном API. В исходниках/тестах только синтетические данные. Живые рабочие записи для тестов создавать не требуется.
