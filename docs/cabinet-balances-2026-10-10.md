## Подтверждённый запрос

Отдельная страница CRM со счетами и текущими остатками GloPro, Яндекс Go, ЛУКОЙЛ, Роснефти и natcar. Пользователь выбрал автоматический вход в кабинеты. Уточнил: именно Яндекс Go и ЛУКОЙЛ запрашивают код при входе; исключать их не нужно. Тип кода и срок жизни сессии пока не подтверждены.

Адреса пользователя:

- `https://business.taxi.yandex.ru/`
- `https://lk.licard.com/`
- `https://lk.rn-card.ru/Account/Login?ReturnUrl=%2F`
- `http://lk.natcar.ru/`

## Что сделано локально

- Раздел «Балансы кабинетов», доступный директору и администратору в рамках существующих административных ролей. Права других сотрудников не расширялись.
- Все пять сервисов, несколько именованных подключений одного сервиса, состояние «Не подключён» / «Доступ сохранён · нужна настройка». Отсутствующий остаток обозначен прочерком, а не нулём.
- `GET/POST /api/cabinets`: проверка CRM-сессии и административной роли, повторная проверка перед записью, существующая защита Origin, ограничение размера запроса, закрытый список провайдеров. Произвольные URL не принимаются.
- Логин и пароль шифруются AES-256-GCM с отдельным серверным ключом и привязкой к ID подключения и провайдеру. Секреты и шифротекст не возвращаются в публичном ответе. Шифротекст хранится через штатный `OperationsStore`; остальные данные не меняются.
- Для настройки сохранения используется серверная переменная `ARTEL_CABINET_ENCRYPTION_KEY`: 32 случайных байта, представленные 64 hex-символами. Ключ необходимо хранить отдельно от данных и резервировать защищённо; не отправлять в чат/Git. Реальный ключ этим продолжением не создан и не установлен. Без ключа сохранение недоступно; просмотр страницы работает.
- Ни POST сохранения, ни открытие страницы не выполняют внешние запросы/входы. Автоматическое чтение, OTP, сохранение браузерных сессий и планировщик ещё не реализованы. Новый пароль можно пока сохранить только как отдельное подключение с другим названием; редактирование/отключение добавлять вместе с жизненным циклом исполнителя.
- Для natcar ссылка интерфейса использует HTTPS. Работоспособность TLS этого адреса не подтверждена. Нельзя передавать реальные доступы по HTTP или отключать проверку сертификата.

- Яндекс Go: прямой запрос без браузерной сессии возвращает публичную посадочную страницу с `authorized=0`, но в рабочем Chrome сохранилась авторизация НК АРТЭЛЬ: открыт `/main`, видна карточка баланса. Сервис сообщает о технических работах. Карточка содержит несколько сумм/сервисов; это ещё не проверенный полный перечень денежных счетов. Логины/пароли пользователя не извлекались и не сохранялись, реальные формы входа не отправлялись. Коды в чат не запрашивались.

1. Пользователь входит в GloPro и Роснефть в обычном рабочем Chrome. Прочитать реальные страницы счетов/договоров и проверить, какие именно значения являются остатками, доступной суммой, кредитным лимитом и долгом.
2. Установить доступность ЛУКОЙЛ и natcar. Для Яндекса/ЛУКОЙЛ пройти штатный вход и выяснить механизм подтверждения; коды вводятся пользователем непосредственно в форму.
3. Реализовать отдельные проверенные адаптеры, изолированные браузерные сессии на сервере, шифрование сессий, состояния ожидания подтверждения, ограниченные повторы и защиту от параллельных входов. Не переносить сессию Mac на сервер без явного механизма настройки и проверки.
4. Только после полной сверки состава счетов публиковать снимок остатков с временем успешного чтения; ошибка/неполное чтение сохраняет прежние данные как устаревшие. Не складывать деньги разных юрлиц/валют и не смешивать их с задолженностью по отгрузкам.
5. Перед выпуском проверить совместимость, backup и preservation. Реальное принятие: повторное чтение на сервере после перезапуска, сравнение каждого остатка с кабинетом, поведение при истечении сессии/коде, отсутствие платежей и изменений лимитов.
