## Реальная проверка текущего адаптера

Текущий `server/saby-client.ts` с исправлением отдельных кабинетов собран во временный диагностический модуль и выполнен от пользователя `node` внутри действующего контейнера CRM. Использован обычный Node `fetch`, без замены внешних ответов. Секреты прочитаны из подготовленного `saby.pending.env` и переданы только через stdin, без значений в аргументах команд или отчётах.

Разрешённый список диагностического транспорта содержит только аутентификацию, список собственных организаций и чтение документа. Модуль не содержит `OperationsStore`, не запускает второй runtime и не вызывает запись/подписание.

Подтверждено:

- две отдельные авторизации в явно заданных кабинетах Артэль и НК Артэль;
- `verifyOrganizations()` успешно сверил реальные ИНН/КПП и подключённый ЭДО каждой организации в её собственном кабинете;
- `readDocument()` прочитал существующую ЭТрН №7 от 15.09.2026; отдельно совпали реальный ID, тип `ConsignmentNote`, номер, дата, получены сведения о восьми вложениях;
- все пять запросов получили HTTP 200 и прошли проверки JSON-RPC/содержимого текущего адаптера.

Это подтверждает работу исправленного адаптера на сервере, **но не его публикацию в рабочем runtime**. Основной процесс приложения не заменялся. Закрытый серверный отчёт: `/opt/artel-crm/private/saby-readonly-20260929/adapter-probe-result.json`.

Новый полный сценарий использует настоящий backend middleware, `SabyClient`, сериализацию и временное хранилище. Подменён только внешний транспорт Saby. Подтверждено:

- сохранение одного рейса с двумя заказчиками создаёт ровно две строки отгрузок; повтор сохраняет ID и учёт;
- двойное нажатие вызывает один браузерный POST; две доставки получают два формализованных черновика с отдельным чтением результата и ссылками Saby, а проверка организаций использует отдельные сессии кабинетов;
- перезагрузка страницы и новый экземпляр middleware/store восстанавливают сохранённые ID; повторная отправка не вызывает внешних запросов, редактирование/удаление отправленных строк блокируется;
- потеря ответа после записи показывает неопределённый результат; проверка статуса находит существующий документ без дубля и без изменения учёта;
- ссылки на посторонние домены отбрасываются; публичные ответы и сохранённые данные не содержат credentials/сессий.

Проверка нового экземпляра middleware/store подтверждает чтение сохранённых связей, но не является перезапуском процесса. Оба браузерных набора работают на полностью синтетическом XLSX-снимке и временных хранилищах: `fixtureOnly=true`, `workingStoreAccessed=false`. Реальные credentials Saby и банков не используются. Ошибок браузера, неожиданных внешних запросов и переполнений мобильной вёрстки не обнаружено.

Отчёты и скриншоты: `qa/trips-2026-09-28/browser.json` и `qa/trips-saby-2026-09-29/browser.json`. Дата в имени первой папки сохранена от существующего набора, сам набор повторно выполнен 29.09.2026.
