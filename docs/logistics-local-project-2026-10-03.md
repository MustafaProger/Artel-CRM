# Отдельный локальный проект логистики

Последнее указание пользователя: «Сделай проект локально, выведи его на рабочий стол… Это будет отдельный проект, который сначала надо будет тестить». Публикация дальнейших изменений не разрешена до нового поручения.

Проект: `/Users/mustafa/Desktop/Artel-Logistics`. Отдельные frontend, package.json, сборка, Git-репозиторий, локальный запуск и инструкция. Рабочего хранилища в нём нет; ручные тесты используют учебные данные `.local/test-data`. Серверная бизнес-логика импортируется из соседней Artel-CRM, без второй реализации учёта и без синхронизации баз.

## Реализация и проверки до выделения

Повторно использованы редактор рейса, справочники с объединением независимых изменений, панель Saby и существующие API/OperationsStore. Добавлены ограниченная сессия логиста, закрытый список маршрутов, проекция справочников без банковских реквизитов и посторонних финансовых контрагентов. Права сотрудников и владение рейсами сохранены. Полный перечень: [инвентаризация](logistics-feature-inventory.md).

- 463 API/unit-теста, TypeScript, ESLint и production build прошли.
- 15 групп браузерной проверки логистики и 14 существующих проверок рейсов/Saby прошли на синтетических данных, в том числе 1440/390/320 px, повтор после потери ответа, версии, права, удаление и файлы.
- Оба собранных образа прошли изолированную проверку без сети/production mounts, включая раздельные сессии и перезапуск. Реальных документов и подписей Saby тесты не создавали.
- После выделения frontend из `/Users/mustafa/Desktop/Artel-Logistics/web` отдельно прошёл 15 групп браузерных проверок: 106 запросов через ограниченный API, ноль ошибок JavaScript и внешних запросов. Отчёт — `Artel-Logistics/qa/browser/browser.json`.

## Production возвращён к прежнему интерфейсу

До уточнения успел быть опубликован `artel-crm:20261002-logistics-260b31d5` (02.10, 18:20:39 UTC), файлы по HTTPS совпали со сборкой. После уточнения в **18:23:53 UTC / 21:23:53 МСК 02.10** включён совместимый образ **`artel-crm:20261002-logistics-260b31d5-ui-rollback`**. Он содержит прежний интерфейс CRM и совместимый backend. `/logistics/` возвращает 404. Новый frontend не опубликован.

Возврат UI подтверждён: контейнер healthy, учёт и пользователи, существующие банковские строки/счета/доступы, runtime, snapshot, Compose, Caddy и соседние контейнеры сохранены. Рабочие данные и секреты назад не откатывались. Backend с защитой аудитории сессий оставлен, чтобы новые ограниченные сессии не превратились в обычные при откате старого кода.

Резервная копия перед возвратом UI: `/opt/artel-crm/backups/artel-crm-20261002T182339.584302Z.tar.gz`. Закрытое подтверждение — `/opt/artel-crm/releases/20261002-logistics-260b31d5/local-only-rollback/release.json`.

Две ранние проверки публикации автоматически возвращали UI из-за снимка `tripSaby` во время фонового мониторинга. Приватное сравнение с backup подтвердило только обновление времён проверок; документы, снимки и содержательные поля сохранились. Финальный контроль ждёт завершения активной lease и сравнивает все содержательные поля, исключая только служебные времена и lease. Эти попытки не откатывали данные.

Авторизованная production UI-приёмка нового frontend не выполнена: браузерные переходы завершались сетевым таймаутом. Её не заменяют локальные тесты или совпадение HTTPS-файлов. Внутри нового локального проекта работа продолжается только на учебном стенде. Git commit/push в основной CRM не выполнялись.

Подпись НК/МЧД и прямая подпись из CRM по-прежнему не завершены. Правила 27,9 т / 17,5 м³, НДС «не указан», сохранение ручных правок и запрет автоматической перезаписи подписанного титула остаются прежними.
