# Saby ЭТрН: API, подпись и проверка кабинетов 29.09.2026

Новое поручение Мустафы расширяет прежний этап локального воспроизведения до рабочего создания ЭТрН и подписи уполномоченным пользователем. Этот отчёт описывает API и результаты **проверки чтением**, не объявляет выполненными новую отправку или новую подпись.

## Поддержанный путь

Сервер CRM записывает новый `ConsignmentNote` с XML первого титула `1110339`, сохраняет полученный ID до дополнительной проверки, отдельно читает последнюю редакцию и предоставляет ссылку на карточку документа в Saby. Владелец электронной подписи открывает эту карточку и выполняет доступное действие. Затем CRM повторно читает состояние, подписи и файлы.

Официальный [TMS API ЭТрН](https://online.saby.ru/page/kbase_entity/2ecadb1a-5bd4-4858-83f4-74d83eb5735a?folderId=f6d99b24-2393-4782-8f65-16a9e0f9e665) определяет endpoint `https://tms.saby.ru/service/`, метод `СБИС.ЗаписатьДокумент`, поля `Грузоотправитель`, `Грузополучатель`, `ТранспортнаяКомпания`, `НашаОрганизация`. Первое подписывающее действие грузоотправителя — этап «Отправка», действие «Погружен». Оно означает фактическое событие; нажимать его заранее вместо простой записи черновика нельзя. Подготовка через `СБИС.ПодготовитьДействие` может дополнить XML служебными реквизитами, поэтому подпись должна относиться к актуальным байтам после подготовки. Старые `.sig` не применимы к новому документу. Автоматических вызовов подписания в клиенте нет: выбран подтверждённый путь через Saby UI.

В [структуре документа](https://saby.ru/help/integration/api/all_methods/object/) отдельно описаны `СсылкаДляНашаОрганизация`, `Состояние`, `Редакция`, `Этап.Действие`, `Вложение.Подпись`, файлы и доверенности. Ссылка на карточку может требовать входа. Наличие учётной записи не означает доступности закрытого ключа или полномочий на каждый этап. Сервис возвращает только безопасные HTTPS-ссылки доменов Saby/SBIS; ссылки файлов не принимаются от браузера и не сохраняются как долговечный адрес скачивания.

Наличие зарегистрированного сертификата не доказывает, что носитель сейчас подключён. Серверного ключа для автоматической подписи логином/паролем не найдено. Для перевозчика текущий пользователь не получил зарегистрированных сертификатов; это не доказывает отсутствие подписи у другого уполномоченного сотрудника. Полномочия и МЧД конкретного нового этапа окончательно проверяет Saby при подписании владельцем. SMS, активация сертификата, регистрация сертификата и внешние записи при диагностике не выполнялись.

## Фактический контракт чтения

`readConsignmentNote(id)` отправляет `ДопПоля: "Расширение,ЭПД,Стороны,ТекущиеЭтапы"`, проверяет тип и ID. Живой ответ №7 вернул участников в `Стороны.Отправитель`, `Стороны.Перевозчик`, `Стороны.Получатель`; каждый содержит `СвЮЛ` с ИНН/КПП. Это отличается от верхних полей записи. Также получены `ГИС_УИД`, `Расширение.ГИС_УИД`, `КодПеревозки`, `ТекущиеЭтапы`; ссылки вложений используют `disk.saby.ru`.

`sabyDocumentWorkflow()` предоставляет ID редакции, состояние Saby, доступные действия, безопасную ссылку и метаданные файлов. `reported_by_saby` означает, что Saby вернул данные подписи; это не локальная криптографическая проверка и не завершение всех этапов. `gisStatus` появляется только при возвращённом идентификаторе ГИС ЭПД, не выводится из общего слова «завершено». Отсутствие подписей в частичном ответе считается `unknown`.

`downloadAttachment(documentId, attachmentId, expectedRevision)` заново читает документ, проверяет ожидаемую редакцию, находит вложение в актуальном ответе и скачивает через серверную сессию. Произвольный URL, чужой домен, URL с credentials/session, нестандартный порт, небезопасная схема и redirect отклоняются; максимальный размер — 20 MiB. Для передачи сессии допускаются только известные download-хосты `disk.saby.ru`, `disk.sbis.ru`, `online.saby.ru`, `online.sbis.ru`, `tms.saby.ru`. Ссылки обновляются чтением: по [документации чтения](https://saby.ru/help/integration/api/all_methods/read_doc) они ограничены сроком действия. Файлы выдаются API как скачивание с контролем доступа к рейсу. Кроме исходного XML, метаданные включают возвращённые Saby подписи, PDF и архив; внутренние ID этих файлов привязаны к редакции.

## Приватная конфигурация и доказательства

Ответы и безопасная сводка расположены вне Git в `private/saby/access/capabilities-20260929/` внутри защищённого каталога Application Support. Секреты, ФИО, номера сертификатов и реквизиты документов сюда не копируются. Создан отдельный `private/saby/access/runtime-candidate.env` с прежним доступом и точными текущими ИНН/КПП/названиями/юридическими адресами из ответа кабинетов; исходный `credentials.env` сохранён без изменений. В актуальном ответе организаций отсутствует телефон, а `Идентификатор` участника пустой: исторические значения автоматически не подставлены. Дополнительно `SABY_CONSIGNMENT_SIGNER_JSON` содержит только ФИО и должность из действующего сертификата; совпадение ФИО владельца и записи сотрудника проверено программно. Серверный парсер принимает только `surname`, `name`, `patronymic`, `position`; основание полномочий и подтверждение сведений автоматически не устанавливаются. Файл имеет формат необработанных `KEY=value`; его нельзя выполнять как shell-скрипт.

`СБИС.ИнформацияОКонтрагенте` не использовался как чистое чтение: [официальное описание](https://saby.ru/help/integration/api/counterparty) допускает создание контрагента при его отсутствии. Диагностика не меняла справочники и рабочий учёт.

Синтетические проверки клиента: создание/чтение правильного типа, защита ID, поиск после неопределённого результата, разделение состояния/подписи/ГИС, допустимые домены, свежие ссылки файлов, защита смены редакции, запрет подмены вложения/redirect/превышения размера, подписи/PDF/архив, чтение сертификатов без подписания, безопасное предзаполнение ФИО. ID PDF/архива зависят от метаданных подписей, событий и состояния: появление новой подписи меняет ID даже при прежней XML-редакции. Короткоживущие URL не участвуют в ID. Команда: `node --import tsx --test tests/saby-client-workflow.test.ts` — 13/13; вместе с прежними `api-saby` — 35/35; TypeScript и ESLint прошли. Это не доказательство новой записи в действующем Saby.

Новый `SabyClient` дополнительно проверен живым чтением №7 с сетевым адаптером `curl --interface en0`: `readConsignmentNote`, `downloadAttachment` с ожидаемой редакцией и `listRegisteredCertificates` выполнены успешно. Получены 22 файла/представления в метаданных; XML первого титула — 5150 байт, SHA-256 совпал с приватным оригиналом. Скачаны настоящая подпись (8088 байт), PDF (129910 байт), архив Saby (301591 байт). PDF/архив при первой попытке завершились транспортной ошибкой; повтор выполнился успешно. Подписи и идентификатор ГИС в этом ответе относятся только к старой №7. Приватная сводка: `capabilities-20260929/client-readonly-check-summary.json`.

Дополнительное наблюдение: успешная историческая №7 имеет непустое `Состояние.Примечание`, но у всех вложений `КоличествоОшибок="0"`. Произвольное примечание не является ошибкой ФЛК. При подтверждении новой записи следует проверять действующий, неудалённый первый титул и его число ошибок, а не запрещать любое пояснение состояния.
