# Область просмотра по разделам — 26.10.2026

Реализовано локально. Публикация, commit/push и изменение действующих учётных записей не выполнялись.

## Подтверждённые правила

- Один клиент закрепляется за одним сотрудником. Новое назначение заменяет предыдущее; владельцы исторических отгрузок не переписываются.
- Для обзора, отгрузок и работы независимо выбираются «Нет доступа», «Только свои», «Все».
- Для клиентов в справочнике отдельно выбирается та же область. «Все клиенты» не открывает чужие отгрузки, расчёты обзора или задачи.
- Поставщики, нефтебазы, товары, формы оплаты, автомобили и водители — общие справочники с отдельным разрешением. Сотрудники и адреса также допускают область «Только свои».
- По последнему уточнению пользователя «Рейсы» остаются разрешением на страницу. Общая очередь заявок, прежняя изоляция рейсов и операции Saby не меняются.
- Расширение просмотра не назначает администратора и не даёт новых прав изменения чужих отгрузок или задач. Прежние полномочия остальных страниц, включая банковские операции, Китай и управление аккаунтами, сохраняются.

## Реализация

`AccountUser.readScopes` хранит независимые области `overview`, `shipments`, `work`. `directoryScopes` хранит разрешения отдельных справочников. Список `sections` по-прежнему разрешает страницы; область `all` не обходит выключенный раздел. Неизвестные ключи/значения и область `own` для общих справочников отклоняются API и валидатором хранилища. Изменение прав завершает прежние сеансы.

Отсутствующие новые поля совместимы с прежними аккаунтами. Существующие записи автоматически не мигрируют и доступ массово не выдаётся. Директор и администратор сохраняют действующие полномочия. Понижение роли не наследует полный доступ.

Сервер отдельно формирует ответы для справочников, отгрузок, рейсов и работы. Список всех клиентов не расширяет отгрузки, фильтры, поиск, постраничный экспорт или финансовый обзор. Карточки общего поставщика с дополнительной ролью клиента не раскрывают закрытую клиентскую категорию и историю. Формам отгрузки остаются необходимые справочные значения; закрытие отдельного справочника не запрещает показать название участника разрешённой отгрузки.

Обзор использует прежние расчёты: область применяется к готовому результату. «Все» учитывается как в общем обзоре, так и в разрезе организаций. Распределение денег не пересчитывается по новой формуле.

В отгрузках чужие строки при расширенном просмотре помечаются доступными только для чтения; их изменение отвергает и сервер. В работе можно читать чужую задачу и её вложения при разрешении «Все», но изменения и удаление остаются ограничены прежним владельцем/администратором.

Назначение через карточку компании уже заменяло ответственного; маршрут назначения через справочник теперь удаляет все прежние связи этого клиента перед сохранением одной. Неоднозначные исторические связи не выбираются произвольно. Старое правило доступа к неназначенным историческим клиентам по своим отгрузкам сохранено; массовое распределение клиентов не выполнялось.

## Проверки

- Общий набор текущего локального checkout: **541 API-тест + 3 bank-period**, все прошли.
- Пять новых API-сценариев: независимость клиентов/отгрузок/обзора; режим всех отгрузок без права записи; общий поставщик без клиентской истории; все задачи без права чужой правки; валидация, сохранение прав, отзыв сеанса и замена ответственного. Повтор после окончательного уточнения по рейсам прошёл.
- TypeScript, ESLint, сборка frontend и server прошли.
- Базовый браузерный сценарий сохранения прав и «Все клиенты / свои отгрузки» прошёл в Chromium/WebKit, 320/1440 px, на исходниках и сборке.
- Расширенная браузерная проверка прошла на исходниках и итоговой сборке: Chromium/WebKit, 320/1440 px. Подтверждены сохранение прав, независимость клиентов/отгрузок, скрытие вкладок, просмотр чужих отгрузок и задач без возможности изменения, отсутствие горизонтального переполнения. Итоговые JSON и журналы находятся в `.local/section-access/`.
- Первые расширенные UI-прогоны сохранены как неуспешные: сценарий повторного входа сначала не перезагружал прежнюю страницу, затем делал лишнюю навигацию перед reload, прерывая запросы WebKit. Исправлен сценарий теста; итоговые повторные прогоны без ошибок.
- После последнего ограничения списка ID назначенных клиентов повторены 42 целевые проверки прав, работы и взаиморасчётов — все прошли.

Браузерный инструмент: `node --import tsx scripts/verify_section_access.mjs`; сборка: тот же запуск с `--built`. Используются только синтетические snapshot и временное хранилище, внешние провайдеры отключены. Пароли QA случайные и не публикуются.

## Граница публикации

Рабочий сайт и реальные права сотрудников этим этапом не изменены. Изменения подготовлены в существующем локальном checkout с сохранением прежних правок. Срез исходников в production может отличаться: перед публикацией нужен перенос узкого патча на свежий действующий серверный исходник и обычная проверка сохранности. Выпускать текущий локальный backend целиком поверх production без такой сверки нельзя, в том числе из-за сохранённых изменений Saby и просмотра новых паролей.
