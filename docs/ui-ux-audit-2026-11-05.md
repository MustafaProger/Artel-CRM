| Ошибка обновления snapshot размонтирует весь текущий раздел | Ошибка показывается рядом с данными; доступен повтор. При отказе авторизации данные очищаются | `App.tsx` |
| Ошибка чтения выглядит как пустая база или отсутствие подключений | Пустое состояние показывается после успешного чтения; ошибка первого запроса не подменяется пустыми данными | Документы, Китай, банки, сотрудники |
| Уведомление «Изменения сохранены» прижато к карточке | Между уведомлением и списком установлен отступ 16 px | `directories.css` |
| В «Работе» удаление сразу отправляет запрос | Добавлено подтверждение с отменой; отдельно показаны сохранение, удаление, архивация и возврат | `WorkPage.tsx` |
| Ошибка или подтверждение закрытия остаётся за пределами прокрутки формы | Подтверждения и ошибки получают фокус и прокручиваются в видимую область | Работа, справочники, Китай |
| Кабинет теряет введённые данные при закрытии или смене сервиса | Явное подтверждение сброса, продолжение редактирования, блокировка во время запроса | `CabinetBalances.tsx` |
| Повторная загрузка кабинетов после ошибки не показывает ожидание | Повтор запускает скелет и блокирует повторное нажатие | `CabinetBalances.tsx` |
| Повторный быстрый Escape после ошибки сохранения закрывает занятую форму | Escape передаётся существующим проверкам формы до штатного закрытия браузером. Открытые списки выбора получают Escape первыми | `useDialogMotion.ts` |
| Кнопки и длинные подписи стесняются на узком экране | Подвал формы переносится; текст уведомлений и подтверждений переносится, действия остаются доступными | Работа, справочники, кабинеты |

Анимация скелета использует transform. При `prefers-reduced-motion: reduce` она отключается. Служебная надпись доступна скринридеру и скрыта визуально. Фоновый индикатор расположен у верхней границы и не добавляет высоту в список. Короткие индикаторы проверки доступа, сохранения, загрузки тайлов карты и дополнительных полей оставлены там, где они обозначают отдельное действие внутри уже открытого интерфейса.

## Покрытие разделов

Для каждого из 12 разделов проверены первая загрузка, готовое состояние, ошибка HTTP и восстановление в Chromium/WebKit. Ширины: 1440, 375 и 320 px.

| Раздел | Дополнительные сценарии |
| --- | --- |
| Обзор | Карточки скелета, повтор загрузки, обычная/ограниченная анимация |
| Работа | Создать/изменить/удалить задачу; ошибка и повтор; блокировка запроса; подтверждение; неизменность DOM/геометрии/прокрутки при обновлении |
| Отгрузки | Таблица, фильтры, поиск, CSV, формы обычной отгрузки и АЗС; геометрия на 11 ширинах |
| Рейсы | Загрузка справочников/заявок/рейсов, сохранение и удаление учебного рейса; отдельный сценарий после прибытия водителя |
| Платежи | Загрузка/ошибки банковских подключений и реквизитов; формы и адаптивность; реальный запрос в банк не выполнялся |
| Балансы кабинетов | Загрузка/повтор; закрытие черновика, смена сервиса; ввод настоящих доступов и подключение не выполнялись |
| Китай | Добавление/изменение дня, добавление платежа; ошибка/повтор/блокировка; сохранение ввода при отмене закрытия |
| Счета | Синтетический каталог/история, выбор покупателя, формы, состояния обработки; отдельный mock-worker suite |
| Операторская | Создание/изменение/удаление операции на учебном задании, ошибка/повтор/подтверждение, восстановление тестового баланса |
| Сотрудники и доступ | Создание/изменение/удаление учебной учётной записи, точное имя при удалении, отмена, ошибка/повтор; запись сотрудника в справочнике сохраняется |
| Справочники | Создание/изменение/удаление товара, длинное правдоподобное название, сохранение ввода, уведомление и доступность действий |
| Документы | Категории и карточки, создание/изменение/удаление, ошибки и повторные действия, подтверждения |

В «Китае» текущий интерфейс не предоставляет удаления дня/платежа и изменения платежа — эти действия не добавлялись и не объявляются проверенными. Полный перебор каждого сочетания доменных правил и каждого поля не заявляется. Реальные банковские операции, выпуск счета в 1С, Saby Create/Execute и подписание не запускались.

- TypeScript, полный ESLint и `build:production` — PASS.
- Основной UI-аудит: **168 состояний страниц и 42 попытки CRUD** в каждом из прогонов source и built. Это попытки с задержками, намеренными ошибками и повтором, а не 42 разных бизнес-функции.
- Дополнительный built-аудит Китая/учётных записей: **36 попыток изменений, 8 групп сценариев**, оба движка × 375/320.
- Рейсы: source и точная сборка — по **4 сценария PASS**, Chromium/WebKit 375/1440, изменение и удаление после прибытия, axe 0, внешних запросов 0.
- Отдельно **4 проверки Escape** внутри списка выбора и формы, без записей.
- Общая проверка точной сборки: **184 наблюдения страниц, 16 форм, 14 групп**, шесть ролей. Отказы доступа, вход/выход, изоляция, CSP и локальная загрузка файлов — PASS.
- В перечисленных финальных прогонах: ошибок JavaScript **0**, внешних запросов **0**, горизонтального переполнения страницы **0**.

Дополнительные проверки исходников в ходе аудита: работа — 60 наблюдений на ширинах 320–1920; счета — 53 проверки и 184 сканирования axe с mock-worker; форма сотрудников — 16 проверок размеров/фокуса; отгрузки — 22 проверки размеров/таблицы/форм. Это дополнительные наборы, их числа не суммируются в число уникальных функций CRM.

Первые отказы QA сохранены. В частности, ошибка повторного Escape воспроизводилась до изменения общего обработчика и исчезла в проверках после исправления. Три отказа WebKit в verifier рейсов воспроизведены и на неизменённой исходной версии: немедленный reload прерывал три чтения после сохранения. Verifier теперь дожидается ответов и обновлённой карточки; ошибки не фильтруются. Диагностика обеих версий сохранена в `qa-trip-diagnostic-{candidate,baseline}` и `trip-lifecycle.log`.

Старые verify_work/verify_directories с устаревшими селекторами или рабочим XLSX не выдавались за успешный тест новой версии.
