## Подтверждённые правила

- В разделе «Рейсы» одна капсула: «Заявки», «Карта», «Рейсы».
- Пользователь отдельно подтвердил общую очередь для всех сотрудников с доступом к рейсам. Справочник очереди содержит необходимые компании и места доставки, без банковских и финансовых данных других сотрудников.
- Заявка содержит компанию, одну конкретную площадку доставки этой компании, положительное количество литров и комментарий. Несколько мест одной компании остаются разными вариантами выбора.
- По уточнению пользователя обязательность заявки временно отключена: новый рейс и новые доставки можно заполнять напрямую из справочника. Заявку можно выбрать дополнительно; тогда компания, адрес и комментарий переносятся из неё, количество литров можно уточнить в рейсе. Исходный объём сохраняется в истории заявки. Срок автоматического возврата ограничения не установлен.
- После успешного сохранения рейса выбранные заявки целиком переходят в историю и больше не присутствуют в активной очереди, карте и выборе нового рейса. Остаток автоматически не создаётся. Это уточнено пользователем отдельно.
- История хранит исходную заявку, её снимок адреса и связь с рейсом/доставкой. Удаление рейса само по себе не возвращает заявку в очередь.

## Сохранение и доступ

Заявки хранятся в `OperationsStore` аддитивно. Создание рейса и потребление заявок проходят в одной файловой транзакции. Весь запрос откатывается при ошибке любой доставки. Версии обнаруживают устаревший выбор, а общий lock оставляет только одного победителя при одновременном выборе одной заявки. Повтор точного запроса после потери ответа возвращает уже созданный рейс.

Для доставки, связанной с заявкой, сервер запрещает подставлять другой источник, компанию, место и комментарий вручную. Общая заявка может принадлежать компании, закреплённой за другим сотрудником: создатель рейса получает доступ к своей новой доставке, но не к чужим отгрузкам, балансу или банковским реквизитам клиента. По новому поручению требование обязательной заявки выключено и в штатном авторизованном API. Прямое заполнение сохраняет обычные ограничения доступа к клиентам; общая очередь не расширяет права для прямых доставок без заявки.

3. Задать `ARTEL_YANDEX_MAPS_API_KEY` в защищённом окружении сервера. Не отправлять ключ в чат, не добавлять его в исходники/Git и не печатать в журнал. Пустой пример добавлен в `.env.example`.
4. После выпуска/перезапуска проверить авторизованную вкладку «Карта» на реальных площадках, точность адресов, подсказку и исчезновение выбранных точек после действительного рейса.

Авторизованный `/api/trip-requests/map-config` возвращает только конфигурацию браузерной карты. На карту попадают активные заявки; маркер показывает компанию, адрес и литры при наведении и нажатии. Для клавиатуры и телефона есть список площадок с переходом к точке. Несколько заявок с одними координатами собираются в один маркер, содержащий сведения обо всех этих заявках.

Сначала используются сохранённые координаты площадки либо явно отмеченная точка `pt` в ссылке Яндекса. Параметр центра карты `ll` не выдаётся за координаты площадки. Если в заявке координат не было, карта принимает добавленные позднее координаты из справочника только при совпадении компании, площадки и полного адреса. Исторический снимок заявки не меняется; изменённый адрес не подставляется. При отсутствии координат адрес ищется через Яндекс; неоднозначный или неточный ответ требует уточнить площадку. Результаты геокодирования живут только в памяти открытой карты, в справочник и долговременное хранилище автоматически не записываются.

Без ключа интерфейс показывает «Карта не подключена» и доступный список активных площадок. Реальная загрузка карт и точность геокодирования Яндекса в этой работе не подтверждены: ключ отсутствует.

Документация провайдера: [метки и подсказки](https://yandex.ru/dev/jsapi-v2-1/doc/ru/v2-1/ref/reference/Placemark), [геокодирование JavaScript API](https://yandex.ru/dev/jsapi-v2-1/doc/ru/v2-1/ref/reference/geocode), [точность результата геокодера](https://yandex.ru/maps-api/docs/geocoder-api/response.html).
