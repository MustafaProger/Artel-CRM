## Причина и исправление

На скриншоте — отказ optimistic concurrency: отправленная версия автомобиля не совпала с текущей. Прежняя форма брала данные из общего снимка, не перечитывала запись перед сохранением и предлагала закрыть карточку при 409. При обновлении родительского снимка она также могла совместить старый ввод с новой версией: строковые поля и версия имели разный жизненный цикл. Кто и когда изменил конкретную запись на скриншоте, по одному изображению не установлено.

Теперь исходный снимок фиксируется на время редактирования. Перед PATCH запрашивается актуальный снимок без кэша и сравниваются исходные, введённые и текущие значения. Независимые изменения объединяются; изменения одного поля показываются с выбором «Моё значение» / «Сохранённое значение». Ввод остаётся в форме. После выбора пользователь нажимает «Применить выбор» и «Сохранить»; перед записью выполняется новая сверка. При гонке между чтением и PATCH выполняется один повтор сверки, серверная проверка версии остаётся обязательной.

Для адресов компании список сверяется целиком: смысл удаления/добавления автоматически не угадывается. Технические версии адресов не считаются пользовательскими изменениями, но при отправке берутся из актуального снимка. Сбои сети и потеря ответа PATCH не закрывают форму; быстрое повторное submit блокируется синхронно. Поздний ответ общего снимка больше не отменяет более свежий. Пустой список секций автомобиля остаётся намеренным очищением.

Область изменения: редактор автомобилей, водителей, клиентов/поставщиков, нефтебаз, участников погрузки, мест и остальных обычных справочников. Скрытая отдельная форма назначения менеджера сохраняет прежний POST-путь. Серверные API, хранилище, правила Saby и внешние документы в этом выпуске не изменялись.
