## Конкретный пробел диагностики в коде

После принятого Execute `dispatchPreparedSigning` сохраняет общий `acknowledged`, затем вызывает `readSigningEvidence`. Полный ответ Execute не сохраняется штатным кодом. Если подписи нет, чтение состояния 23 возвращает общее `pending`. Сам планировщик не получает сведения о служебном задании отложенного подписания и не объясняет, почему оно не исполнено. Поэтому интерфейс способен неопределённо долго показывать ожидание без причины.

Это подтверждённое ограничение диагностики, но не доказанная причина отсутствия подписи №21. Подмена режима, повторный Execute или ослабление проверки файлов не следуют из результатов аудита. Для дальнейшего установления причины нужны сведения именно о существующем служебном задании №21; чтение такой очереди должно быть без блокировки заданий и без повторных действий с документом.
