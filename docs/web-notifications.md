# Web Push и напоминания

В разделе «Работа → Напоминания» доступны включение, выключение и проверка уведомлений текущего устройства. Разрешение браузера запрашивается только после нажатия кнопки. Подписка хранится в закрытом хранилище CRM и относится к вошедшему сотруднику. Уведомления получают исполнители задач и записей о работе с компаниями, когда наступает `reminderAt`. Время вводится в часовом поясе устройства и хранится в UTC.

На iPhone/iPad (iOS/iPadOS 16.4+) добавьте CRM на экран «Домой», запустите с её значка, войдите и нажмите «Включить уведомления». На компьютере и Android используйте браузер с поддержкой Push API. Нажмите «Проверить уведомление», чтобы проверить доставку. Разрешение также должно быть включено в настройках ОС; режим фокусирования и отсутствие сети могут задержать уведомление.

Service worker показывает уведомления и при закрытой странице. Его регистрация не включает офлайн-кеширование финансовых данных. Manifest и PNG-иконки обеспечивают установку приложения. Нажатие на уведомление открывает связанную запись; при необходимости сначала появляется обычный вход. Подробности задачи не передаются на экран блокировки. Завершённые, архивные записи и отключённые сотрудники исключены. При выходе отключается устройство этого сеанса, а другие устройства продолжают работать.

## Серверные настройки

- `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` — пара ключей Web Push. Сгенерировать один раз через `web-push.generateVAPIDKeys()` и хранить вне Git. Ротация требует повторной подписки устройств.
- `VAPID_SUBJECT` — контактный `mailto:` или HTTPS URL (для этого проекта `https://artel-crm.vercel.app`).
- `PUSH_SCHEDULE_ENABLED=true` — включать после настройки фонового расписания.
- `CRON_SECRET` — случайный секрет не короче 32 символов для ручного вызова и внешнего планировщика. В GitHub Actions не требуется.

Браузеру выдаётся только публичный ключ. API подписки и тестирования требует сеанс и проверку источника запроса; подписку нельзя создать для произвольного сотрудника. Адреса ограничены известными push-сервисами браузеров. Тестовая отправка ограничена одной попыткой за 30 секунд.

## Фоновое расписание

Production: `.github/workflows/reminders.yml` запускается каждые 5 минут (также есть ручной запуск в Actions и проверка при обновлении самого workflow в `main`). Вызов `GET /api/push/dispatch` подписан короткоживущим GitHub OIDC токеном. Сервер проверяет подпись, issuer, audience, срок, ID репозитория и владельца, ветку `main`, точный путь workflow и тип события. Ключи VAPID и хранилища остаются в Vercel; постоянный секрет в GitHub не нужен. Это работает на Vercel Hobby, где собственный cron ограничен одним запуском в сутки.

GitHub не гарантирует точное время: расписание может задерживаться при нагрузке. В публичном репозитории оно отключается после 60 дней без активности — включите его снова в Actions. CRM показывает предупреждение, если последний запуск был более 20 минут назад. Для строгого интервала в минуту используйте отдельный планировщик с `Authorization: Bearer <CRON_SECRET>` или подходящий тариф Vercel.

Локально Vite dev/preview проверяет напоминания каждые 30 секунд при настроенных переменных. Процесс сервера должен работать. Закрывать вкладку CRM можно. Ключи задаются в `.env.local`; после изменения переменных перезапустите сервер. Хранилища localhost и production независимы, поэтому подписку включают отдельно на каждом адресе.

Доставка резервируется атомарно до сетевой отправки. Ключ включает запись, время напоминания и устройство; повторный запуск не отправляет уже доставленное напоминание. Временные ошибки повторяются с задержкой до часа, подписки с ответами 404/410 удаляются. При смене исполнителя, даты, архивировании и удалении запись проверяется снова перед отправкой. В одном запуске обрабатывается до 20 доставок; остаток попадёт в следующие запуски. Если процесс прервался после приёма сообщения push-сервисом, но до сохранения результата, возможна повторная доставка: одинаковый notification tag заменяет видимое уведомление. TTL сообщения — один час.

## Проверки

`npm run test:api` включает права доступа, проверку подписок, повторную/конкурентную отправку, смену исполнителя и времени, отключение устройства, повтор после ошибки, удаление истёкшей подписки и проверку GitHub OIDC. `npm run test:push-ui` проверяет формы в Chromium и WebKit, подключение и service worker в изолированном хранилище.
