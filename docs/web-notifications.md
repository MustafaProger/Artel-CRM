# Web Push и напоминания

В разделе «Работа → Напоминания» доступны включение, выключение и проверка уведомлений текущего устройства. Разрешение браузера запрашивается только после нажатия кнопки. Подписка хранится в закрытом хранилище CRM и относится к вошедшему сотруднику.

- Если сотрудник назначает задачу другому человеку или передаёт существующую задачу, исполнителю сразу после сохранения отправляется уведомление о назначении. Поле «Напоминание» для этого не требуется.
- Если у задачи задано напоминание, после наступления его времени исполнителю отправляется отдельное уведомление. Оно работает и для задач, созданных самому себе.
- Создание задачи себе и обычное редактирование без смены исполнителя не создают уведомление о назначении. Повтор сохранённого запроса не дублирует назначение.

У записей о работе с компаниями отправляются напоминания по заданному времени. Время вводится в часовом поясе устройства и хранится в UTC; редактирование других полей сохраняет точное исходное время. Получателю нужно включить уведомления на своём устройстве.

На iPhone/iPad (iOS/iPadOS 16.4+) добавьте CRM на экран «Домой», запустите с её значка, войдите и нажмите «Включить уведомления». На компьютере и Android используйте браузер с поддержкой Push API. Нажмите «Проверить уведомление», чтобы проверить доставку. Разрешение также должно быть включено в настройках ОС; режим фокусирования и отсутствие сети могут задержать уведомление.

Кнопка проверки теперь различает отправку сервису уведомлений и получение браузером. Сообщение «Браузер получил тестовое уведомление» появляется только после подтверждения от service worker, создавшего уведомление. До этого CRM ожидает подтверждение до минуты; отсутствие ответа означает, что получение не подтверждено. Повторной автоматической отправки теста нет. Для обычных задач и напоминаний дополнительных подтверждений не запрашивается.

При временной сетевой ошибке worker повторяет только подтверждение до трёх раз, без повторного создания уведомления. Подключение показывает текущий этап и ограничивает ожидание: запрос разрешения — 30 секунд, подготовка — 15, подключение браузера — 25, ответ CRM — 15. Если браузер продолжает подключение после истечения ожидания, повторное нажатие ждёт ту же операцию; параллельная подписка не создаётся.

Service worker показывает уведомления и при закрытой странице. Его регистрация не включает офлайн-кеширование финансовых данных. Manifest и PNG-иконки обеспечивают установку приложения. Нажатие на уведомление открывает связанную запись; при необходимости сначала появляется обычный вход. Подробности задачи не передаются на экран блокировки. Завершённые, архивные записи и отключённые сотрудники исключены. При выходе отключается устройство этого сеанса, а другие устройства продолжают работать.

## Серверные настройки

- `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` — пара ключей Web Push. Сгенерировать один раз через `web-push.generateVAPIDKeys()` и хранить вне Git. Ротация требует повторной подписки устройств.
- `VAPID_SUBJECT` — контактный `mailto:` или HTTPS URL (для этого проекта `https://artel-crm.vercel.app`).
- `PUSH_SCHEDULE_ENABLED=true` — включать после настройки фонового расписания.
- `CRON_SECRET` — случайный секрет не короче 32 символов для ручного вызова и внешнего планировщика. В GitHub Actions не требуется.

Браузеру выдаётся только публичный ключ. API подписки и тестирования требует сеанс и проверку источника запроса; подписку нельзя создать для произвольного сотрудника. Адреса ограничены известными push-сервисами браузеров. Тестовая отправка ограничена одной попыткой за 30 секунд. Статус проверки видит только её владелец. Подтверждение от worker использует случайный токен со сроком пять минут, переданный внутри зашифрованного push; в хранилище остаётся только его хеш. Повтор подтверждения не меняет сохранённое время.

## Фоновое расписание

Production: `.github/workflows/reminders.yml` настроен на каждые 5 минут (также есть ручной запуск в Actions и проверка при обновлении самого workflow в `main`). Вызов `GET /api/push/dispatch` подписан короткоживущим GitHub OIDC токеном. Сервер проверяет подпись, issuer, audience, срок, ID репозитория и владельца, ветку `main`, точный путь workflow и тип события. Ключи VAPID и хранилища остаются в Vercel; постоянный секрет в GitHub не нужен. Это работает на Vercel Hobby, где собственный cron ограничен одним запуском в сутки.

GitHub не гарантирует точное время: расписание может задерживаться при нагрузке. В публичном репозитории оно отключается после 60 дней без активности — включите его снова в Actions. CRM показывает предупреждение, если последний запуск был более 20 минут назад. Для строгого интервала в минуту используйте отдельный планировщик с `Authorization: Bearer <CRON_SECRET>` или подходящий тариф Vercel.

Локально `npm run dev` / preview проверяет напоминания каждые 30 секунд при настроенных переменных, независимо от открытой страницы CRM. Процесс сервера должен работать, компьютер не должен находиться в спящем режиме. Закрывать вкладку CRM можно. Ключи задаются в `.env.local`; после изменения переменных перезапустите сервер. Хранилища localhost и production независимы, поэтому подписку включают отдельно на каждом адресе. Сведения о последней проверке обновляются в видимой вкладке раз в минуту и при возвращении к ней.

Для запуска расписания отдельно от dev-сервера подготовлены [локальный runner и шаблоны systemd](../ops/reminders/README.md). По умолчанию runner обращается только к localhost. В обычном dev-режиме запускать его параллельно встроенной проверке не требуется. По решению пользователя размещение на сервере отложено: службы не устанавливаются, опубликованный сайт не обновляется.

Доставка резервируется атомарно до сетевой отправки. Ключ напоминания включает запись, время напоминания и устройство; повторный запуск не отправляет уже доставленное напоминание. Назначение сохраняется вместе с задачей и использует отдельный ключ по версии назначения и устройству, поэтому не заменяет её напоминание. Если немедленная попытка не удалась, задача остаётся сохранённой, а планировщик повторяет отправку. Актуальное назначение доступно для отправки в течение суток; предыдущие назначения отменяются при смене исполнителя.

Временные ошибки повторяются с задержкой до часа, подписки с ответами 404/410 удаляются. При смене исполнителя, даты, архивировании и удалении запись проверяется снова перед отправкой. Завершение задачи и отзыв доступа к разделу «Работа» также отменяют отправку. В одном запуске обрабатывается до 20 назначений и 20 напоминаний; остаток попадёт в следующие запуски. Если процесс прервался после приёма сообщения push-сервисом, но до сохранения результата, возможна повторная доставка: одинаковый notification tag заменяет видимое уведомление. TTL сообщения — один час.

## Проверки

`npm run test:api` включает назначение другому сотруднику, напоминания по чужим и собственным задачам, права доступа, проверку подписок, повторную/конкурентную отправку, смену исполнителя и времени, отключение устройства, повтор после ошибки, удаление истёкшей подписки и проверку GitHub OIDC. `npm run test:push-ui` проверяет формы в Chromium и WebKit, подключение и service worker в изолированном хранилище.

`node scripts/verify_task_notifications.mjs` проверяет сохранение времени из формы, неизменность секунд и миллисекунд при редактировании других полей, изменение и удаление напоминания, работу с компаниями и открытие задачи по ссылке уведомления. Проверка использует временное хранилище и отключённую отправку push.

### Локальная проверка 16 сентября 2026

Локально прошли все 126 API-тестов, включая 19 тестов push и назначений. Проверены подтверждения браузера, срок и права токенов, гонки, повтор подтверждения и ошибка сохранения результата после успешной отправки. Целевая проверка форм прошла в Chromium и WebKit: по восемь сценариев, без ошибок браузера. Транспорт push в API-тестах подменён, а в проверках форм отключён. Отдельный замер встроенного расписания показал интервалы 29 967 и 29 999 мс; ручной вызов планировщика для этого не использовался.

Ещё один изолированный прогон ожидал настоящее время: назначение другому сотруднику отправилось сразу, собственная задача — без раннего уведомления. Оба напоминания обработал встроенный планировщик через 14,121 секунды после указанного времени. Следующий цикл подтвердил отсутствие дублей. В этом прогоне подменён только транспорт push; время и запуск планировщика не подменялись. Это подтверждает локальную серверную обработку, а не доставку на устройство.

Сборка, ESLint и `test:push-ui` прошли. В автоматизированном браузере транспорт подписки подменялся, событие push для настоящего worker создавалось синтетически. Дополнительно проверены зависшее подключение, повтор без параллельной подписки, поздний ответ браузера и тайм-аут HTTP без ложного успеха.

После включения разрешения пользователем проверена настоящая доставка в Chrome на локальном адресе `http://127.0.0.1:5174` с отдельным временным хранилищем. Получены четыре подтверждения создания уведомления браузером: тест, назначение другим сотрудником, напоминание по этой задаче и напоминание по собственной задаче. Оба напоминания пришли при закрытой вкладке CRM; процесс локального сервера продолжал работать. Использован настоящий `sendPush` и сервис Web Push, без подмены транспорта или push-событий. Только в тестовом процессе к сообщениям задач добавлялся токен подтверждения, чтобы проверить получение. Подтверждение означает успешный `showNotification` и ответ worker, а не прочтение человеком; опубликованный сайт этой проверкой не охвачен.

Напоминания назначены на 12:49:45,473 МСК и отправлены через 5,966 и 5,972 секунды после срока; подтверждения браузера получены примерно через 6,6 секунды после срока. Дополнительный автоматический цикл в 12:50:21 МСК подтвердил отсутствие дублей. Все три доставки по задачам сохранены успешно, токены подтверждения соответствуют четырём фактическим отправкам. Полный локальный отчёт: `.vercel/local-real-push-result.json` (без секретов).
