# Покадровый переаудит загрузки — 05.11.2026

Исправлено локально. Production не менялся. Предпросмотр: http://127.0.0.1:5261/__preview. Галерея оригинальных кадров и видео: http://127.0.0.1:5261/__loading-audit/.

## Что было пропущено

Первая итерация UI-аудита проверяла отдельные состояния и не выявила переходы между ними. Общий skeleton показывался на уровне lazy-модуля и предварительного snapshot, затем заменялся другим внутри раздела. В счетах одновременно существовали две отдельные заглушки. В холодной карте загрузка данных могла сменяться новым ожиданием модуля.

На неизменённой копии первой итерации записано 96 переходов: 12 разделов × прямое открытие/переход из меню × 1440/375 px × Chromium/WebKit. Все 96 имели повторное монтирование skeleton, 88 — смену его формы, 8 — два skeleton одновременно. Это число тестовых переходов, а не независимых дефектов.

## Исправления

- Начальная загрузка модуля и предварительных данных использует нейтральную «Загрузка…». Затем раздел показывает один собственный skeleton до готовности содержимого. Импорт разрешённого раздела начинается параллельно со snapshot.
- В справочниках данные уже готовы после snapshot: нейтральный индикатор сменяется сразу списком, без искусственной дополнительной задержки.
- Счета используют один общий макет формы и истории. Настройки заблокированы до первого ответа.
- Карта рейсов загружает модуль параллельно данным; один внешний placeholder остаётся на месте до готовности обоих. Ошибка импорта имеет повторную попытку.
- Заголовки и мобильное меню сохраняются на промежуточных этапах, включая отгрузки.
- Позднее завершение операции на старой странице не отменяет загрузку новой страницы. Ранее введённые данные формы сохраняются при обновлении.

## Метод и ограничения

Файлы раздела, предварительный контекст и последующие API задерживались независимо. DOM, геометрия и идентичность элементов записывались каждый requestAnimationFrame. Для каждого перехода сохранены четыре исходных PNG с временными интервалами и непрерывное WebM-видео 25 кадров/с. Галерея позволяет переключить браузер/ширину/тип перехода и двигаться по видео с шагом 40 мс. Снимки не перерисовывались.

Структурные прогоны используют reduced-motion. В обычном режиме снимки делаются в пределах viewport: первоначальный fullPage-захват сам менял геометрию во время снимка кабинетов; этот диагностический отказ сохранён, а контроль с viewport и непрерывным видео прошёл. Проверка shimmer подтвердила transform-анимацию 1,8 с и отключение при reduced-motion.

Все записи учебные, в отдельных временных хранилищах; реальные документы, деньги, подписи, аккаунты и провайдеры не использовались. Банковские ответы, счета и остатки кабинетов синтетические. В обзоре выбранная по умолчанию вкладка поставщиков осталась пустой даже в заполненном fixture: проверены её оболочка, итоги, фильтры и empty state; заполненные строки этого конкретного среза отдельно не подтверждаются. Физические телефоны, Firefox и все возможные сочетания данных не проверялись.

Сохранены исходные отказы QA: старые ожидания invoice-loading, гонка закрытия drawer в verifier, fullPage-артефакт и визуальная ошибка ширины Китая до исправления. Старый функциональный verifier адаптирован к нейтральному начальному ожиданию; CRUD-проверки не ослаблялись.
