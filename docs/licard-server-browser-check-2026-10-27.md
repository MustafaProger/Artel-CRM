# Нагрузка Яндекса и проверка ЛУКОЙЛ — 27.10.2026

Поручение: оценить влияние серверного браузера Яндекса на CRM и попробовать аналогичное подключение ЛУКОЙЛ. Данные со скриншота не сохранялись в исходники/отчёт и не отправлялись: обе страницы ЛУКОЙЛ отказали до формы входа.

## Измерения

Сервер: **4 vCPU**, около 4 ГБ RAM, доступно 1715 MiB в момент проверки. У контейнера CRM лимит **2 CPU**. Эти величины проверены через nproc/lscpu и Docker inspect; первоначальное утверждение в комментарии о двух ядрах всего сервера исправлено. Swap занят 488 MiB; причина и текущая активность swap отдельно не измерялись. CRM: примерно 598–622 MiB, 140–148% одного ядра. Общее время ответа CRM этим замером не проверялось.

Два последовательных окна по cgroup CPU usage и memory.current, до открытия ЛУКОЙЛ:

| Режим Яндекса | Время | Средний CPU одного ядра | RAM в конце окна |
|---|---:|---:|---:|
| Простой | 20,04 с | 0,49% | 443,2 MiB |
| Полное обновление | 11,01 с | 46,96% | 524,1 MiB |

По одному такому циклу оценка средней загрузки за пять минут — 2,2% одного ядра, около **0,55% четырёхъядерного сервера**. Во время обновления — около 11,7% всего сервера. Это оценка из коротких окон, не длительный нагрузочный тест. Ограничения контейнера: 0,5 CPU, 768 MiB RAM, 256 процессов. По сумме измеренных потребителей запас CPU есть; отсутствие влияния на задержки CRM отдельно не доказано. OOM/oom_kill в cgroup обоих контейнеров — 0.

Архитектура подходит для браузерного способа: отдельный ограниченный сборщик, фоновое чтение, атомарный небольшой снимок, доступ CRM через её собственные права, последнее успешное время и явный stale/auth_required. Посещения страницы сотрудниками не запускают дополнительные обращения к Яндексу. Главный постоянный расход — память браузера. Официальный поддерживаемый API был бы предпочтительнее по устойчивости и стоимости, если поставщик его предоставляет.

Для нескольких браузерных поставщиков требуется разнести/сериализовать обновления и измерить их реальный расход. Нельзя экстраполировать потребление Яндекса на ЛУКОЙЛ без входа. Платные ресурсы или изменение ресурсов CRM не подключались.

## ЛУКОЙЛ

В серверном Chromium проверены `https://lk.licard.com/` и `https://my.licard.com/`. Оба вернули HTTP 403 до входа. Первый ответ показал Forbidden с серверным IP 130.49.151.239 и временем 2026-10-27 11:30:54 UTC; второй — 403 Forbidden/nginx. Само по себе это не доказывает точное правило блокировки: возможную причину должна уточнить поддержка.

Новый адрес `my.licard.com` проверен по ссылке на [официальной странице ЛУКОЙЛ](https://auto.lukoil.ru/ru/ForBusiness/PersonalAccount). Там указана возможность просмотра баланса договора в кабинете, но это не подтверждение серверного API.

Интеграция ЛУКОЙЛ не объявлена подключённой. Баланс/договор не прочитаны, доступ в CRM не сохранялся. Обход блокировки и перенос cookies с Mac не выполнялись. Для продолжения нужен разрешённый доступ с сервера либо поддерживаемый метод интеграции от ЛУКОЙЛ. [Текст обращения](licard-server-access-request-2026-10-27.md) подготовлен, не отправлен.

Локальные доказательства: `.local/licard-browser-20261027/load-proof.jsonl`, `measure.py`, `server-403.jpg`. Рабочая версия CRM не изменялась.
