# OpenStreetMap + Leaflet — 12.10.2026

## Задача

По прямому поручению пользователя встроить OpenStreetMap + Leaflet в CRM: активные заявки на карте и выбор точки доставки. API-ключи Яндекс/Google не требуются. База выпуска — `artel-crm:20261012-login-design-19361470`; сохранены последние оформление входа и ускорение страниц.

## Изменения

- Leaflet 1.9.4 установлен через npm, библиотека и CSS входят в сборку; публичные CDN-скрипты не используются.
- На вкладке «Рейсы → Карта» показаны активные заявки с подтверждёнными координатами. Заявки с одной точкой объединяются в метку; карточки показывают компанию, адрес и литры, данные вставляются как текст.
- Для заявки без точки есть понятное состояние и «Выбрать точку доставки». Случайный центр карты не считается выбранной точкой.
- В создании/редактировании заявки, карточке клиента/площадки и добавлении нового места доставки можно выбрать точку нажатием, перетаскиванием или введением координат. Сохранение происходит вместе с формой, отмена не записывает изменения.
- Точка конкретной заявки изменяет только её снимок, не справочник или исторические рейсы. Площадка в справочнике сохраняет свою точку для следующих заявок. Адресные тексты не заменяются автоматически.
- Сервер принимает только полную валидную пару широты/долготы. Проверки доступа, версии и идемпотентности сохранены; прежние запросы без координат совместимы. Повтор после потерянного ответа и совпадения литров/комментария дополнительно сверяет точку.
- Выбранная точка переносится в создаваемый рейс и ссылку водителя. Старая навигационная ссылка заменяется только при явном изменении точки. Ручные координаты в справочнике синхронизируют ссылку; новая ссылка сбрасывает прежнюю пару, отсутствующая точка удаляет старую метку.
- Ошибка получения изображения карты показывает сообщение и повтор; список заявок остаётся доступен.

## Карта и данные

Используется `https://tile.openstreetmap.org/{z}/{x}/{y}.png` с видимой атрибуцией, обычным HTTP-кешем и `strict-origin-when-cross-origin` для изображений. Массовое скачивание, предзагрузка регионов, offline-архив и автоматический обход масштаба отсутствуют. Имена компаний, комментарии и литры не передаются серверу карт; он получает стандартные запросы изображений для открытой области.

Автоматическое определение точки по адресу не подключалось. Существующие заявки без координат остаются в списке; точку выбирает пользователь. Из старых ссылок используется только явный `pt`, не `ll` (центр просмотра). Совместимый старый `/api/trip-requests/map-config` сохранён; новый интерфейс к нему не обращается.

Официальные источники: [Leaflet stable](https://leafletjs.com/download.html), [правила OpenStreetMap](https://operations.osmfoundation.org/policies/tiles/). Публичный сервис карт не даёт SLA; отдельный платный аккаунт не создавался.

## Проверки

- На точном исходном снимке выпуска прошли `npm ci`, lint, TypeScript, frontend/backend build, 490 API-тестов, 3 банковских и 9 целевых проверок карт/ссылок.
- Локальные и изолированные проверки не используют рабочее хранилище и не отправляют документов Saby.
- Chromium/WebKit: 46 групп, 34 снимка экрана, размеры 320–1440 px. Проверены карта, группировки, безопасный текст, неизвестные точки, выбор и перенос метки, сохранение/перезагрузка, отмена, конфликт версии и потерянный ответ. Автоматические browser-тесты используют настоящий Leaflet и локальные изображения вместо публичных OSM tiles.
- Отдельно в обычном Chrome открыта тестовая CRM: настоящая OpenStreetMap загрузила 15 из 15 видимых изображений, четыре учебные заявки показаны на карте. Это проверка поставщика изображений, не авторизованная production-приёмка.
- Авторизованный production Chrome загрузил новый JavaScript и настоящие изображения OSM: 12 из 12 на общей карте и 8 из 8 в форме выбора точки. Открыты существующая заявка и карта выбора без изменения или сохранения деловых данных. Текущая заявка «НЕРУД ПРОМ» не имеет координат: показано «На карте 0 из 1 заявок», доступна кнопка выбора точки. Подтверждение произвольного места на рабочей заявке не выполнялось.
- После закрытия формы чтение заявок один раз вернуло `Failed to fetch`; штатная кнопка повтора восстановила список и карту. Итоговый production-снимок сохранён, вкладка оставлена на работающей карте. Причина разового сетевого отказа не установлена; настройки сети не менялись.
- Оба изолированных Docker-образа прошли smoke и проверки блокировки хранилища; рабочие тома и сеть провайдеров при тестах не использовались.
- Через публичный HTTPS побайтно сверены 14 файлов интерфейса. Health возвращает 200, закрытые API — 401 без авторизации, `.env` и `/logistics/` — 404. Проверка публичной сборки на раскрытие секретов прошла.
