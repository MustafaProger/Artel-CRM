# Подключение уведомлений на телефоне оператора

Дата: 21.10.2026, Москва. Подтверждены телефон Huawei и Huawei Browser. Модель и версия системы неизвестны; для первого шага диагностики они не требуются. Реальная доставка на телефон пока не подтверждена. Настоящих тестовых заданий, переводов или заправок для проверки создавать не нужно.

## Что установлено

Сообщение на исходном снимке появляется, когда отсутствует хотя бы одна из четырёх возможностей: защищённое открытие страницы, Service Worker, Push API или Notifications API. Это проверяется до попытки подписки; изменение серверной очереди не добавит отсутствующий браузерный API. Отказ в разрешении уведомлений — отдельное состояние.

Опубликованная в `artel-crm:20261021-operator-returns-6e18a802` диагностика показывает эти четыре признака, разрешение, известное имя/версию браузера и режим открытия. Технические подробности находятся под «Проверка этого устройства». Копируется только этот ограниченный набор: полный User-Agent, URL, endpoint подписки, ключи, учётная запись, сеанс и деловые данные в диагностику не включаются. Проверка возможностей сама уведомления не отправляет.

## Первый шаг на Huawei без знания модели

1. Открыть сам Huawei Browser и ввести в его адресную строку `https://artel-crm.online/`. Если CRM обычно запускается с рабочего стола или из мессенджера, сначала проверить именно обычную вкладку браузера.
2. Войти в свою учётную запись, открыть «Операторская» и нажать колокольчик.
3. Раскрыть «Проверка этого устройства» → «Скопировать диагностику». Если автоматическое копирование недоступно, выделить текст в поле и скопировать обычным способом. Передать этот текст Мустафе; система сама никому его не отправляет.
4. Если CRM обычно открывается по значку на рабочем столе, повторить только диагностику оттуда и сравнить результаты. Huawei указывает, что на системах ниже HarmonyOS 5 сайты с поддержкой PWA могут получать ярлык Quick App; режим запуска поэтому нужно проверять отдельно. Сам ярлык не доказывает возможность получения Web Push. [Официальная инструкция Huawei о ярлыках](https://consumer.huawei.com/cn/support/content/zh-cn00448896/).

Если «Защищённое открытие» недоступно — проверить точный HTTPS-адрес. Если отсутствует Push API, Service Worker или Notifications API — не нажимать бесконечно «Включить»: этого браузерного пути сейчас нет. Сначала сравнить обычную вкладку и значок, затем доступное официальное обновление браузера и повторить диагностику. Результат обновления заранее не обещается. Модель/версия EMUI или HarmonyOS из «Настройки → О телефоне» понадобятся, только если эти шаги не дадут поддерживаемого пути.

В официальных материалах Huawei найдены переключатели уведомлений приложения и новостных сообщений браузера; они не подтверждают поддержку стандартного Push API сайтов на конкретном телефоне. Отдельная инструкция веб-разрешений явно относится к ноутбукам с HarmonyOS 5, переносить её на телефон нельзя. Официально подтверждённый переключатель, добавляющий отсутствующий Push API в этой мобильной среде, не найден. [Huawei: уведомления приложения](https://consumer.huawei.com/cn/support/content/zh-cn00689778/), [Huawei: новостные уведомления](https://consumer.huawei.com/ca/support/content/en-us00706919/), [Huawei: веб-разрешения на ноутбуках](https://consumer.huawei.com/cn/support/content/zh-cn16048858/).

Установка Chrome или Firefox не объявляется гарантированным решением для Huawei без сервисов Google. Firefox Android использует Firebase/Google Cloud Messaging совместно со службой Mozilla. Выбор другого канала уведомлений или отдельного приложения требует согласования; этим изменением такой канал не подключается. [Документация реализации Firefox](https://firefox-source-docs.mozilla.org/dom/push/index.html), [справка Mozilla](https://support.mozilla.org/en-US/kb/push-notifications-firefox).

## Реальная проверка после появления поддержки

1. В операторской выбрать уже существующее доступное задание, которое можно открыть для проверки. Не создавать деловую запись ради теста.
2. Нажать колокольчик → «Включить уведомления» → разрешить запрос браузера. Если разрешение ранее запрещено, включить его для CRM в настройках браузера и разрешить уведомления самому браузеру в настройках телефона, затем снова открыть CRM.
3. Повторно открыть колокольчик и один раз нажать «Проверить уведомление». Проверка сохраняет служебный probe и отправляет тестовое уведомление только на текущую подписку текущего пользователя. Тестовая ссылка должна использовать контекст `operator` и ID выбранного существующего задания. При отсутствии задания допустима проверка перехода в раздел, но она не доказывает переход к заданию.
4. На этом физическом телефоне убедиться, что уведомление появилось в системной шторке или на экране блокировки. Нажать его и проверить открытие именно выбранного задания. Сообщить время, факт появления и фактический экран после нажатия. Получение на другом устройстве не засчитывается.
5. Для отдельной проверки фонового режима нажать «Проверить уведомление» и сразу свернуть CRM. Если уведомление появилось уже после сворачивания, зафиксировать это. Если оно успело появиться до сворачивания, фоновый режим этим тестом не подтверждён. Не принимать настройки энергосбережения/разрешения за доказательство доставки.

Сервис различает принятие провайдером (`providerAcceptedAt`) и успешное создание уведомления браузером (`notificationCreatedAt`, receipt после `showNotification()`). Ни одно из этих полей не подтверждает, что человек увидел уведомление или открыл задание. Финальная приёмка требует наблюдения на телефоне и проверки перехода.

## iPhone/iPad, если проверяется другое устройство

С iOS/iPadOS 16.4 поддерживаются Web Push для веб-приложений на экране «Домой». Открыть «Поделиться» → «На экран Домой», запустить CRM по её значку и включить уведомления нажатием пользователя. В manifest CRM уже используется `display: standalone`. Это инструкция для Apple, а не способ исправления Huawei. [WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).

## Граница текущего результата

Код опубликован 21.10.2026 в 09:55:30 МСК. Локальные проверки подтверждают ветви диагностики, безопасное копирование и отображение в Chromium/WebKit на синтетических данных. Рабочий Chrome под Egor подтвердил панель диагностики на сервере; подписка выключена, её не включали и тестовый push не отправляли. Регистрация на телефоне Джибриля, получение настоящего push и переход к заданию пока не проверены: телефона рядом нет. До физической проверки уведомления на этом телефоне не считать исправленными.

## ННК в опубликованной версии

В defaults добавлен сервис `operator-service-nnk`, название «ННК», скидка `10`. Defaults используются только при отсутствии сохранённого массива `operatorServices`. Уже сохранённый список, включая намеренно пустой, чтением не дополняется и не заменяется.

В контрольном production-снимке сохранённый `data.directories.operatorServices` отсутствовал. ННК появился из defaults нового кода без изменения хранилища. После публикации рабочий Chrome подтвердил ННК и скидку 10% в форме операции; черновик закрыт через «Не сохранять». Ручного добавления сервиса, перезаписи справочников или изменения других скидок при выпуске не было.
