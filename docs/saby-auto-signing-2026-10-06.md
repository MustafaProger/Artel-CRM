# Автоматический обмен при сохранении готового рейса — 06.10.2026

## Прямое поручение

Пользователь уточнил, что не хочет подтверждать подпись для каждого рейса. На вопрос о моменте запуска он выбрал **«При сохранении готового рейса»**. Это заменяет прежний сценарий отдельного выбора подписей/поручения на каждую заявку. Готовность определяется существующими проверками полей и документов Saby; недостающие сведения не придумываются. Факты погрузки по-прежнему требуются на соответствующем этапе ЭТрН.

## Проверенные факты Saby

Скриншот показывает бессрочное доверие перевозочных документов. В Saby срок доверия и настройка «Владелец подтверждает подписание» независимы: [официальная настройка доверия](https://saby.ru/help/another/delegate/transfer_of_rights/).

В текущем API обе выбранные подписи имеют тип `Client`, действующие квалифицированные сертификаты. У действия НК «Утвердить» выбранный сертификат прямо объявлен с `Ключ.Тип="Отложенный"`, `Активирован="Да"`. Это режим без согласования каждого документа. Прежняя интеграция принудительно отправляла `ОтложенныйСПодтверждением`, что не соответствовало уточнённому требованию пользователя. Точная причина неопределённого результата прежнего Execute не восстановлена: исходная ошибка провайдера не сохранялась.

Режим `Отложенный` не переносит закрытый ключ на сервер CRM: для сертификата `Client` требуется доступная среда Saby с ключом/СКЗИ и авторизованным владельцем или доверенным пользователем. Никакие архивы ключей, PIN или новые доверенности этим изменением не создаются и не запрашиваются. [Порядок отложенного подписания](https://saby.ru/help/integration/api/sequence/delegate/doc).

После нажатия пользователем сверки №11 в 14:43:34 МСК сохранены подготовленные файлы, успешная проверка содержимого и намерение Execute. Эти флаги не доказывают, что сам HTTP Execute завершился. Чтение Saby показало состояние 10, исходный этап «Утверждение», отсутствие подписи НК и пустой список служебных этапов по конкретной заявке (`Блокировать="Нет"`). Подпись АРТЭЛЬ подтверждена. Новая автоматизация не повторяет эту неопределённую попытку и не меняет её режим.

## Реализация

- Серверная настройка `SABY_AUTO_SIGNING_JSON` закрепляет две организации и уже выбранные пользователем сертификаты. Настройка содержит только идентификаторы сертификатов; применяется при запуске серверного процесса. Её изменение/отключение после перезапуска останавливает поручения с прежним основанием.
- Сохранение готового рейса и неизменяемое поручение обмена записываются одной транзакцией. Сеть вызывается только после успешного сохранения; очередь сохраняется при закрытии вкладки, сбое соединения или перезапуске.
- Повтор идентичного POST не создаёт поручение задним числом. Включение настройки, чтение списков и планировщик не отправляют ранее сохранённые рейсы сами по себе. Неготовый рейс остаётся редактируемым; следующий настоящий save может поставить его в очередь после заполнения обязательных сведений.
- Права сотрудника, сохранившего рейс, организации, настройка, сертификаты, редакция и содержимое проверяются перед внешними действиями. Новый режим закреплён в сохранённом задании и его хеше. Старые задания без нового поля сохраняют прежнюю семантику.
- В интерфейсе автоматического режима нет отдельных кнопок отправки/запуска подписи, выбора сертификатов или согласия на каждый рейс. Показываются готовность, очередь и фактический результат. Статус неизвестной прежней попытки не обещает автоматического завершения.
