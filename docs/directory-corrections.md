# Справочники и очистка операций — 10 сентября 2026

В справочниках остались компании, менеджеры, товары, автомобили и водители. Формы открываются кнопкой «Добавить» или нажатием на запись. Компания объединяет реквизиты, менеджера и несколько фактических адресов загрузки поставщика / отгрузки клиента. Клиенты и поставщики выбираются фильтром в списке компаний; одна компания может иметь обе роли. Менеджеры добавляются и редактируются вручную.

Учтены поля с фотографии: полное название, ИНН, КПП, ОГРН/ОГРНИП, руководитель, юридический адрес, телефон, почта и банковские реквизиты; паспортные данные водителя; характеристики автомобиля, сведения СТС и ПТС/ЭПТС. Пустой ИНН разрешён для неполной карточки, заполненный проверяется по контрольным цифрам. Паспортные и автомобильные сведения вводятся пользователем, проверка документов государственными реестрами не реализована.

Отдельные вкладки форм оплаты, адресов, связей клиентов с менеджерами и возможных дублей удалены. Формы оплаты продолжают использоваться в расчётах отгрузки. Страница проверки старых данных и связанные с ней блоки убраны. Меню сворачивается до работающих иконок на компьютере; на телефоне открывается выдвижной панелью. Выбор сохраняется в браузере. Название в интерфейсе — «Артель»; удалены подписи рабочего пространства и не меняющая вид таблицы кнопка полноэкранного режима. Верхний поиск работает по кнопке, Enter и Cmd/Ctrl+K, включая страницу отгрузок.

## Сохранение

- `POST /api/directories` добавляет запись; `kind: companies` сохраняет компанию, менеджера и все адреса в одной транзакции.
- `PATCH /api/directories/{companies|managers|products|drivers|vehicles}/{id}` редактирует запись с обязательной текущей `version`. Ответ 409 сохраняет открытый черновик и сообщает о конфликте.
- Идентификаторы справочников сохраняются при редактировании. Переименованные исходные менеджеры/товары и предустановленные водители/автомобили не создаются заново при чтении.
- Адрес с привязанной отгрузкой разрешено изменить, но нельзя удалить. Чужие адреса и неверные ссылки на менеджеров/автомобили отклоняются до записи.
- Старые расчёты и назначения в сохранённых отгрузках не переписываются при смене менеджера компании. В новой отгрузке используется текущее назначение.
- Закрытие изменённой карточки требует выбора «Не сохранять»; во время запроса сохранение и закрытие заблокированы.

## Заполнение из Чекко

`POST /api/companies/lookup` получает реквизиты без сохранения компании. Данные попадают в форму и сохраняются вместе с адресами и менеджером после нажатия «Сохранить». Контакты и банковские реквизиты остаются ручными. Серверный ключ не отправляется браузеру. Данные руководителя читаются из `Руковод[].ФИО` согласно [документации Чекко](https://checko.ru/integration/api/company).

В текущей сессии реальный запрос через локальный API вернул 502 с ошибкой подключения к Чекко / чтения ответа. Успех заполнения проверен тестовым провайдером на сервере и тестовым ответом в браузере; это не подтверждение живого доступа.

## Очистка операций

`node --import tsx scripts/reset-operations.ts --confirm` — явная локальная операция обслуживания. Сначала сохраняется резервная копия рабочего файла в закрытом каталоге `qa/operations-reset-*/operations-before.json`, затем атомарно удаляются рабочие отгрузки и привязки платежей. Флаг `sourceOperationsCleared` отключает повторную загрузку всех исходных отгрузок, платежей и складских сводок. Обнуляются связанные агрегаты, периоды, ссылки компаний и сведения проверки старых операций. Все справочники и назначения менеджеров сохраняются.

Исходный XLSX/JSON остаётся архивом; в активные операции строки из него больше не возвращаются. Новые отгрузки сохраняются обычным образом. Скрипт не подключается к облачному Blob и не очищает опубликованную базу. Повторный запуск удаляет также операции, созданные после предыдущей очистки, поэтому это не миграция, запускаемая при старте приложения.

## Проверки

API-проверки: `tests/api-directory-editing.test.ts` и остальной набор `npm run test:api`. Сборка и статические проверки: `npm run build`, `npm run lint`.

Браузерные сценарии работают с отдельными временными хранилищами, контролируя неизменность рабочего файла:

- `npm run test:directories-ui` — карточки, реквизиты, ошибки и отмена, поиск, сворачивание меню, новая отгрузка после очистки, шесть страниц на ширинах 1440/1024/768/390/320. Отчёт: `qa/directories-2026-09-10/verification.json`.
- `npm run test:shipments-ui` — таблица, фильтры, CSV, формулы, создание/редактирование/удаление машины, сохранённые оплаты и адаптивность. Отчёт: `qa/shipments-excel/verification.json`.
