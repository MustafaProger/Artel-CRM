# GitHub → Vercel

Репозиторий: `MustafaProger/Artel-CRM`. Production-ветка: `main`.
Проект Vercel: `mustafas-projects-62eca26d/artel-crm`.
Адрес: https://artel-crm.vercel.app

После push в `main` Vercel автоматически собирает версию из GitHub. Команда сборки и маршрутизация находятся в `vercel.json`. `scripts/prepare-vercel.mjs` получает исходный снимок из приватного Blob и собирает серверный модуль для Node.js. Рабочие изменения хранятся отдельно в приватном Blob (`artel/operations.json`); новая сборка их не перезаписывает. Локальные операции и облачные операции после публикации развиваются независимо.

В production окружении Vercel должны быть настроены `BLOB_READ_WRITE_TOKEN`, `ARTEL_SOURCE_SHA256`, `ARTEL_AUTH_USER`, `ARTEL_AUTH_PASSWORD`, а для поиска реквизитов — `CHECKO_API_KEY`. Значения не входят в Git. Production-секреты не передаются в preview-окружения; для preview нужна отдельная настройка хранилища и доступа.

Исходные JSON остаются вне Git и статической раздачи. Сборка загружает закреплённый снимок `artel/source/<ARTEL_SOURCE_SHA256>/`, сверяет идентификатор источника и SHA-256 каждого файла. Если данные отсутствуют или повреждены, сборка останавливается. Смена исходной Excel-книги требует отдельного переноса данных, а не только изменения переменной.

Доступ к приложению и API закрыт HTTP Basic через HTTPS. Это общий доступ владельца; разделения прав между менеджерами пока нет. Данные для первого входа переданы владельцу в локальном игнорируемом файле `.vercel/Доступ к CRM.txt`. Не добавляйте этот файл в репозиторий.

Облачные операции используют чтение без кеша и условную запись по ETag. При конфликте приложение получает 409; нужно обновить данные и повторить действие. Автоматического повторения неоднозначно завершившихся записей нет.

Перед обновлением:

```sh
npm ci
npm run lint
npm run test:api
npm run build
git add <изменённые файлы>
git commit -m "Описание обновления"
git push origin main
```

После push проверьте успешное развёртывание с соответствующим commit SHA в Vercel. Проверка опубликованной версии с локальными данными доступна командой `node --import tsx scripts/verify_vercel.mjs`; она только читает данные и проверяет запрет постороннего доступа. Сравнение с локальным хранилищем подходит для первоначального переноса: после начала работы онлайн данные могут обоснованно отличаться.
