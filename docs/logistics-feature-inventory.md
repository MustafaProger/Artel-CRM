# Соответствие функций интерфейса логиста

Инвентаризация по текущему коду от 02.10.2026. Документ описывает реализованные функции и точки повторного использования; фактические результаты проверок и публикации фиксируются отдельно. Новый интерфейс использует тот же сервер, OperationsStore и клиентские строки отгрузок; второго учёта нет.

## Рейсы

| Функция | Общий код и поведение |
| --- | --- |
| Список и просмотр | `web/src/TripsPage.tsx`: список по дате, поиск по дате/клиенту/поставщику/водителю/примечанию, страницы по 20 рейсов, загрузка/ошибка/повтор/пустой результат. Карточка показывает выбранную машину, погрузку, все доставки, промежуточные остановки, литры, цену доставки, массу, заметки, «Счёт не нужен», ссылки на карту. |
| Создание и изменение | `web/src/ShipmentTripEditor.tsx`, `server/shipment-trips.ts`: общие организация, дата погрузки, поставщик, нефтебаза, товар, закупочная цена за тонну, масса, водитель, фактическая машина, дополнительные затраты и заметка. Обычное сохранение не отправляет Saby. |
| Несколько доставок | От 1 до 100 клиентских строк. У каждой клиент, менеджер, форма оплаты, литры, цена за литр, стоимость перевозки, место/плановая и фактическая выгрузка, заметка, «Счёт не нужен». Одинаковые получатель и адрес не объединяются. Существующие строки меняются под прежними ID; добавление и удаление строк атомарны. |
| Маршрут | `web/src/TripLocationPicker.tsx`, `trip-route.ts`: выбор клиентского адреса; администратор с доступом к справочникам может создать место прямо в форме. До 10 промежуточных остановок после доставки; включение в заявку выбирается отдельно, в ЭТрН они не входят. Адреса/карта/координаты сохраняются снимком, последующее изменение справочника не меняет старый рейс. |
| Даты и транспорт | `trip-editor-rules.ts`, `trip-input-rules.ts`: общая дата погрузки, время необязательно; исторические разные даты сохраняются до явной правки. При смене водителя подставляется его машина, разрешён ручной выбор другой. Для наливного дизеля единая масса нетто/брутто. |
| Расчёты и проверки | `trip-calculations.ts`, `shipment-calculations.ts`: точное пропорциональное распределение массы и затрат по литрам, вывод суммы и прибыли, предупреждение о превышении вместимости. Обязательные справочные ссылки, положительные массы/литры/цены и неотрицательные затраты проверяются клиентом и сервером. Готовность Saby проверяется отдельно. |
| Повтор и потеря ответа | Редактор хранит стабильный ключ создания и точное тело неопределённого запроса, запрещает параллельный submit/изменение тела до сверки. `tripCreateRequests` хранит отпечаток, автора и ID: повтор возвращает тот же рейс; иной запрос/автор и повтор после удаления отклоняются. При PATCH потеря ответа сверяется чтением полей и версий. |
| Конфликты и несохранённый ввод | PATCH требует версии всех клиентских строк. Изменённый состав или версия дают 409; редактор предлагает загрузить актуальный рейс. Закрытие изменённой формы требует выбора; незавершённое сохранение не теряется обычным закрытием. |
| Удаление | Ранее было доступно администратору из `web/src/ShipmentsPage.tsx`; в интерфейсе логиста тот же DELETE доступен через `TripsPage` с `allowDelete`. Диалог перечитывает состав/версии и состояния Saby до подтверждения, защищён от повторного submit. Сервер запрещает удаление при Saby-связях или банковских привязках. Удаление клиента/замена клиента с банковскими привязками также запрещены. |
| Ограничения после передачи | `hasSabyDocuments` в `server/saby-service.ts`: начатая общая цепочка, документы ЭТрН и сохранённые/неопределённые прежние Saby-документы запрещают изменение и удаление рейса. Проверка остаётся серверной, включая гонку после открытия формы. |

## Saby

Повторно используется `web/src/TripEtrnPanel.tsx` и `trip-workflow-view.ts`, без собственной реализации обмена в новом frontend.

- Чтение готовности, конкретных блокеров, текущего этапа/ошибки и сведений мониторинга; отдельное действие «Создать заявку в Saby» после сохранения готового рейса.
- Шесть этапов: подготовка, отправка АРТЕЛЬ, водитель и машина, подтверждение НК, создание ЭТрН, отправка клиентам. Черновик не отображается завершённой отправкой.
- Ссылка на общую заявку; данные водителя/автомобиля для НК и копирование этих данных; заполнение ответа НК отдельным действием, состояния ожидания/частичного сохранения/неопределённого результата и блокеры, подтверждение сохранения водителя/машины/ответственного.
- После подтверждения НК — форма фактической погрузки: прибытие/убытие по Москве, фактическая масса и способ определения массы по каждой доставке, явное подтверждение. Расчётный тоннаж не переносится сюда автоматически.
- «Обновить из Saby» / «Сверить результат с Saby», защита параллельного действия и чтение долговечного состояния после потери POST-ответа. Открытие панели и браузерный polling выполняют только GET; продолжением занимается сервер.
- Мониторинг работающей цепочки: обычно 5 минут; готовность ответа НК — 15 секунд в ограниченном периоде ожидания. Вкладка показывает время последней проверки, ошибку связи, историю этапов.
- Отдельная ЭТрН каждой доставки: удалённый статус, ошибка, время обновления, сведения о подписи и ГИС ЭПД, доступные действия Saby, ссылка на документ, скачивание возвращённых файлов через авторизованный API.
- Ранее созданные документы доступны для сверки; новая общая заявка автоматически поверх прежнего обмена не создаётся.

Текущие ограничения из `AGENTS.md`, `PROJECT_STATUS.md`: подпись НК/МЧД не подключены, прямая подпись из CRM и полная реальная цепочка не завершены. Кнопка подписи в новом интерфейсе не добавляется. Для согласованной машины принимаются 27,9 т, объём цистерны отдельно 17,5 м³; НДС остаётся «не указан». Ранее отправленный титул самопроизвольно не исправляется, ручные изменения Saby не перезаписываются. Секретная настройка ответственного остаётся на сервере.

API основной модели: `GET/POST /api/shipment-trips`, `GET/PATCH/DELETE /api/shipment-trips/:id`; `GET/POST .../saby-workflow`, `POST .../loading-facts`, `POST .../carrier-details`; чтение `.../saby`, `.../etrn` и `.../etrn/files/:shipmentId/:fileId`. Ранее созданные API для профиля/XML и одиночного обмена ЭТрН остаются серверными возможностями, но не являются отдельными действиями текущей панели.

## Справочники и права

`web/src/DirectoriesPage.tsx`, `directory-editor-data.ts`, `directory-fields.ts` сохраняют существующие формы и проверку конфликтов: актуальное чтение перед сохранением, объединение независимых правок, выбор спорных полей, повторная сверка при гонке, версии адресов, запрет двойного submit и закрытия без решения о несохранённом вводе.

В рабочем интерфейсе доступны автомобили (включая секции, ПТС/СТС, согласованные транспортные поля и договор), водители (контакты/ВУ/связь с машиной), клиенты/поставщики, нефтебазы с участниками погрузки, товары и места доставки. Менеджеры, формы оплаты и назначения клиентов используются как существующие справочные значения в формах. Отдельных вкладок «Компании», «Перевозчики», очистки справочников, банковского учёта и администрирования нет. Банковские реквизиты компаний исключены из формы и payload интерфейса логиста; их текущие значения в общем учёте сохраняются.

`web/src/auth-model.ts`, `server/permissions.ts`, `server/auth-scope.ts`: раздел «Рейсы» не выдаёт административные полномочия или право менять справочники. Обычный сотрудник видит только целиком доступные ему рейсы; общий рейс с чужими строками не раскрывается через список/ID/Saby. Изменение прав отзывает сессии. Доступ к справочникам и управление ими сохраняют прежние условия. Ограниченная точка входа использует отдельную сессию/API; разделы CRM не добавляются в её навигацию.

`web/src/workspace-api.ts` направляет запросы общих компонентов из `/logistics/` в `/api/logistics/`. `fetchDirectoryData` получает минимальный контекст логистики вместо полного снимка. Основная CRM сохраняет прежние адреса API. Файлы ЭТрН также скачиваются через namespace логистики.

## Обязательные сценарии приёмки

Использовать только временное хранилище, синтетических сотрудников/клиентов/рейсы и заменённый транспорт Saby. Проверить:

- основную CRM и логистику после сборки, отдельный вход/выход, сохранение прав, отсутствие банков/администрирования и лишних полей API;
- desktop/mobile список/поиск/формы/справочники, новый многоклиентский рейс и те же строки в основной CRM;
- валидацию, повторные нажатия, потерю ответа, стабильные ID, конфликт версий и запрет чужого/смешанного рейса;
- удаление целого рейса и запреты при Saby/банковских связях/устаревших версиях;
- изменение справочника, независимые правки/конфликт одного поля, сохранность неотображаемых банковских реквизитов;
- готовность/ошибки/неопределённый результат Saby, carrier-fill, факты погрузки, статусы/файлы и отсутствие записи при простом открытии панели;
- отзыв доступа и прямые запросы к запрещённым API, не только скрытые пункты меню.
