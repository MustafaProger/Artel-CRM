# Повторная сверка ЭТрН и «ЭТрН не нужна» — 26.10.2026

## Запрос и правило

Исправить сообщение «Связанный черновик ЭТрН не подтверждает сохранённые сведения доставки» у завершённого рейса №41; проверить исключение доставки из СБИС. Пользователь отдельно подтвердил: доставка с «ЭТрН не нужна» остаётся только в CRM/отгрузках, никак не взаимодействует с СБИС и не должна мешать обмену остальных доставок.

## Причина и изменение

Фоновый `exchangeEtrn(refresh=true)` сравнивал действующий подготовленный/подписанный T1 с `linkedDraft.filledBase64`, сохранённым до Prepare. Эти XML закономерно отличаются. Теперь только при уже подтверждённом дозаполнении и `sender.verified` повторная read-only сверка использует сохранённый валидный manifest: тот же документ, редакция, T1 и точный SHA-256, затем полная проверка бизнес-полей против frozen snapshot и прежнего согласования. Неподтверждённые/неподписываемые черновики по-прежнему сверяются со своим исходным expected XML. Ошибка не скрывается и не очищается отдельной миграцией.

Дополнительно обнаружена непостоянная ошибка «Сведения дополненной ЭТрН изменились во время сверки»: Saby перевыпускает `Вложение[].Подпись[].Файл.Ссылка`. Из сравнения metadata исключена только эта временная ссылка; сертификат, имя, хеш, содержимое подписи, состав вложений, связи, участники и редакция остаются под контролем. Тесты отвергают изменённый hash подписи, XML, редакцию, ID, manifest и сведения получателя.

Изменены два серверных файла, два набора тестов и скрипт проверки optional-ETRN для проверки также собранного интерфейса. Правило исключения доставок уже было реализовано; менять бизнес-логику не потребовалось.
