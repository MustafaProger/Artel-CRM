# Доступ сотрудников к справочникам — 26.10.2026

## Подтвержденные правила

- У клиента один закрепленный сотрудник. Сотрудник получает своих клиентов, их адреса, личные отгрузки, обзор и работу по существующей привязке.
- Новая учетная запись сотрудника по умолчанию получает страницы «Обзор», «Работа», «Отгрузки», «Справочники». Явно пустой список страниц остается пустым.
- Общие подразделы справочника включаются отдельно: поставщики, нефтебазы, товары, автомобили, водители, сотрудники, сервисы операторской. Галочка дает полный доступ к данным и существующим действиям подраздела, включая добавление, изменение и удаление там, где оно предусмотрено справочником. Ограничения удаления используемых записей сохраняются.
- «Рейсы» остаются отдельным разрешением страницы. Общая очередь заявок и существующие проверки владения рейсами сохранены.
- Предыдущий локальный вариант с режимами «Свои / Все» по страницам отменен. Для текущей задачи нет readScopes/directoryScopes и отдельного доступа ко всем чужим клиентам.
- Для существующих учетных записей страницы и привязки не мигрируются. Отсутствующий directoryGrants означает, что общие подразделы закрыты. Администратор и директор сохраняют полный доступ.

## Реализация и аудит

Финальные исходники собираются отдельно: `.local/directory-access/source`. Основной checkout содержит старые и посторонние незавершенные изменения, поэтому его приложение целиком не используется для публикации и не заменяется новой серверной базой.

- Новый необязательный список directoryGrants валидируется в учетной записи, сохраняется в store и возвращается в публичном описании пользователя без секретных полей.
- Изменение прав отзывает старую сессию по существующим правилам учетных записей.
- Отдельная проекция для GET /api/directories и snapshot?context=directories фильтрует данные на сервере. Скрытие вкладки не является единственной защитой.
- Сервер повторяет проверку прав внутри транзакции записи: создание, изменение и удаление, прямой ID, роли компании, вложенные адреса, восстановление по имени/ИНН.
- Новый клиент сотрудника автоматически закрепляется за ним. Переназначение другого клиента и редактирование чужого клиента запрещены.
- Компания с одновременно разрешенной и чужой клиентской ролью может отображаться в разрешенном общем справочнике без клиентской роли и истории; изменение общей карточки запрещено, чтобы не изменить чужого клиента косвенно.
- Существующая ссылка нефтебазы на чужую компанию дает только название для отображения, без закрытых реквизитов и финансовой истории. Ее можно сохранить; новую скрытую связь подставить нельзя.
- Неиспользуемый собственный клиент удаляется вместе с метаданными закрепления. Адреса, отгрузки и остальные деловые зависимости по-прежнему блокируют удаление.
- Старый нетипизированный endpoint companies/from-inn ограничен администрацией. Действующая форма заполнения из Чекко использует companies/lookup и остается доступна сотруднику с разрешением справочников.
- Полномочия учетных записей не выдаются через разрешение на справочник сотрудников. Удаление водителя с учетной записью требует администратора.
- Скрытые ранее формы оплаты и связи «клиенты–менеджеры» не добавлены в меню. Разрешение форм оплаты валидируется для API, но не предлагается отдельной неработающей галочкой.
