## Поведение

- Компактные строки рейсов, раскрытие маршрута по нажатию/клавиатуре, группировка по машине. Пустые машины не занимают список рейсов.
- Поиск по номеру/водителю/клиенту/адресу, фильтры машины и этапа, «В работе / Завершённые / Все», количество подтверждённых доставок.
- Вместо галочек будущих этапов один текущий статус, объяснение ожидаемой отметки и справка «Как работают статусы?». Отсутствие отметки не объявляется доказательством отсутствия фактической доставки.
- Кнопка «Подтвердить доставку» доступна только назначенному водителю. Логист видит ожидание или сохранённую отметку. Отдельной кнопки «Рейс выполнен» нет.
- Последняя доставка атомарно сохраняет завершение в `tripExecutions`; время/автор совпадают с последней доставкой. Повтор запроса идемпотентен. По уточнению пользователя POST логиста запрещён (403 без записи). Историческое авторство прежних событий сохраняется.
- Водитель сразу видит завершение и рейс в архиве; список логиста обновляется через существующий polling или «Обновить».
- Старый отдельный endpoint `complete` возвращает 410 с пояснением, без записи. Старые полностью отмеченные доставки без явного закрытия проецируются как завершённые по последней настоящей отметке, без перезаписи истории. Неотмеченные старые рейсы не закрываются.
- Saby, приёмка клиента, массы и денежные расчёты этим действием не изменяются.
