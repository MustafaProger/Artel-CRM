# Банковские выписки в «Платежах»

## Локальное обновление 22.09.2026

`ARTEL_BANK_SYNC_ENABLED=true` включает серверную сверку всех действующих подключений: Т-Банка и СберБизнеса НК АРТЭЛЬ. Для каждого банка новый цикл начинается каждые пять минут от начала предыдущего; при первом включении интервал отсчитывается от последней успешной загрузки. Проверяются последние семь календарных дней Москвы. Первая загрузка истории остаётся ручной. Не настроенные подключения и макет СберБизнеса АРТЕЛЬ запросов не делают.

Локальный сервер каждые пять секунд продолжает страницы активных заданий, соблюдая банковские лимиты, блокировки и задержки повторов. Ошибка одного банка не останавливает другой; после пяти ошибок сохраняется требование ручного повтора. Задания и начало цикла сохраняются на диске, поэтому перезапуск не создаёт повторный цикл. Страницу браузера держать открытой не требуется; сервер CRM и компьютер должны работать. При выключенном сервере или спящем компьютере запросы не выполняются. Интерфейс перечитывает сохранённые результаты каждые 30 секунд.

Карточки всех банков используют одинаковые блоки реквизитов, оборотов за выбранный период и времени успешного обновления. Для Сбера обороты считаются из подтверждённых операций с точной десятичной арифметикой. Чтение банковских данных не изменяет сохранённые отгрузки или ручные распределения оплат.

> Обновление 16.09.2026: действующий модуль Сбера описан в [инструкции выписок](sber-statements.md), автоматическое распределение поступлений по ИНН — в [инструкции взаиморасчётов](settlements.md). Ниже сохранена история отката 14.09; она не описывает новую интеграцию Сбера.

## СберБизнес: только вёрстка

По запросу владельца 14.09.2026 интеграция Сбера удалена. Две карточки компаний и экран выписки остаются макетом (`web/src/SberLayout.tsx`). В нём нет сетевых запросов, таймеров, авторизации и обработки операций. Управляющие элементы отключены; доступна навигация к списку банков и архиву.

Удалены OAuth, callback, UserInfo, mTLS-транспорт, диагностика, адаптер выписки/печатной формы, обновление токенов и скрипт ввода секретов. Старые URL не запускают банковские действия. Серверный список, экспорт, чтение операций и планировщик работают только с Т-Банком.

Существующие записи Сбера остаются совместимыми с общим хранилищем CRM. Они исключены из выдачи и планировщика; токены не расшифровываются. Частные локальные файлы, переменные хостинга и настройки в кабинете банка этим изменением не удаляются. Для возврата интеграции потребуется отдельная реализация, одного добавления переменных окружения недостаточно.

## Т-Банк

Подключение `tbank-nk-artel` для НК АРТЕЛЬ использует серверные переменные:

- `ARTEL_BANK_TBANK_NK_ACCOUNTS` — JSON-массив счетов с полями `number` (20 цифр строкой) и `currency`.
- `ARTEL_BANK_TBANK_NK_TOKEN` — токен с правами чтения выписок.
- `ARTEL_BANK_TBANK_NK_INTERFACE` — необязательный локальный сетевой интерфейс (например, `en0` на macOS). Только запросы Т-Банка привязываются к его текущему IPv4-адресу; VPN и интеграция Сбера не перенастраиваются. При отсутствии интерфейса запрос завершается ошибкой без перехода на маршрут по умолчанию. Внешний IP выбранного маршрута необходимо сверить с разрешённым в токене; привязка интерфейса не гарантирует постоянный внешний IP и зависит от маршрутизации ОС. После изменения переменной перезапустите CRM. Проверка TLS остаётся обязательной.
- `ARTEL_BANK_TBANK_NK_WEBHOOK_TOKEN` — необязательный токен проверки вебхуков.
- `ARTEL_BANK_SYNC_ENABLED=true` включает плановую сверку после первого успешного ручного запуска.

Запросы отправляются на фиксированный адрес `https://business.tbank.ru`, выписка — `/openapi/api/v1/statement`, PDF — `/openapi/api/v1/payment-document`. История запрашивается с июня 2023 года, только `Transaction`. Календарные дни Москвы переводятся в UTC-интервал. Платёжные поручения не создаются. Официальная документация: [Т-Бизнес API](https://developer.tbank.ru/).

Постраничная синхронизация сохраняет задания и повторы в operations-store. Полностью загруженный день заменяет предыдущую версию; неполный ответ не стирает сохранённые данные. Lease и CAS защищают от параллельных записей. Изменённые ID сохраняются в архиве, расчёты используют точные десятичные значения и отдельные итоги по валютам.

GitHub Actions (`.github/workflows/banking.yml`) вызывает `/api/banking/dispatch` каждые пять минут с OIDC. Планировщик продолжает задания и сверяет последние семь дней после первой успешной загрузки. Вебхуки только ставят сверку в очередь и не создают движения денег.

Финансовые API требуют входа и управляющей роли. Фильтры, итоги, страницы, CSV, карточка операции и печатная форма сохранены. XLSX-архив доступен отдельной вкладкой; его суммы не смешиваются с банковскими API. Отгрузки и распределения оплат автоматически не изменяются.

## Проверки

- `npm run test:api` — изолированные проверки CRM, Т-Банка и невозможности запуска прежних маршрутов Сбера.
- `node --import tsx scripts/verify_banking.mjs` — макеты Сбера без API-запросов, Т-Банк на тестовых ответах, архив, адаптивность и доступность.
- `npm run lint` и `npm run build`.

Браузерные проверки используют временное хранилище и искусственные ответы; они не подтверждают реальное подключение Т-Банка. Откат публикуется через `main` → GitHub → Vercel; состояние конкретного production-деплоя проверяется отдельно.
