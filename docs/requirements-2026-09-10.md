# Работа, справочники, отгрузки и Китай — 10 сентября 2026

Изменения внесены в существующее приложение. Публикация и очистка рабочих данных в рамках этого этапа не выполнялись.

## Реализовано

- **Работа.** Вместо трёх колонок — единый список «Работа с компаниями», включающий существующие задачи и записи по компаниям. Поиск по названию/ИНН в списке и в выборе компании. Карточка сохраняет название, описание, компанию, исполнителя, комментарии, срок, напоминание и файлы. Сохраняются существующие правила назначения/передачи между сотрудниками. Есть «Архив задач» и возврат в работу; задачи через API больше не удаляются. Архивирование применяется и к записям по компаниям. Коллекции не объединяются физически, исходные ID и данные сохранены. Заметки и напоминания сохранены. Календарь показывает срок и напоминание активных записей; архив исключён из текущего календаря.
- **Файлы.** Сохраняются на сервере вместе с карточкой, доступны назначенному сотруднику, директору и администратору по существующим правилам работы. Скачивание требует действующей сессии и доступа к записи; API списка возвращает только метаданные. Передача исполнителю сохраняет файлы и авторство комментариев.
- **АЗС.** Средний формат сохраняет текущие 19 полей и действия. Малый содержит ровно 10 столбцов: дата, контрагент, менеджер, форма оплаты, количество литров, сумма покупателя, сумма поставщика, поставщик, прибыль, оплата. Отдельного столбца действий в малом формате нет; дата открывает редактор. CSV соответствует выбранному формату, предпочтение сохраняется в браузере.
- **Бензовозы.** В оранжевой группе одна колонка «КВП / Допзатраты» показывает оба сохранённых значения с подписями. Нового сложения, пересчёта или переноса значений между финансовыми полями нет. Стандартный формат также использует объединённую колонку; уменьшенный состав остальных полей сохранён. Существующие финансовые функции этого этапа не изменены.
- **Справочники.** Убраны отдельные вкладки форм оплаты, адресов, клиентов и менеджеров. Клиенты, поставщики, менеджеры, товары, автомобили и водители остаются. Существующие адреса загрузки/отгрузки и менеджер редактируются в карточке компании. Значения форм оплаты остаются существующими: `б/нал`, `нал`, `ф2`; правила допустимости форм в АЗС этого этапа не менялись.
- **Менеджеры.** Настройка учётной записи связывает её с сотрудником справочника через существующий `managerId`. Сервер при каждом чтении получает назначенных клиентов из `customerManagers`; список выбора клиентов в отгрузках использует эту связь. Новые назначения доступны при обновлении данных, повторного списка компаний в настройках роли нет. Текущий клиент сохранённой отгрузки остаётся в выборе при редактировании. Состав серверных прав на отгрузки не расширялся, существующее ограничение по менеджеру отгрузки сохранено. Чужие отгрузки не становятся доступными от одного назначения клиента.
- **Китай.** Добавление/редактирование дня с несколькими строками поставщиков дизельного топлива. Литры и суммы сохраняются отдельно в каждой строке. Отдельные платежи с датой и суммой, включая даты без заправок; поступления справа со знаком `+`. Дневные итоги суммируются точно десятичной арифметикой; детали раскрываются в таблице. Повтор POST с тем же идентификатором запроса не дублирует день/платёж, версия защищает редактирование дня. Используемого поставщика нельзя удалить или убрать у него тип поставщика.
- **Прочее.** Обзор и склад пустые. Платежи сохранены. Переключение зарплат водителей/менеджеров сохранено. Команды и роли сохранены.

## Явная очистка справочников

Путь: **Справочники → Очистка справочников → Создать копию и очистить**. Доступ — по существующему праву управления справочниками.

Предварительная проверка выполняет всю предполагаемую операцию на копии в памяти. При внешней зависимости (отгрузка, платёж, склад, задача, заправка Китая, учётная запись с managerId) очищаемые записи и связанные документы не удаляются. В интерфейсе отображается первое препятствие. Частичная очистка не выполняется.

При подтверждении внутри транзакции повторно проверяются права, ревизия и связи. До записи очищенного состояния создаётся отдельная резервная копия и читается обратно для проверки. Без успешной копии очистка запрещена. Устаревшая предварительная проверка отклоняется. Внутренние назначения клиентов/менеджеров и адреса очищаемых компаний удаляются как части справочников; остальные роли общей компании могут сохранять её карточку. Учётные записи, команды, роли и постоянные формы оплаты не очищаются. Tombstone ID не дают импортным справочникам и автопарку появиться заново.

Локальная резервная копия сохраняется в `backups/` рядом с `operations.json`, в облачном адаптере — в приватном `artel/backups/`. Подтверждение возвращает путь копии. Копия содержит полное состояние операций, включая учётные записи; её нельзя публиковать. Для восстановления требуется остановить записи, проверить SHA источника и checksum через `decodeOperations`, вернуть копию в соответствующее хранилище, затем проверить снимок. Автоматического интерфейса восстановления нет.

## Допущения и ограничения

- Объединение КВП и допзатрат трактуется как объединение отображения двух значений; новая финансовая формула не вводится.
- Один календарный день Китая — одна редактируемая запись с несколькими заправками. Повторное добавление той же даты предлагает открыть существующий день. До 100 строк поставщиков на день; это технический предел формы.
- Общий учёт Китая использует существующие роли директора/администратора, как административная финансовая работа. Новые права менеджера на общий финансовый учёт не добавлены.
- Файлы: до 1 МБ каждый, до 20 файлов и 2 МБ суммарно в карточке. Данные сохраняются внутри существующего локального/Blob-хранилища. Общий предел хранилища 64 МБ проверяется до записи. Внешнее файловое хранилище для крупных вложений не добавлялось.
- **Формула баланса Китая не настроена.** Интерфейс явно сообщает об этом, числового баланса нет. Формула «платежи минус заправки» не вводилась. Валюта не была задана, поэтому суммы показываются без придуманного обозначения валюты.
- **Excel-файл для Операторской отсутствует.** Показано соответствующее сообщение, новая структура учёта и расчётная функциональность не добавлялись.
- Очистка связанных справочников может быть заблокирована. Связанные документы и учётные записи ради очистки не удаляются.
- Проверки относятся к локальному приложению. Облачное резервное копирование проверено контролируемым Blob-клиентом; реальная публикация и живое облачное восстановление не проверялись.
