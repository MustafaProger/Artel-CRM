# Отгрузки — итерация Excel, 9 сентября 2026

Последующая доработка: [общая форма машины с несколькими клиентами](shipment-trips.md). Она заменяет описанную ниже форму создания; старые одиночные операции продолжают использовать прежний редактор. Выбранный `vehicle_id` теперь сохраняется как автомобиль конкретной отгрузки.

После [сверки полей исходного XLSX](workbook-field-reconciliation.md) КВП, исходный срок, дата без заголовка и перевозчик показаны в таблице; виды теперь содержат 34/23/12 колонок. Ниже сохранено описание предыдущей итерации.

Рабочая реализация находится в `/Users/mustafa/Desktop/Artel-CRM`. Существующий React/Vite-интерфейс и локальный API расширены. SQL-базы в проекте нет; новый стек хранения не вводился.

Таблица занимает всю страницу: навигация открывается по кнопке меню, верхние информационные блоки скрыты. Расширенный вид содержит 30 колонок, стандартный — 20, уменьшенный — 11. Высота строки 38 px, заголовков — 76 px. Сохранены серверные страницы по 50 строк, виртуализация и CSV всего результата. Закреплены дата и контрагент на ширине больше 800 px. На узких экранах горизонтальное закрепление отключено, чтобы оставался доступ к остальным колонкам. Двойной щелчок, Enter или F2 на ячейке открывают редактор; стрелки перемещают фокус между отрисованными ячейками.

Кнопка в заголовке колонки открывает фильтр со списком значений и поиском. Поддерживаются содержит, равно, пустые/непустые и диапазон чисел/дат. Фильтрация, сортировка, итоги и CSV применяются до пагинации. Значения фильтра поступают со всех подходящих строк, без ограничения первой страницей. Выбранный вид таблицы сохраняется в браузере. Произвольного редактирования ячейки без формы, вставки диапазонов, изменения порядка/ширины колонок и совместной работы в этой итерации нет.

Форма содержит исходные величины и выбор готовых записей. Создание компаний из формы отключено. Справочники открываются отдельно: компании через ИНН/Чекко, менеджеры, товары, формы оплаты, автомобили, водители и адреса. Новый водитель обязательно связан с автомобилем. В отгрузке сохраняется `driver_id`; госномер и имя водителя разрешаются при чтении и не копируются в изменяемое хранилище отгрузки. Автомобиль поддерживает марку, модель и прицеп. Старые компании-перевозчики сохранены; они не преобразуются в людей автоматически.

Адрес содержит `companyId` и тип `loading`/`delivery`. Сервер проверяет принадлежность адреса компании и тип точки. Смена компании сбрасывает адрес. Если у компании ещё нет точек или ИНН, приложение не придумывает их: справочник нужно заполнить. Юридический адрес из реестра не считается автоматически местом загрузки/выгрузки. Старые строковые адреса сохраняются как исторические значения. В новых записях используются идентификаторы плюс автоматически заполненное название точки для снимка операции.

Автоматические значения:

| Поле | Правило |
| --- | --- |
| Месяц | `YYYY-MM` из даты, отображение «сентябрь 2026 г.» |
| ИНН | Из выбранной компании, если известен |
| Цена продажи за тонну | Сумма продажи / количество тонн, при тоннах > 0 |
| Сумма покупателя | Литры × цена продажи за литр для новых операций |
| Сумма закупки | Тонны или литры × цена закупки; единица выбирается явно |
| Водитель, автомобиль | Из связей справочников |
| Оплачено и дата оплаты | Подготовлены для распределённых платежей; новые операции до связки имеют 0 и пустую дату |
| Долг / переплата | Оплачено − сумма покупателя: минус означает долг, плюс переплату |
| Просрочка | Срок оплаты → день полного погашения либо текущая дата Москвы. Без срока или достоверной суммы оплаты — пусто |
| Прибыль | Подтверждённое правило; для новых операций правило пока не задано |

Расчёты сосредоточены в `web/src/shipment-calculations.ts`, используются сервером и редактором; арифметика выполняется через Decimal с точностью 80. В исходных строках распознаны формулы продажи для 1914 строк, закупки — для 1743, прибыли — для 1947 из 2092. Распознаются только формулы с подтверждёнными ссылками на ту же строку. Исходные суммы и старые поля сохранены; массового пересчёта старой книги не выполнялось. Изменение исходных величин пересчитывает зависимые поля по распознанному правилу; изменение даты/адреса не переписывает старые финансовые значения. Особые неподдержанные формулы блокируют изменение зависимых количеств/цен до уточнения.

Большинство исходных формул прибыли: продажа − закупка − перевозка − КВП; когда закупка больше продажи, к ней применяется 0,83; в большинстве строк результат округлён до целого рубля. Существуют варианты без округления и с другим учётом КВП. Новые допзатраты отсутствуют в этих исходных формулах. При появлении ненулевых допзатрат в исторической операции пересчёт прибыли требует уточнения, вместо предполагаемой суммы выводится пустое значение с пояснением. Для новых операций также не выбран один из вариантов автоматически. `simple` и распознанные варианты Excel предусмотрены в сервисе; значение по умолчанию находится в `directories.defaults.profit` и сейчас равно `null`. Требуется подтвердить применимость коэффициента 0,83, округление и учёт допзатрат/КВП. Пользователь не вводит прибыль вручную.

Старые `kvp_source`, `unlabelled_note`, `term_source` сохранены в данных, но убраны из рабочего UI. Старый «Срок» из Excel не интерпретируется как договорная дата оплаты: добавлено отдельное поле `payment_due_date`. Нулевая задолженность источника при неизвестной оплате не считается доказательством полного погашения.

Миграция `server/migrations/002-shipment-directories.ts` переводит рабочий JSON с версии 1 на 2, добавляя справочники и `paymentAllocations`. Она идемпотентна, сохраняет все прежние ID и поля и не изменяет исходную выгрузку. При чтении миграция выполняется в памяти, физически сохраняется при следующей успешной записи под прежней блокировкой, с контрольной суммой и атомарным переименованием. API и чтение хранилища проверяют ссылки. Необходимо переносить исходную выгрузку вместе с рабочим JSON.

Банковская интеграция подготовлена функцией `server/payment-allocations.ts`: платёж может распределяться между отгрузками, повторное распределение той же пары идемпотентно, превышение суммы поступления запрещено. Функция предназначена для вызова внутри `OperationsStore.mutate`; внешнего endpoint и автоматического сопоставления выписки пока нет. Историческая оплата хранится как начальная сумма; её согласование с выпиской потребуется отдельно. Удаление отгрузки с распределёнными платежами блокируется до снятия связи. `server/shipment-numbering.ts` — точка добавления нумерации внутри транзакции создания; пока номер новой операции пустой.

Защита от дублей: существующий ИНН возвращает ту же компанию; одинаковое название старой фирмы без ИНН блокирует создание до проверки; разные подтверждённые ИНН не объединяются. Названия справочников нормализуются по регистру и пробелам; госномера — также по совместимым русским/латинским буквам. Адрес уникален в пределах компании и типа точки. Проверки выполняются под блокировкой записи, включая одновременные запросы. 166 групп возможных дублей компаний вынесены в «Справочники → Возможные дубли»; автоматическое слияние юридических лиц не выполнялось. Варианты регистра менеджеров и товаров объединены в доступных значениях без потери текста источника.
