# Артэль CRM

Локальная CRM на данных `БХЧ Артэль 2026 (5).xlsx`: отгрузки, платежи, контрагенты, складские сводки и проверка источника. Отгрузки можно создавать, редактировать и удалять; изменения сохраняются на диске между перезапусками.

## Запуск

```sh
npm ci
npm run dev
```

Откройте [Артэль CRM](http://127.0.0.1:5173/#shipments). На macOS также можно дважды нажать `Запустить Артэль.command`. Окно терминала нужно оставить открытым.

```sh
npm run build
npm run preview
```

Предпросмотр сборки: [127.0.0.1:4173](http://127.0.0.1:4173/#shipments). Оба режима используют локальный API. Вход и разграничение доступа пока не реализованы; приложение доступно на этом компьютере.

## Отгрузки

Таблица занимает всю рабочую область, навигация доступна по кнопке меню. Расширенный вид — 34 колонки, стандартный — 23, уменьшенный — 12. Восстановлены КВП, исходный срок и даты из столбца без заголовка; перевозчик показан отдельно от водителя. Дата и контрагент закреплены на широких экранах. Поиск, сортировка и фильтры колонок применяются ко всем строкам; доступны списки значений, диапазоны, пустые и непустые ячейки. CSV экспортирует весь отфильтрованный результат. Порции по 50 строк и виртуализация сохранены, высота строки — 38 px.

Новая форма оформляет всю машину: дата, поставщик, закупочная цена за тонну, общий тоннаж, несколько клиентов со своими литрами, формой оплаты, ценой и перевозкой, водитель и выбранный автомобиль. Тоннаж клиентов распределяется автоматически по долям литров. Допзатраты раскрываются отдельно и распределяются по тем же долям. При редактировании строки клиента открывается вся машина. Адреса ограничены выбранной компанией; ИНН, месяц и суммы рассчитываются автоматически. Оплаты подготовлены для связи с банковскими операциями. Формула прибыли новых отгрузок требует подтверждения и пока не подставляется предположением. Исторические формулы и значения сохранены.

«Справочники» — отдельный раздел для компаний, менеджеров, товаров, форм оплаты, автомобилей, водителей и адресов. Там же находятся 166 групп возможных дублей компаний для проверки без нарушения связей. Двойной щелчок, Enter или F2 на ячейке открывают редактор.

Новый сценарий, формула распределения и сохранение: [отгрузка машины нескольким клиентам](docs/shipment-trips.md). В справочниках уже доступны 7 водителей и 5 машин из предоставленного списка, с телефонами, вместимостью и секциями.

Подробности исходной модели, миграции и исторических формул: [итерация отгрузок](docs/shipment-workspace.md).

Выписка дополнена исходным месяцем и дополнительным полем; складская таблица показывает все шесть величин. [Сверка полей с XLSX](docs/workbook-field-reconciliation.md) подтверждает совпадение источника и сохранение данных.

## Добавление фирмы по ИНН

В разделе «Справочники → Компании» введите ИНН. Сервер проверяет ИНН и получает реквизиты через [официальный API Чекко](https://checko.ru/integration/api). Повторный ИНН возвращает существующую фирму. Совпадение названия старой записи без ИНН требует проверки; новая запись не создаётся. После добавления компания доступна в форме отгрузки.

Серверный ключ задаётся в `.env` как `CHECKO_API_KEY`; шаблон без ключа — `.env.example`. После изменения настройки перезапустите сервер. Ключ не передаётся браузеру. Ошибка соединения, неверный ИНН или отказ сервиса показываются в форме, фирма без подтверждённых данных не создаётся.

## Хранение

| Путь | Назначение |
| --- | --- |
| `web/src/` | React-интерфейс, шаблоны и редактор |
| `server/` | Локальный API, проверка данных, сохранение, интеграция Чекко |
| `data/local-xlsx-final/` | Неизменяемый исходный экспорт с контрольными суммами |
| `data/local-operations/operations.json` | Версия 2: изменения отгрузок, удаления, реквизиты, справочники и связи оплат |
| `.env` | Приватные серверные настройки |
| `scripts/`, `tests/`, `qa/` | Проверки и их результаты |

При переносе CRM сохраните обе папки данных. Запись выполняется атомарно с блокировкой и проверкой контрольной суммы; повреждённое хранилище не заменяется пустым. Версия операции защищает от перезаписи чужого изменения в другом окне. Для тестов можно задать отдельную папку через `ARTEL_STORE_DIR`.

Рабочие операции не записываются обратно в Excel. Склад и замечания к формулам остаются снимком исходного файла. Платежи доступны для просмотра и экспорта. Публичная публикация и онлайн-синхронизация не выполнялись.

## Проверки

Прошли typecheck, lint, production build, 21 API-тест, 12 тестов экспорта и 10 групп браузерных проверок. Исходные данные не изменены. Реальный Чекко в этой итерации не проверялся.

```sh
npm run typecheck
npm run lint
npm run test:api
npm run build
npm run test:shipments-ui
python3 -m unittest discover -s tests -v
```

Для Python-тестов нужен Python 3.10+ с зависимостями из `requirements.txt`. Браузерный тест самостоятельно запускает production preview на 5186 с временным хранилищем и установленным Google Chrome. Результат по умолчанию сохраняется в `qa/shipments-excel/verification.json`; `ARTEL_QA_OUTPUT` позволяет указать другую папку. Старые браузерные скрипты отгрузок описывают прежний UI и заменены сценарием `verify_shipments_excel.mjs`.

**Источник:** `БХЧ Артэль 2026 (5).xlsx`. Актуальная Google-таблица ещё не проверена: ссылка пока не предоставлена. Выгрузка отражает приложенный файл, включая его формулы и сохранённые результаты. Формулы не пересчитывались.

Все JSON, кроме манифеста, имеют оболочку `{ "meta": {...}, "data": ... }`. Метаданные включают SHA-256 исходника, версию схемы и способ сохранения формул. [Манифест и контрольные суммы](data/local-xlsx-final/manifest.json), [описание формата](docs/json-format.md).

## Что требует проверки

- Девять поступлений на **4 718 709,11 ₽** записаны текстом и не входят в обычный числовой SUM. В JSON есть и исходный текст, и отдельно разобранная сумма.
- 70 строк выписки содержат ноль вместо даты; две строки содержат только дату. Все сохранены и помечены.
- 497 формул содержат `#REF!`, пять ячеек склада содержат `#DIV/0!`. Часть сводных диапазонов не охватывает последние строки; сохранённые итоги нельзя считать пересчитанными.
- Похожие названия и совпадающие операции оставлены на ручную проверку. Владельцы компаний и отгрузок не назначались по предположениям.

Подробности и контрольные суммы: [аудит исходника](docs/source-audit.md), [машиночитаемый отчёт](data/local-xlsx-final/validation_report.json), [независимое основание сверки](qa/source-baseline.json).

Независимая сверка всех ячеек, формул, комментариев, связей и Decimal-сумм прошла без расхождений переноса. Также прошли 12 тестов преобразования. Это проверка корректности выгрузки; ошибки самой таблицы остаются в данных и отчёте. [Результат проверки](qa/export-verification.json).

## Роли и будущее хранение

[Описание ролей](docs/access-model.md) и [roles.json](config/roles.json): директор — полный доступ, администратор — управление пользователями, ролями и распределением данных, менеджер — свои компании и свои отгрузки этих компаний. Бухгалтер и склад описаны как предлагаемые базовые роли. Файл ролей является спецификацией; он сам не защищает JSON на диске.

Сейчас храним данные локально в JSON. Для общей CRM предложен PostgreSQL: бесплатное ПО, место размещения выбирается отдельно. Для приложения на одном компьютере возможен SQLite. [Сравнение и официальные источники](docs/storage-options.md).

## Повторная выгрузка и проверка

Python 3.10+ и `openpyxl`:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/export_workbook.py "/путь/БХЧ Артэль 2026.xlsx" --output data/new-snapshot
.venv/bin/python scripts/verify_export.py --source "/путь/БХЧ Артэль 2026.xlsx" --export data/new-snapshot --output qa/new-snapshot-verification.json
.venv/bin/python -m unittest discover -s tests -v
```

Экспортёр не перезаписывает существующую папку снимка. Он проверяет основные заголовки; изменение структуры листов требует пересмотра отображения колонок. Компания получает устойчивый ID по консервативно нормализованному названию; ID операции связан с SHA-256 книги, листом и строкой. Синхронизация изменившейся книги потребует отдельного правила сопоставления операций.

Для проверки актуальных данных нужен URL Google Sheets и возможность чтения. После получения доступа следует сделать новый снимок, сверить формулы и результаты, сравнить с этим Excel. Параметр `--source-url` сохраняет только происхождение; сам по себе не загружает Google Sheets и не подтверждает онлайн-проверку.

Исходник не изменён. Выгрузка хранится локально в `data/`, вне публичного веб-каталога. Данные, отчёты QA и локальное окружение исключены из Git через `.gitignore`.
