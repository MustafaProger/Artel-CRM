# Артэль CRM

CRM для отгрузок, рейсов, справочников, банковских операций и работы сотрудников. Интерфейс — React/TypeScript, сервер — Node.js, рабочие данные сохраняются в файловом хранилище. Вход, права сотрудников и доступ к данным проверяются сервером.

Рабочий сайт: [artel-crm.online](https://artel-crm.online). Актуальные результаты, ограничения и следующая точка работы — в [PROJECT_STATUS.md](PROJECT_STATUS.md). Перед изменениями прочитайте [AGENTS.md](AGENTS.md).

## Локальный запуск

Нужны Node.js 22+ и npm. Для запуска приложения необходим приватный исходный снимок `data/local-xlsx-final/`; он не входит в Git. При переносе существующей CRM также сохраните её рабочее хранилище и серверную конфигурацию.

```sh
npm ci
npm run dev
```

Откройте [127.0.0.1:5173](http://127.0.0.1:5173). На macOS можно запустить `Запустить Артэль.command` и оставить окно терминала открытым. Существующие пользователи входят под своими учётными записями; при первом запуске пустого рабочего хранилища интерфейс предлагает создать директора.

Серверные параметры описаны в [.env.example](.env.example). Настройки внешних интеграций задавайте только для нужного окружения; действующие банковские подключения обслуживает production. Порядок настройки и переноса — в [инструкции production](ops/production/README.md).

Для локального предпросмотра интерфейса:

```sh
npm run build
npm run preview
```

Адрес предпросмотра: [127.0.0.1:4173](http://127.0.0.1:4173). Оба локальных режима используют API и рабочее хранилище; для изолированной проверки укажите отдельный `ARTEL_STORE_DIR`.

## Структура и данные

| Путь | Назначение |
| --- | --- |
| `web/src/`, `web/public/` | Интерфейс и публичные ресурсы |
| `server/` | API, авторизация, хранение и интеграции |
| `scripts/`, `tests/` | Обслуживание, экспорт и проверки |
| `docs/` | Описание функций, контрактов и решений |
| `ops/production/` | Сборка, размещение, резервирование и отчёты релизов |
| `data/local-xlsx-final/` | Приватный неизменяемый исходный снимок |
| `data/local-operations/` | Приватное рабочее хранилище по умолчанию |
| `.env` | Приватные локальные серверные настройки |
| `app-dist/`, `server-render/`, `qa/` | Создаваемые сборки и результаты проверок |

Приватные исходные документы хранятся вне checkout, в `~/Library/Application Support/Artel-CRM/private/saby/source-documents/`. Старые результаты `qa/` и файлы `.vercel/` от 29.09.2026 сохранены в проверенном архиве `~/Library/Application Support/Artel-CRM/private/cleanup-2026-09-29/local-artifacts.tar.gz`; исключены только воспроизводимые зависимости/сборки вложенного clone и побайтно совпадающий снимок данных. Новые проверки снова создают `qa/`.

Данные CRM, исходные документы, секреты и результаты QA не публикуются в Git. В тестовых fixtures допустимы синтетические данные и публичные схемы. Проверки изменений выполняйте с временными хранилищами; сохранность и восстановление рабочих данных описаны в [инвариантах хранилища](ops/production/storage-invariants.md).

## Проверки и сборка

```sh
npm run lint
npm run typecheck
npm run test:api
npm run test:etrn
npm run build:production
```

Выборочные браузерные сценарии после сборки:

```sh
npm run test:shipments-ui
npm run test:trips-ui
npm run test:trips-etrn-ui
npm run test:trips-etrn-runtime
npm run test:customer-creation-ui
```

Команды остальных проверок находятся в [package.json](package.json). Браузерные сценарии используют Playwright; зависимости браузера и исходного снимка указаны в соответствующих скриптах. Результаты сохраняются в игнорируемой папке `qa/`. Синтетические тесты Saby не подтверждают реальную запись, подписание или обмен.

Python-проверки экспорта и локального воспроизведения ЭТрН:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
```

## Повторная выгрузка XLSX

Для экспорта нужен Python 3.10+ с зависимостями из `requirements.txt`:

```sh
.venv/bin/python scripts/export_workbook.py "/путь/исходник.xlsx" --output data/new-snapshot
.venv/bin/python scripts/verify_export.py --source "/путь/исходник.xlsx" --export data/new-snapshot --output qa/new-snapshot-verification.json
```

Экспортёр сохраняет исходные формулы и их сохранённые значения, не пересчитывает Excel и не перезаписывает существующий снимок. Новая выгрузка не объединяется с рабочими операциями автоматически. Формат, идентификаторы и ограничения импорта: [JSON](docs/json-format.md), [аудит исходника](docs/source-audit.md), [сверка полей](docs/workbook-field-reconciliation.md).
